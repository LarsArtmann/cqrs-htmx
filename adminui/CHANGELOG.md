- **i18n seam (labels, locale, direction, reduced motion).** The panel's display strings now live in one label table (`labels.go`; nav, chrome, confirm dialogs, empty states, page headers, table headers, primary actions) that every covered surface reads — `Config.Labels` overrides values by key (REPLACING table values; unknown keys are REJECTED at `New` so a typo can never hide behind an inert override), and an unmapped key renders the KEY text, never blank. `Config.Locale` (BCP-47) sets the `<html lang>` attribute and picks date shapes (`en` default keeps the historical shapes — default-config renders are unchanged; `de` ships its dotted day-first shape; other locales fall back to ISO), `Config.Dir` (`ltr` default, `rtl`) sets `<html dir>`; both validated at `New`. ### Added

- **Member-safety batch: role distribution, the last-admin DOWNGRADE guard, and the suspended banner.** The tenant detail identity card now answers "who holds which roles here" with a per-role holder count (`owner ×1 · admin ×2 · viewer ×3`, assignable-role order, roles nobody holds omitted — an empty roster renders a dash, never a zero row), built from the member rows the page already resolves. The last-admin guard now covers role CHANGES, not just removal: the membership decider (`usermgmt/es_membership_decide.go`) has no domain-level last-admin rule, so the panel is the only guard — when a role-set change (roster "Set" form or the user page's per-tenant role form) would strip the tenant's ONLY admin-tier role (`admin` or `owner`), the POST is refused with an escalation toast naming the situation ("the last admin cannot be downgraded in this tenant") and the roles are left untouched; the same rows' confirm dialogs carry the escalation copy with the admin-tier count so the admin never reaches the refusal by surprise, and the escalation disappears the moment a second admin-tier holder exists. A suspended tenant now announces itself where the admin is looking: a standing warning banner on the detail page states that its N member(s) cannot sign in and carries an in-context Reactivate CTA posting to the existing reactivate route (no new routes); the banner renders in the HTMX partial too, and an active tenant renders no banner. Pinned by `member_safety_test.go` (distribution render + live count, downgrade refusal on BOTH write surfaces with roles verified unchanged, release-valve success with a remaining admin, confirm escalation presence/absence, banner states across suspended/reactivated/normal, partial parity) and the updated `user_tenant_access_test.go` replace-set fixture (a standing second admin keeps the legal steps legal).

- **`Config.ReadOnly`: mount the panel without its write routes.** A deployment that wants browse-and-audit access (a staging mirror, a read-only on-call view) had no seam — every list page rendered live creation/deletion forms. `ReadOnly: true` skips every route-table row marked `write: true` **at registration**: the write handlers never mount, so a mutating request finds no route and the mux's method catch-all answers `405` — the refusal is structural (there is no route to reach), not a handler check that can be forgotten or bypassed. The manifest (`Routes()`) reflects the same skip, so a reverse-proxy allowlist or `authztest` matrix built from it never names a route this instance refuses, and the sidebar footer renders an amber "Read-only" notice chip instead of implying the write forms are live (the read-only *forms* still render — posting to one is what 405s). Reads are unaffected, including the safe `POST /users/search` fallback twin, which stays mounted — precision pinned, a blanket POST block would be a different contract. The default (zero value) mounts the full surface, so existing consumers change nothing. Pinned by `readonly_test.go` (per-write-route 405 probes derived from the FULL manifest's write rows so new writes join the probe set automatically, safe-POST-still-mounted, manifest-equals-full-minus-write-rows truth, notice chip render + exact markup golden) and `security_posture_test.go` (the `authztest.Suite` posture matrix run over the whole panel route table: every declared row refuses anonymous callers 401, role-gated rows refuse authenticated non-admins 403, the `super_admin` grant holder is admitted, declarations-count pin, and the fail-closed receipt — a suite declaring an ungated posture is refused before any probe runs). Also new: `headers_test.go` pins what the panel's own middleware chain emits on all three response classes — page, HTMX partial, static asset — for X-Content-Type-Options/X-Frame-Options/Referrer-Policy/Permissions-Policy, a per-request-nonce CSP whose nonce the page markup actually embeds (partials carry no inline script, assets no markup — asserted as truth, not excused), a fresh nonce per request, and the honest HSTS absence pin (the panel's chain leaves TLS policy to the deployment edge).

- **Dashboard intelligence: the overview now computes from the audit window instead of only counting it.** Every derived stat card carries an honest period-over-period delta: the window's retained entries are split at the midpoint of their time span into a later half ("current") and an earlier half ("previous"), and the change renders as "+N"/"−N"/"±0" with an up/down trend — but a selection that matches ZERO events renders NO delta at all (no change text, no arrow), because a "0% → 0%" line would claim a stability an empty window cannot attest. A window caption under the stat grid states exactly what the derived numbers cover ("Audit window holds N events from X to Y · the journal keeps the full history") — the dashboard sibling of the audit page's retention caption, built from the projection's own facts and reusing the metadata text tokens. New derived cards and surfaces: **Login failures** (window count, amber above the attention threshold, delta split on failure entries only), a **registrations-per-day sparkline** (templ SVG polyline over a trailing 14-day local-day bucket range; empty windows render an explicit "nothing recorded yet" note and all-zero windows a flat baseline, never a fabricated wave; visible caption doubles as the `aria-label`), **Passkey adoption** and **OAuth adoption** ratios alongside Verified/MFA, and a **Platform operators** card counting DISTINCT users holding admin-tier (`super_admin` OR `admin`) grants in the wildcard domain via `Authz.UsersForRole` (same role-name-subject filter `HasAdminGrant` applies) and linking to the platform-admin filtered users list (`/users?filter=admin`). When exactly ONE user holds every admin-tier grant, an amber **bus-factor-of-one banner** renders above the grid (the zero-grant case keeps its stronger existing banner). Every derived element renders INSIDE the polled stats region, so page and 30s polled refreshes stay in parity by construction. Pinned by `dashboard_intelligence_test.go` (empty-window no-delta honesty, midpoint split math, threshold tone, sparkline bucketing + all-zero flat line, caption span truth, polled parity for all cards, adoption presence with a seeded passkey, bus-factor banner matrix at one vs two operators, distinct admin-tier operator count).

- **Global membership directory (super-admin `GET /members`).** The panel could edit a tenant's roster but could not answer "who has access to what" across the installation in one place. The new directory page lists every membership across every tenant resolved to its tenant and its person (email + display name, linked to the user page; bot actors keep their prefixed id), with role chips, a joined column (relative time), a search over email/display name, tenant and role filter chips with live search-scoped counts, a Tenant/Joined ordering toggle, and the shared page-size-bounded windowed pager — filters, chips, ordering, and page all survive each other via one URL builder. The route rides the route table (super-admin mode only, read-only) and the sidebar gains a Members entry in super-admin mode; the same `/members` path keeps serving the tenant-admin roster in that mode — the two handlers are mode-scoped rows of one table and never mount in the same panel. Empty is honest: no memberships anywhere renders an explicit empty state pointing at the tenants page, and a filtered miss says so instead of reading as "none exist". Memberships are resolved per-tenant over one `AllTenants()` pass (the read model has no all-memberships listing method yet — an upstream ask). Pinned by `members_directory_test.go` (render, search, tenant/role chips, unknown-chip degrade, pager at `MinPageSize`, tenant-mode absence) and `e2e/tests/admin-members-directory.spec.ts` (chromium smoke: render + search + tenant chip).

- **Accessibility completion: the contrast design pass + full-surface axe gate + keyboard list navigation.** The first sweep's accepted debt is now fixed, not excused: the ACCEPTED ledger in `admin-a11y.spec.ts` was an unscoped whole-rule `color-contrast` entry covering ~115 pre-existing findings; T15's design pass removed the rule entirely (the ledger is empty, and every adminui surface — tenants/users lists + details, audit page, panel dashboard, import form — sweeps CLEAN at critical/serious). New keyboard contracts in `admin.js` (all document-delegated and re-queried per event — gotcha 57: element-bound JS dies with the pre-swap DOM under hx-boost): "/" focuses the list search, Escape clears it and re-runs the search, ArrowDown/ArrowUp traverse the visible list rows (rows become `tabindex="-1"` programmatic targets, never Tab stops), and after an HTMX swap destroys a focused trigger, focus is restored to the fresh DOM's `data-focus-restore` twin (the audit "Apply dates" button and the pager controls are marked). - **Per-render cache wave: the hot list pages pay one policy pass, not two queries per row.** The users directory resolved every row's platform roles and tenant count with a policy-engine query pair per candidate (`RolesForUser` + `DomainsForUser` + one `GetTenant` per domain), so the admin-filter chip and every page render paid O(rows) Casbin reads. Each render now builds ONE authorization snapshot: a single `GroupPolicies()` pass feeds a subject→platform-roles map and a subject→domains map, and a single `AllTenants()` pass becomes the domain→real-tenant set the tenant count reads by membership. The snapshot's hierarchy-row filter is the same one `usermgmt.HasAdminGrant` uses — a row whose SUBJECT is a role name is a mirrored inheritance edge, not a grant — so a seeded role hierarchy can never manufacture platform admins that do not exist (gotcha 45; pinned by `render_cache_test.go`, which proves snapshot-vs-per-row agreement over grants, memberships, phantom registration domains, and asserts the seeded hierarchy edges really were filtered). The last-seen column's audit-window scan is memoized behind a 30s TTL cache (mutex-guarded, injectable clock seam — no package-level state), so a burst of renders pays one window scan, and the tenants list bounds its `TenantMembers` count queries to the visible page except under the members sort, whose ranking legitimately spans pages. Pinned by `render_cache_test.go` (snapshot parity, hierarchy-subject exclusion, admin-chip truth, TTL reuse/refresh through the clock seam, concurrent readers under `-race`, bounded count scopes) and `users_render_bench_test.go` (200-row page render, req/s metric; raw baseline in `docs/benchmarks/adminui-baseline.raw.txt` — ~400 req/s, ~2.1 MB/op, ~18.8k allocs/op on the capture machine, advisory).

- **Render benchmark (`BenchmarkUsersPageRender`): a measurable perf floor for the directory page.** One benchmark renders a full 200-row users page (the page-size ceiling) against a real in-memory service, with per-request logging suppressed for the run and restored via `b.Cleanup`; it uses `b.Loop` + `ReportAllocs` and reports a req/s metric alongside ns/op and allocs. The raw capture lives in `docs/benchmarks/adminui-baseline.raw.txt` (second of two consecutive runs; header marks it advisory — captured on a shared machine). Re-run with `GOEXPERIMENT=jsonv2 go test ./adminui/ -run XXX -bench BenchmarkUsersPageRender -benchtime=2s` before and after any render-path change.

- **Audit filter depth: date range + actor-kind chips + a retention-honesty caption.** The audit page's omnibox answered "what happened" but not "when" or "by whom": an inclusive from/to date range (YYYY-MM-DD, each bound counting its whole day, server-local) and an actor-kind chip row (user / bot / system / service, the entries' own actor spelling) narrow the window, and every active filter survives the round trip — the inputs re-render with their submitted values and the chips, pager, and HTMX swaps carry the full filter set (the omnibox's wired URL bakes the non-q filters in, so a keystroke search cannot silently drop a date range). A refused filter is announced, never silently dropped: a malformed bound renders an issue naming the input and ignores that half, and a reversed range says so and keeps every row. The empty state distinguishes "nothing recorded at all" from "nothing matches the active filters", and a retention caption built from the audit window's own facts (holds / capacity / rolled-off) says plainly that the journal keeps the full history. Pinned by `audit_filters_test.go` (range boundary matrix, issue + ignore semantics, chip degrade, filter-state round trip, partial swap, caption truth).

- **Per-user activity timeline with load-more (GET `/users/{id}/activity`).** The user detail card showed a fixed glance and the audit page was the only way deeper. The card now pages its stream: an in-card "Load more" fetches the next chunk at the card's page size and appends it in place (the response fragment replaces the trigger row, so rows land directly under the existing ones), ending in an honest "All N events in the audit window are shown." note. Malformed or negative cursors degrade to the beginning (our own links emit the cursor; a malformed one is tampering, not intent), and the route rides the route table with the same super-admin posture as the user detail it extends. Pinned by `audit_filters_test.go` (card + fragment cover the full stream exactly once, exhausted/mid-stream/overrun cursors, tampered cursor degrade, invalid-id refusal, fragment-not-page swaps).

- **Profile-change rows are honest about what the audit window records.** The audit projection records that a display name or email changed but not its old and new payload values, so change rows now say "values not recorded" (with an explanatory title) instead of inviting a fabricated diff; the diff renderer (old struck through, new bold) exists and is the single display source for the day the projection carries payloads. Pinned by `audit_filters_test.go` (honesty note present, no struck-through diff rendered).

- **Dashboard quick actions: Create user / Create tenant, one click from the overview (super-admin).** The dashboard answered "what is happening" but not "do something about it" — creating a user or tenant meant walking through the Users/Tenants list first. The stats region now opens with a quick-actions row linking to the existing `/users/new` and `/tenants/new` forms — no new routes: the creation routes and their forms already existed, and the row links to them. The row renders INSIDE the polled region (the partial response IS the region), so the 30s stats refresh keeps the row instead of dropping it, and page and polled refreshes stay in parity by construction. Mode honesty: both creation routes are super-admin route-table rows, so tenant-admin mode renders nothing rather than a control whose target page does not exist in that mode. Pinned by `stats_partial_test.go` (super-admin presence with form hrefs on the page AND the polled partial; tenant-admin absence on both).

- **`Config.PageSize`: the rows-per-page knob for every paginated list.** The 50 rows per page on the users, tenants, audit, and search lists was a hardcoded constant; a deployment wanting tighter or larger pages had no seam. `Config.PageSize` feeds every `pageBounds` call site (one config value shapes all lists) and is clamped into 10..`MaxListRows` at `New` — clamped, not rejected, because an out-of-range value is a tuning mistake, not an invalid panel; unset keeps the historical 50, so the default changes nothing. Pinned by `pagination_test.go` (clamp boundary cases — below-floor, negative, and above-ceiling values snap to the boundary — plus an end-to-end render test: an 11-user directory splits into two pages at PageSize 10 and stays one 11-row page at the default).

- **The user detail page is honest about authentication state.** The panel rendered the Passkeys, TOTP, and External-accounts surfaces unconditionally, so a deployment without those providers showed dead cards — an empty state that implies an enrollment or link the user can never perform. The page now reads the Service's published capability probes (`HasWebAuthn`/`HasTOTP`/`HasOAuth2`, `ConfiguredOAuth2Providers`) into an `authMethods` snapshot and gates every sign-in surface on it: no WebAuthn provider, no Passkeys card (and no Credentials stat); no OAuth2 provider, no External-accounts card or stat; no TOTP provider, no "TOTP MFA" details row. Dead cards never render — not even as empty states. The same truth powers a first-class rescue signal the panel could not express before: a **"Cannot sign in" badge** (with the last-passkey confirm's blast-radius copy — "locked out of their account until a passkey is re-enrolled, a provider is linked, or TOTP is enabled") fires when a user holds no credential, no linked provider, and no TOTP, i.e. is locked out of their own account; it clears the moment any single channel exists. Pinned by `user_auth_state_test.go` (probe snapshot over bare vs provider-rich services, the cannot-sign-in truth table — credential-only / external-only / TOTP-only / none — at helper and render level, badge clears after a real `AddCredential`), the enriched `user_lifecycle_test.go` dead-card absence pins, and the flipped `oauth_views_test.go` external-card gate. Paper only: the supervised-enrollment rescue design (short-TTL one-time token satisfying owner-match without a session) is drafted for the owner in `docs/decisions/2026-11-24_adminui-supervised-enrollment-note.md`.

## [v4.18.0] - 2026-11-21

### Added

- **User search rides the HTTP QUERY ladder (RFC 10008).** The users panel's search was GET-only; complex criteria (name + status + page) had to squeeze into URL params. New routes: `QUERY /users/search` (the native body-carrying read) and `POST /users/search` (the fallback twin) register the SAME handler, so every rung of the fallback ladder answers byte-identically; `MethodOverrideMiddleware` is wired into the panel's own stack, so a POST + `X-HTTP-Method-Override: QUERY` reaches the native rung (only QUERY is an override target — never an unsafe verb). The search input upgrades Enter-submits to native QUERY via the embedded `cqrs-query` extension (served at `/-/ext/cqrs-query.js`, auto-downgrading only when an intermediary refuses the verb) and fires the POST twin on live typing; the GET route stays the bookmarkable rung the filter chips and history navigate. The criteria ride one shared data path with the GET route (`usersSearchData`), so the rungs cannot drift on filtering, pagination, or enrichment. Pinned by `user_search_test.go` (ladder byte-parity across QUERY/POST/override/legacy-override, body criteria parity with URL params, oversized + malformed body 400s, anonymous 401, extension-script asset posture, rendered ladder attributes) and the e2e chromium ladder tests (request-method assertions: Enter → native QUERY, typing → POST twin).

- **Bulk import form adopts the library's `forms.FileInput`.** The import page's hand-rolled file input (its own label element, a 12-class hand-rolled class string, and a hand-linked help paragraph) moved to templ-components' `forms.FileInput` — the same styled native button, ring focus, and help-text contract as every other form field in the panel, with the `import-file` DOM hook preserved. CSS bundle rebuilt in the same change (the library's file-button utilities are harvested now). Pinned by the existing `TestImportPage_Renders` render assertions (unchanged, they still hold) plus the class-set gate (`check-css-bundle-classes`).

- **Accessibility sweep over the touched surfaces (axe + keyboard), with the first findings fixed.** The panel had never been audited with axe-core; the new `admin-a11y` e2e spec sweeps the tenants/users lists and the tenant/user detail pages (critical/serious only, accepted findings must carry a written reason) and pins the keyboard path through the multi-role grant form: Tab reaches the tenant select, every role checkbox, and the submit; Space toggles; Enter submits — no mouse required. What the first sweep found and this wave fixed: the user-menu trigger was labelled with the bare email (WCAG 2.5.3 Label in Name — the accessible name must contain the full visible text, avatar initials included; it now names initials + email, and the tenant switcher's label names the tenant it currently shows), the users-list filter chips carried `aria-pressed` on links (invalid attribute mapping — the active chip uses `aria-current` now), two icon-only remove buttons (roster, user-page tenant access) had no accessible name at all (now named per target), and the new status chips' gray text missed 4.5:1 (Tailwind v4's gray-500; bumped to gray-600). Remaining debt documented, not hidden: ~115 pre-existing color-contrast findings (accent-tinted brand chrome + gray-400 metadata ramp) accepted with a written reason in the spec — a design pass for a later wave, and the ACCEPTED entry says so.

- **Tenant list polish: lifecycle chips + status filter and member-count sort.** The tenants overview mixed live, suspended, and deleted tenants with no way to narrow the view and only one fixed ordering. Filter chips (All / Active / Suspended / Deleted, each with the search-scoped live count) and a Name / Members ordering toggle ride the URL (`?status=`, `?sort=`), so a narrowed view is shareable; unknown filter values degrade to the unfiltered list rather than an empty one, and the chip precedence matches the status badge exactly, so a chip never promises a row its badge would render differently. Sorting by members counts every matched tenant before paging (the count is computed for the whole match set, not just the visible window). **Delete and suspend preflights name their blast radius** — the confirm dialog states exactly how many memberships the action revokes or cuts off, replacing the vague "remove all memberships" phrasing. Pinned by `tenant_polish_test.go` (status filter narrowing + unknown-value degradation through the HTMX partial, member sort with tiebreak, impact confirms carrying the real counts). NOT shipped from this wave: the per-tenant audit shortcut — the audit log records no tenant lifecycle entries (the audit middleware covers user/session commands only), so the shortcut would land on an empty search; recorded as the usermgmt ask in TODO_LIST item (h).

- **Header tenant switcher (super-admin mode).** Moving between tenants meant walking back to the tenants list every time; the header now carries a dropdown of the live tenants (display-name order) that jumps straight to each tenant's detail page and marks the one being viewed with a check icon — the trigger names it too, so "where am I" is answered at a glance. Suspended and deleted tenants stay out of the list (they are not navigable targets), and tenant-admin mode renders no switcher at all: that mode is scoped to exactly one tenant by construction, so a switcher there would offer navigation that does not exist. Same library Dropdown as the user menu, so native-Popover light-dismiss, Esc, and keyboard navigation come for free. Pinned by `tenant_switcher_test.go` (live-listing with suspended exclusion, tenant-admin absence, current-tenant marking on the detail page).

- **Bulk import/export of users (CSV + JSON, super-admin).** The panel could create users one at a time while the Service has shipped `ImportUsersFromJSON/CSV` and `ExportUsersTo*` since v4.20.0 with no surface — onboarding a team or migrating a directory meant scripting against the API. New routes: `GET /users/import` (the form), `POST /users/import` (multipart upload, dispatched to the published importer), `GET /users/export.csv` / `GET /users/export.json` (streamed straight from the Service — no whole-directory buffering — with `Content-Disposition` naming the file). Guardrails that keep the bulk path honest: the upload is size-capped before the parser reads it (413, not OOM); the CSV header must declare an `email` column or the import is refused up front (the importer maps columns by name and would silently land nothing); existing emails are SKIPPED by the importer itself, so re-running a file is safe and the result says so; and the result panel reports exact imported/skipped counts with a bounded per-row error list (counts exact, list readable). Every imported account is passwordless — the form says so where the create-user form does. Entry points on the users list (Import users, Export CSV). Zero usermgmt change: published v4.20.0 API only. Pinned by `import_export_test.go` (JSON+CSV round-trip through the real streaming handlers, duplicate re-run safety, malformed JSON / headerless CSV / unknown extension refusals, oversized-body 413, service-level end-to-end import, render bound).

### Fixed

- **The tenant/user surfaces now handle their edge states honestly (M03 wave).** Four gaps the tenant-integration wave left open: (1) the grant form's tenant select was a dead end for a user who belongs to every live tenant — the disabled prompt survived filtering and rendered a select with nothing selectable; `withoutTenantOptions` now returns empty when only the prompt remains and the card renders "member of every live tenant" instead of the form. (2) The true-empty users directory ("no users at all") rendered a dead-ended empty state; it now carries a **Create the first user** CTA into the existing new-user form (the search-miss variant keeps its Clear search escape hatch). (3) The inline unknown-email banner downgraded to `role="status"` — the library announces assertively (`role="alert"`) only for error-class feedback, and a failed grant IS an error-class miss, so the banner is now `FeedbackError` and screen readers announce it. (4) Member removal confirmed with one line no matter the blast radius: removing the tenant's ONLY admin-tier (admin/owner) holder now escalates the confirm dialog on both surfaces (roster + user page, passkey-case style: "the tenant would be left without an admin"), backed by a bounded per-tenant admin count the detail handler computes for the visible rows. Also in this change: `data-sync-target` markers on the tenant identity card and the user's tenant-access card — the ADR-0056 regions whose content moves outside a navigation. Pinned by `edge_states_test.go` (member-of-every-tenant, empty CTA, alert semantics, sync targets, last-admin escalation on both surfaces with its disappearance once a second admin exists) and the trued `user_tenant_access_test.go`/`handler_test.go` expectations.

- **A member can finally HOLD the two roles the API always allowed: the single role select became a checkbox group on both membership surfaces.** identity-model memberships are role SETS (`AssignableRoles()` = viewer/user/admin/owner), but both the tenant roster's per-row control and the user page's tenant-access row rendered ONE `<select>`, so correcting a multi-role membership meant two writes that fought each other — and the add-member form silently flattened a set to one role. The new `roleCheckboxGroup` primitive (one templ component, both surfaces: tenant roster rows, tenant add-member form, user-page grant + per-row controls) posts `roles` as a multi-value field — the same field name and parsing the platform-access card already uses.
