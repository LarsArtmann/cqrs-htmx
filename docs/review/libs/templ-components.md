## Popover anchoring — upstream fix LANDED (v1.27.1); vendored-layer retirement pending

Root-caused 2026-11-05: `tcPopoverPosition` (upstream `display/shared.go:329-336`) defers to the CSS anchor layer on Chromium ≥125, but the library's compound `position-area` values were rejected by the engine (declaration drops, popover parks at the viewport corner). **Upstream status: FIXED.** [PR #101](https://github.com/LarsArtmann/templ-components/pull/101) ("position-area alignment bands use x-axis spellings", branch `fix/popover-x-axis`, filed 2026-11-16 from this repo) **merged 2026-11-17** (`0cbee16c`) and shipped in **v1.27.1**; the library's `custom.css` now uses the accepted `span-x-start`/`span-x-end` spellings (`templ-components/templates/custom.css:160-172`, comment block `:105-125` carries the empirical Chromium 152.0.7977.82 receipt). This repo rode the fix on the v1.27.2 train.

**What the vendored adminui layer still is:** the corrected layer at `adminui/tailwind.css:316-380` remains in place. Its band half (single-keyword `position-area` values) is now redundant with upstream; its unique remaining value is the explicit `anchor-name`/`position-anchor` pair that flushes the user-menu's inline-end edge with the trigger's (`adminui/tailwind.css:375-380`) — upstream's layer is bands-only by design ("no per-instance anchor names required", `custom.css:111-118`), so wholesale deletion would drop the user menu to anchor-centered band placement. Two staleness notes: the vendored block's header comment still describes the pre-#101 library layer as broken, and still carries the "Chromium 156" probe claim that AGENTS.md trued to 152 on 2026-11-16. **Owning row:** TODO_LIST "templ-components PR-#101 release watch" — retirement = vendored block deleted (or slimmed to the user-menu instance) + visualtest green same-change. Severity: Minor (rendering is correct today; this is hygiene). Flip trigger: that TODO row's verify clause.
