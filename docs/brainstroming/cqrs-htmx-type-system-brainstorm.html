1.1 Core Design Principles (Current)

  • Framework-agnostic: No router dependency. Works with net/http, Gin, Chi, Echo.
  • Zero mutual imports: Root and usermgmt are fully independent. Cross-module bridging only in integration_test.
  • Flat root package: 19 files form a cohesive "HTMX-aware CQRS HTTP integration" library. Sub-package extraction would harm consumer UX.
  • Interface-driven: Enforcer enables mock/fake enforcers. UserStore/SessionStore enable swapping backends.
  • Library principle: Never enforce defaults consumers might disagree with (no mandatory CSP/HSTS, no mandatory CSRF).

1.2 The Inseparable Cycle

Critical: Three files form a dependency cycle that prevents further splitting:
errors.go → response.go → csrf.go → errors.go
Any module boundary would cut through this cycle. This is intentional and correct for a cohesive library.

3. Identified Gaps & Type-Safe Improvements

3.1 The any Problem

Issue: Query dispatch returns any. Render functions receive any. This is the biggest type-safety hole. 
// CURRENT (lossy):
func (a *App) Query(qryType query.Type, opts ...HandlerOption) http.HandlerFunc
// result is any inside the handler
// cfg.render receives (w, r, result any)

// RenderTemplResult does a runtime type assertion:
func RenderTemplResult[T any](mapper func(T) TemplComponent) HandlerOption {
    return func(cfg *handlerConfig) {
        cfg.render = func(w, r, result any) error {
            typed, ok := result.(T)  // <-- runtime check, compile-time unknown
            ...
        }
    }
}

Proposed Fix: Typed Query Registration

go-cqrs-lite v2 already has RegisterTyped / DispatchTyped. We should expose this:

// PROPOSED:
func QueryTyped[Q query.Query, R any](
    app *App,
    qryType query.Type,
    opts ...HandlerOption,
) http.HandlerFunc {
    return func(w http.ResponseWriter, r *http.Request) {
        // decode into Q
        // dispatch returns R (typed, not any)
        // render receives R directly
    }
}

// Consumer usage:
app.QueryTyped[GetUserQuery, *User]("GetUser",
    cqrshtmx.DecodeJSONQuery[GetUserQuery](...),
    cqrshtmx.RenderJSON[*User](),
)

This eliminates the any intermediary entirely. The compiler knows R at every stage.

3.2 HandlerOption Is Not Type-Safe

HandlerOption is a closure over *handlerConfig. It cannot enforce at compile time that you only set command decoders on commands, or query decoders on queries.

// CURRENT: This compiles but fails at runtime:
app.Command("CreateUser",
    cqrshtmx.DecodeJSONQuery[GetUserQuery](...), // WRONG: query decoder on command
)

// PROPOSED: Phantom type parameter
// Not possible without breaking the fluent API, BUT we can use type constraints:

type CommandHandlerOption interface {
    applyToCommand(*handlerConfig)
}

type QueryHandlerOption interface {
    applyToQuery(*handlerConfig)
}

func (a *App) Command(cmdType command.Type, opts ...CommandHandlerOption) http.HandlerFunc
func (a *App) Query(qryType query.Type, opts ...QueryHandlerOption) http.HandlerFunc
Trade-off: This adds API surface. The current HandlerOption with runtime checks inside buildHandlerConfig is simpler. For a library, simplicity wins unless the type safety unlocks major DX improvement.

3.3 Result[T] Type

Go's error handling is verbose. A generic Result[T] can make query pipelines composable:

// PROPOSED (in root or a shared subpackage):
type Result[T any] struct {
    value T
    err   error
}

func Ok[T any](v T) Result[T]  { return Result[T]{value: v} }
func Err[T any](e error) Result[T] { return Result[T]{err: e} }

func (r Result[T]) IsOk() bool      { return r.err == nil }
func (r Result[T]) Value() T        { return r.value }
func (r Result[T]) Err() error      { return r.err }
func (r Result[T]) Unwrap() (T, error) { return r.value, r.err }

// Map transforms a Result without unwrapping
func Map[T, U any](r Result[T], fn func(T) U) Result[U] {
    if r.err != nil {
        return Err[U](r.err)
    }
    return Ok(fn(r.value))
}

// Use in render pipeline:
func RenderResult[T any](r Result[T], w http.ResponseWriter) error {
    if !r.IsOk() {
        return r.Err()
    }
    return json.NewEncoder(w).Encode(r.Value())
}

Library principle check: Should this live in cqrs-htmx or a separate utility module? Given it's generic and widely useful, a separate go-result micro-package might be better. But providing it here reduces consumer friction.

3.5 Generic Store Interface

Currently UserStore and SessionStore are hand-rolled per entity. With generics, we can define a base Store[T, ID] and specialize:

// PROPOSED (in usermgmt or sqlstore):
type Store[T any, ID comparable] interface {
    FindByID(ctx context.Context, id ID) (T, error)
    Save(ctx context.Context, entity T) error
    Create(ctx context.Context, entity T) error
    Delete(ctx context.Context, id ID) error
}

type UserStore interface {
    Store[*User, UserID]
    FindByEmail(ctx context.Context, email string) (*User, error)
}

// In-memory generic implementation:
type InMemoryStore[T any, ID comparable] struct {
    mu      sync.RWMutex
    items   map[ID]T
    indexes map[string]func(T) string // generic index support?
}
Caution: Generic Store[T, ID] is elegant but may be too abstract for real-world SQL stores where each entity has different columns, joins, and query patterns. Use it for the interface contract, not for a universal implementation.

4. Deep Dive: Generics Opportunities

4.1 Type-Safe Context Keys

Current context keys use empty structs. We can make them type-safe with generics:

// CURRENT:
type userIDKey struct{}
func WithUserID(ctx context.Context, id UserID) context.Context {
    return context.WithValue(ctx, userIDKey{}, id)
}
func UserIDFromContext(ctx context.Context) UserID {
    v, _ := ctx.Value(userIDKey{}).(UserID)
    return v
}

// PROPOSED: Generic context key
type contextKey[T any] struct{ name string }

func (k contextKey[T]) WithValue(ctx context.Context, v T) context.Context {
    return context.WithValue(ctx, k, v)
}

func (k contextKey[T]) FromContext(ctx context.Context) (T, bool) {
    v, ok := ctx.Value(k).(T)
    return v, ok
}

var userIDKey = contextKey[UserID]{name: "user_id"}
var correlationIDKey = contextKey[CorrelationID]{name: "correlation_id"}

// Usage:
ctx = userIDKey.WithValue(ctx, uid)
uid, ok := userIDKey.FromContext(ctx) // returns (UserID, bool) -- type-safe!

Benefit: No type assertion at retrieval site. The compiler guarantees the type. Zero runtime cost (key is still a struct, just parameterized).

4.2 Sum Types via Generics

Go doesn't have algebraic data types, but we can approximate sum types:

// PROPOSED: Either[L, R] for operations that can fail with typed errors
type Either[L, R any] struct {
    left  L
    right R
    isLeft bool
}

func Left[L, R any](v L) Either[L, R]  { return Either[L, R]{left: v, isLeft: true} }
func Right[L, R any](v R) Either[L, R] { return Either[L, R]{right: v} }

func (e Either[L, R]) IsLeft() bool  { return e.isLeft }
func (e Either[L, R]) IsRight() bool { return !e.isLeft }
func (e Either[L, R]) Left() L      { return e.left }
func (e Either[L, R]) Right() R     { return e.right }

// Use case: Auth result is either User or AuthError
type AuthResult = Either[AuthError, *User]

func (s *Service) Authenticate(ctx context.Context, token string) AuthResult {
    session, err := s.sessions.Find(ctx, token)
    if err != nil {
        return Left[AuthError, *User](AuthError{Reason: "invalid_session"})
    }
    user, err := s.users.FindByID(ctx, session.UserID)
    if err != nil {
        return Left[AuthError, *User](AuthError{Reason: "user_not_found"})
    }
    return Right[AuthError, *User](user)
}

Library principle check: This is powerful but adds conceptual weight. Provide as an optional package (cqrshtmx/optional?) rather than forcing it on all consumers.

4.3 Phantom Types for State Machines

Encode state in the type system to prevent invalid transitions at compile time:

// PROPOSED: Type-safe HTTP response state machine

// States
type Uncommitted struct{} // headers writable, status unset
type Committed struct{}   // headers frozen, status set

// Response is parameterized by its state
type Response[S any] struct {
    w          http.ResponseWriter
    r          *http.Request
    statusCode int
}

// Only Uncommitted responses can set headers
func (resp *Response[Uncommitted]) PushURL(url string) *Response[Uncommitted] { ... }
func (resp *Response[Uncommitted]) Status(code int) *Response[Committed] { ... }

// Only Committed responses can write body
func (resp *Response[Committed]) Body(data []byte) *Response[Committed] { ... }

// Usage:
resp := NewResponse[Uncommitted](w, r)
resp.PushURL("/users").Status(200).Body(html) // compiles
resp.Status(200).PushURL("/users")             // COMPILE ERROR: PushURL not on *Response[Committed]
Win: Prevents the classic bug of writing headers after WriteHeader has been called. The compiler enforces correct ordering.

4.4 Constraint-Based APIs

Use type constraints to restrict what types can be used with generic functions:

// PROPOSED: Only types with a Validate() error method can be decoded
type Validatable interface {
    Validate() error
}

func DecodeAndValidateJSON[T Validatable](
    mapper func(T) (command.Command, error),
) HandlerOption {
    return DecodeJSON(func(t T) (command.Command, error) {
        if err := t.Validate(); err != nil {
            return nil, err
        }
        return mapper(t)
    })
}

// Usage: RegisterRequest.Validate() is automatically called
app.Command("Register", cqrshtmx.DecodeAndValidateJSON[RegisterRequest](
    func(req RegisterRequest) (command.Command, error) {
        return RegisterCmd(req), nil
    },
))

4.5 Generic Middleware Composition

Current Chain uses variadic functions. We can make it type-aware:

// PROPOSED: Middleware that transforms request types

type Middleware[T any] func(http.Handler) http.Handler

// Typed middleware: transforms *http.Request into a richer type
func WithTypedContext[T any](
    extract func(*http.Request) (T, error),
) func(http.Handler) http.Handler {
    return func(next http.Handler) http.Handler {
        return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
            t, err := extract(r)
            if err != nil {
                http.Error(w, err.Error(), 400)
                return
            }
            ctx := context.WithValue(r.Context(), typedContextKey[T]{}, t)
            next.ServeHTTP(w, r.WithContext(ctx))
        })
    }
}

// Retrieve typed value without type assertion:
func TypedFromContext[T any](ctx context.Context) (T, bool) {
    v, ok := ctx.Value(typedContextKey[T]{}).(T)
    return v, ok
}

5.4 Transaction Boundary

// PROPOSED: Generic transaction runner
type TxFunc func(ctx context.Context) error

func (s *Store) WithTx(ctx context.Context, fn TxFunc) error {
    tx, err := s.db.BeginTx(ctx, nil)
    if err != nil {
        return mapSQLError(err)
    }
    defer tx.Rollback() // safe: no-op after Commit

    txCtx := WithTxContext(ctx, tx)
    if err := fn(txCtx); err != nil {
        return err // tx.Rollback() called by defer
    }
    return tx.Commit()
}

// Context-scoped transaction retrieval
func TxFromContext(ctx context.Context) (*sql.Tx, bool) {
    v, ok := ctx.Value(txKey{}).(*sql.Tx)
    return v, ok
}

// Store methods use tx if present, otherwise db
func (s *PostgreSQLUserStore) execer(ctx context.Context) sqlExecer {
    if tx, ok := TxFromContext(ctx); ok {
        return tx
    }
    return s.db
}
Win: The usermgmt Service.Register compensating-transaction logic becomes a real atomic transaction. No more manual rollback chains.

6. Advanced Type System Techniques

6.1 Sealed Interfaces (Go 1.22+ via method unexporting)

Prevent external implementations of sensitive interfaces:

// PROPOSED: Sealed EventHandler

type EventHandler interface {
    HandleEvent(ctx context.Context, evt Event) error
    seal() // unexported: only we can implement
}

type eventHandlerFunc struct {
    fn func(context.Context, Event) error
}

func (h eventHandlerFunc) HandleEvent(ctx context.Context, evt Event) error {
    return h.fn(ctx, evt)
}
func (h eventHandlerFunc) seal() {} // satisfies interface

// Consumers can only use the constructor, not implement their own
func EventHandlerFunc(fn func(context.Context, Event) error) EventHandler {
    return eventHandlerFunc{fn: fn}
}

9. Summary: The Path to Perfection

Current Strengths

  • Branded IDs prevent accidental mixing
  • Generic decoders deduplicate 4 variants
  • Duck-typed TemplComponent avoids templ dependency
  • authMode enum makes impossible states unrepresentable
  • Zero mutual imports = clean module boundaries
  • Context key sentinels prevent collisions

Immediate Wins

  • Adopt QueryTyped[Q,R] to kill any
  • Generic contextKey[T] for type-safe storage
  • PaginatedResult[T] for list queries
  • sqlstore module with numeric branded IDs
  • Transaction boundary WithTx
  • Sealed interfaces for sensitive contracts

Future Vision

  • Phantom-typed Response[State]
  • Generic Result[T] for pipeline composition
  • Type-safe event metadata builders
  • Constraint-based decode+validate
  • Generic middleware with typed context
  • Redis/BadgerDB stores via same interfaces

What NOT to Do

  • Don't split the root package further (coupling cycle)
  • Don't force Result[T] on all consumers
  • Don't build a universal generic SQL store (too abstract)
  • Don't add generics where interfaces suffice
  • Don't break zero-mutual-import boundary
  • Don't make the API clever at the cost of clarity
The Goal: Every compile should guarantee that IDs aren't mixed, responses are built in the right order, transactions are atomic, and query results flow through the system with their types intact. Runtime type assertions should be a code smell, not a necessity.
