# V007 Spike Plan — `stack.Bundle` → `system.New` composition (usermgmt)

**Status:** PREPARED (spike deferred; rationale below). Written 2026-09-10 per the
Pareto plan Round 2 task P26 — "branch or ADR note if deferred".
**Scope:** the 3 usermgmt files still building on go-cqrs-lite's deprecated
`stack/v4` API — `es_setup_core.go` (1 site), `stack_repositories.go` (5 sites),
`es_materialize_adapter.go` (8 sites; includes `Materialize` + `IncludeTombstoned`).

## Why defer the code spike

1. **The hard part is already proven.** `TestDeclarative_EquivalenceWithProjectionLayer`
   (systemadapter/declarative_test.go) dispatches identical event sequences
   through the legacy ProjectionLayer and the declarative
   `DomainConfig.Projections` path and asserts fold-equivalence. The
   `systemadapter` fix of 2026-09-10 (external-account unlink) hardened exactly
   this equivalence class. Migrating usermgmt's four read models follows the
   same recipe — it is mechanical, not exploratory.
2. **The remaining risk is behavioral, not compositional.** The
   `stack.Materialize` folds in `es_materialize_adapter.go` carry
   tombstone/`IncludeTombstoned` semantics (ADR-0114 migration remnants). The
   declarative path's `Remove`-style folds need a one-to-one mapping for each of
   the 8 sites; that mapping must be driven by the existing
   `es_materialize_adapter_test.go` expectations, which is exactly what a spike
   would discover — but only worth doing when the migration itself is scheduled,
   not before.
3. **No master risk is currently carried.** The stack.* usage is
   verified-functional on v4 and lint-exempted with a removal-conditioned rule
   (`usermgmt/.golangci.yml`, "V007 v5-migration debt"). Nothing degrades while
   this sits.

## Spike recipe (when scheduled — ~90m)

1. `git worktree add ../cqrs-htmx-v007 v007-spike` (never the main tree; master
   and any running gates stay untouched).
2. In the worktree, replace `NewEventSourcedSetup`'s stack.Bundle construction
   (`es_setup_core.go`) with `system.New(ctx, DomainConfig(), DeploymentConfig)`
   + `systemadapter.NewProjectionLayer`-free declarative registration.
3. Migrate `stack_repositories.go` repository factories one aggregate at a time
   (user → tenant → membership → bot), running the aggregate's fold tests after
   each.
4. Port the 8 `stack.Materialize` sites in `es_materialize_adapter.go` to
   declarative folds, mapping `IncludeTombstoned` to `DeleteTypes`/`Remove`
   semantics; keep `es_materialize_adapter_test.go` as the behavioral oracle —
   it must pass UNMODIFIED except for import paths.
5. Verify: `GOEXPERIMENT=jsonv2 GOWORK=off go test . -race -count=1` in
   usermgmt + systemadapter, then the full ladder via
   `bash scripts/bump-verify.sh --skip-bench`.

## Exit criteria

- `usermgmt/.golangci.yml`'s scoped SA1019 exclusion DELETED (the rule carries
  its own removal condition).
- `docs/guides/v5-removal-inventory.md` class 4's stack.* entries collapsed.
- Bench-spike gate unchanged (no measured-path deltas) or re-pinned per policy.
