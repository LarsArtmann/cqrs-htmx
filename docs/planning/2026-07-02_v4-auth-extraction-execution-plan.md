> **Date:** 2026-07-02
> **Status:** Active
> **Goal:** Release v3.5.0, then extract TOTP/WebAuthn/OAuth2 behind interfaces as independent v4 modules

## 1. Brutal Self-Review

### What Did We Forget?

1. **v3.5.0 tags NOT pushed.** The release was tagged locally but never published. Consumers cannot `go get` it. A release that isn't pushed to remote is not a release — it's a local annotation.
2. **Dirty working tree at release time.** Two `adminui/*_templ.go` files have uncommitted codegen churn. The tag was placed on a tree that BuildFlow then mutated.
3. **go.mod version string drift.** `usermgmt/go.mod` declares `cqrs-htmx/v3 v3.3.0` in the require block (masked by `replace => ../`). Not breaking but misleading for anyone reading the file.

### What's Stupid That We Do Anyway?

1. **Committed generated code that keeps churning.** `*_templ.go` files are committed AND regenerated by BuildFlow's pre-commit hook, causing constant diff noise. The installed templ CLI (v0.3.1036) generates `var x =` + single-line imports, while older commits used `x :=` + grouped imports. Every commit fights this.
2. **25,941-line god package.** `usermgmt` has ~84 prod files in one flat `package usermgmt`. Five auth-related deps (go-webauthn, pquerna/otp, oauth2, go-oidc, go-jose) are forced on ALL consumers even if they only want basic user CRUD.
3. **Ghost interface.** `auth_interfaces.go` defines `TOTPVerifier` with a compile-time assertion — but nothing USES the interface. The Service still holds `*TOTPConfig` directly. The interface is a ghost system that proves a contract but delivers zero value until wired.

### What Could We Still Improve?

1. **ServiceConfig is a god-config.** 20+ fields mixing core, auth, persistence, and security concerns. Should be composed: `ServiceConfig{ Core, Auth{TOTP, WebAuthn, OAuth2}, Persistence }`.
2. **TOTP extraction is trivial but keeps getting deferred.** 1 file (244 lines), 1 dep (pquerna/otp), interface already designed. The cost of delay is zero progress on the v4 promise.
3. **encoding/json/v2 available.** Go 1.26.3 supports `encoding/json/v2`. Not urgent but worth adopting for performance.

### Ghost Systems & Split Brains

- **TOTPVerifier interface**: Ghost — designed, verified, unused. Must be wired to deliver value.
- **WebAuthnProvider/OAuth2Provider interfaces**: Even bigger ghosts — "v4 target shapes" that current Service doesn't even satisfy yet.
- **Two UserID types**: Documented split brain (root `id.UserID` vs usermgmt `brandid.ID`). Bridge exists but trap remains.

## 5. Type Model Considerations

### ServiceConfig Composition (deferred to v4.1+)

Current: flat 20+ field struct. Better:

```go
type ServiceConfig struct {
    Core          CoreConfig
    Auth          AuthConfig      // { TOTP, WebAuthn, OAuth2 }
    Persistence   PersistenceConfig // { ReadModelDB, SecurityHooks }
}
```

**Decision: DEFER.** Orthogonal to extraction. Mixing two refactors doubles risk.

### TOTP Secret as Branded Type (not worth it)

`TOTPSetupResponse.Secret` is `string`. Could be branded to prevent logging. But it's short-lived (returned to caller, never stored). Not worth the complexity.

### AuthResult Already Clean

`WebAuthnProvider.FinishLogin` returns `*AuthResult` — good domain type. No change needed.
