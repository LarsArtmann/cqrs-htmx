Extract identity-model Domain Module

A pure Go type/domain-model module for event-sourced identity management: Users, Tenants/Orgs, Sessions, Auth — zero infrastructure dependencies.

Date: 2026-07-23 Module: identity-model/v4 Scope: Domain types only (no HTTP, no SQL, no Casbin)
TL;DR

Extract all pure domain types from usermgmt into a new identity-model Go module within the workspace. This module contains only types: identifiers, value objects, event payloads, command structs, aggregate states, fold functions, auth domain types, session types, error sentinels, and interface contracts. Zero dependencies on HTTP frameworks, SQL drivers, or Casbin. The existing usermgmt module will depend on identity-model and re-export types for backward compatibility.

Key design decision: errors.go decoupled from HTTP

The current usermgmt/errors.go uses cqrshtmx.WithHTTPStatus() to attach HTTP status codes to domain errors. The pure domain model defines errors using only errorfamily (Rejection/Conflict/Transient classification). HTTP status mapping is the infrastructure layer's concern — usermgmt retains the status-mapping wrappers for backward compatibility.

Backward compatibility strategy

usermgmt will import identity-model and provide type aliases (type UserID = model.UserID) so existing consumers see zero API breakage. The errors.go in usermgmt will wrap the domain errors from identity-model with HTTP status codes, preserving the current behavior. No consumer code changes needed.
