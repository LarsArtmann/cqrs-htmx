01Pareto Breakdown

The 80/20 lens applied to remaining work only. Phase 0 (production JournalSSEStore) and Phase 1 server-side (ACK protocol: CommandAck, BroadcastOnAck, BroadcastOnAckWS) are committed and pushed.

The 1% → 51% — Prove it works & track it

The integration test is the single highest-leverage task. Unit tests prove each piece in isolation, but nothing proves JournalSSEStore + Broadcaster + BroadcastOnAck work together in a real HTTP handler. If the integration test fails, it reveals Phase 0/1 bugs before we build honest UI on top of a broken foundation. Docs (TODO_LIST, CHANGELOG, README) make the shipped work discoverable and tracked.

The 4% → 64% — Honest UI CSS + JS core

This makes the ACK protocol user-visible: the actual honest UI. Pending items appear immediately (optimistic) but look different (dashed/muted, yellow dot) until the ACK arrives, then flip to confirmed (solid, green) or rejected (red, inline error + retry). Driven by data-sync-state DOM attributes reacting to CSS. Never-silent rollback — the cardinal sin of standard optimistic UI.

The 20% → 80% — Full honest UI + demonstrable demo

Counter, global indicator, retry buttons, accessibility (aria-live), optimistic render on htmx:beforeRequest. Plus admin-demo wiring (Broadcaster + SSE endpoint + BroadcastOnAck hook) so the whole lifecycle is runnable at localhost:8097.

The 80% → 20% — Phase 2 research (deferred)

Offline queue, Service Worker / SharedWorker, OPFS, local decide(). Substantially more complex and blocked on Q1/Q2 product decisions. Included in this plan for completeness but not on the critical path.

05Architecture Decisions Embedded

Decision Rationale
Integration test is Tier 1, not verification If it fails, it reveals Phase 0/1 bugs before honest UI is built on top. Proof before polish.
Sync commands, not events Commands are re-decidable against fresh state; events are immutable. Prevents invariant violations (Greg Young). ADR 0023.
Honest UI via data-sync-state DOM attribute No IndexedDB, no client store. CSS classes react to the attribute. ADR 0024.
ACK is opt-in (X-Command-Id header) No header, no ACK broadcast. Respects the library principle (no forced opinions).
Never-silent rollback is mandatory Standard optimistic UI's silent disappearance is the cardinal sin. Rejected items stay visible with retry.
Phase 2 deferred pending Q1/Q2 Where does decide() run? Must writes survive closed tabs? Cannot design offline queue without these.
