Pareto-ranked execution plan for making HTMX + DataStar dual support a first-class, documented, tested feature — and for the demand-gated panel variants beyond it. Derived from the research report docs/architecture-understanding/2026-09-07_datastar-dual-frontend-support.html.

Total estimated effort

The 1% that delivers 51%

M1 + M2 + M3: a setup.Config.DataStar opt-in that mounts /datastar.js and a DataStar SSE feed on the same hub as the existing HTMX feed (via NewBroadcasterFromHub), plus the route-split coexistence recipe in the fullstack-wiring guide. Dual support stops being tribal knowledge and becomes a shipped, tested, documented feature. Total: ~2.25h.

Deliberately excluded from the 1%

Converting adminui/dashboardui/loginpage to dual-mode rendering (Model B in the research report) is the highest-effort, lowest-certainty work and stays demand-gated in P4. The library principle ("never enforce defaults") also prohibits bundling DataStar into the existing panels' dependency trees.

05Risks & Guards

Guard

Do not regress the library principle

setup/go.mod · ROADMAP.md library principle

The setup module must not gain a hard dependency that changes default installs' behavior; DataStar stays opt-in (Config.DataStar defaults false). No existing consumer sees any change.

Guard

Hermetic verification only

AGENTS.md gotchas · go caches on /tmp

Workspace mode masks broken requires. Gate sweep runs GOWORK=off per module, with the /tmp cache layout (scripts/lib/go-cache-env.sh); check df /tmp before the batch.

Guard

Never hand-revert adminui/styles.css

AGENTS.md 2026-08-30 gotcha

The pre-commit hook regenerates the minified artifact; whatever it produces is canonical. P4's adminui work must respect this.

Note

Commit promptly (shared tree)

AGENTS.md concurrent-sessions gotcha

An auto-git daemon commits dirty files wholesale; verify gates then commit immediately so attribution stays correct.
