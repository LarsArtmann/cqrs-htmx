## Reading the numbers

- **ns/op overhead:** ~3µs / ~10k req/s of the appkit middleware stack on top of httputil's bare Server. Disappears in any real handler doing I/O.
- **allocs/op gap:** ~30 extra allocations per request — the real per-request cost the appkit stack adds. Recovery → RequestID → Logging → SecurityHeaders is a non-trivial chain.
- **Variance:** the run-5 spike in appkit (32950 ns/op) is scheduler jitter, not regression — the B/op + allocs/op columns are flat across runs. Use `benchstat` (not raw eye-balling) for any before/after comparison.
- **Comparison-report finding 7 context:** the original 16178 vs 45049 ns/op delta was 80% per-request INFO logging (a formatted charmbracelet/log line per request). Pinning `LogLevelError` removes that — the honest comparison is 16178 vs ~20000.

## Why these knobs are load-bearing

- `LogLevelError` is mandatory — without it, appkit's per-request INFO log line dominates the measurement.
- `DrainDelay: 10ms` keeps the per-iteration shutdown cost near zero — b.N scales by elapsed time, so an in-timer 2s drain would poison every measurement.
- `b.Cleanup(b.StopTimer(); stop())` ensures the (short) drain happens AFTER the timer has stopped.
- `b.ReportMetric(req/s)` adds a throughput column for human-readable at-a-glance comparison.
- `b.Cleanup(slog.SetDefault(prevLogger))` keeps the surrounding suite's logs intact.
