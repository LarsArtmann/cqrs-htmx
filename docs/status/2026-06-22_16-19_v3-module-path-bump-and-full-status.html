+
Identity model redesign (ADR-0015) Tenant (create/suspend/reactivate/delete), Bot (register/delete/resolve-by-token), Membership (add/update-roles/remove), Impersonation (begin/end). All event-sourced with pure deciders + read model projections. CasbinProjection derives policies for all identity events.
+
WebAuthn passwordless authentication go-webauthn v0.17.4. Full registration + login ceremonies. In-memory challenge store with proactive eviction. Account lockout wired into login flow. Credential management HTTP endpoints.
+
OAuth2/OIDC integration (ADR-0014) Dual-mode providers (OIDC discovery + pure OAuth2). PKCE S256 on every flow. Subject-first matching. Global provider+subject uniqueness. 2 events, 2 commands, 3 HTTP endpoints. Google (OIDC) + GitHub (OAuth2) both covered.
+
SSE + WebSocket real-time (ADR-0004, 0010) Full transport parity: Broadcaster fan-out (O(1) unsubscribe), SSE reconnection (SSEEventStore + ReplayEvents), CQRS dispatch bridges (BroadcastOnSuccess/OnError), WS message parser + encoder, WS dispatch bridge. Generic fanOut[T] shared by SSE + WS.
+
CSRF + Rate Limiting + Security Headers justinas/nosurf CSRF with custom header/field translation + per-handler CSRFProtect. Token-bucket rate limiter with min-heap O(log n) eviction. SecurityHeadersMiddleware with configurable CSP/HSTS. All opt-in (library principle).
+
Catalog sub-package (ADR-0008, 0009) Independent Go module. Builder API with generics. OpenAPI + AsyncAPI + D2 handlers. EventCatalog MDX export. Schema reflection from struct tags. BuildValid() for non-panic validation. Zero dependency on root or usermgmt.
+
Event signing + encryption (opt-in) (ADR-0011) Dependency-free seams: StoreWrapper, PublishMiddleware, HandlerMiddleware. Store-level encryption + bus-level signing. Consistent with duck-typing pattern (Enforcer, TemplComponent). Consumers who don't need crypto pull zero new deps.
+
TOTP MFA + Email verification + Import/Export pquerna/otp/totp (audited). Two-phase TOTP setup with event-sourced secret. Email verification with single-use tokens. JSON/CSV import/export with admin authorization + per-IP rate limiting.

go-error-family adoption (0 violations) NO stdlib error constructors (errors.New, fmt.Errorf, errors.Join banned). Enforced by branching-flow errorfamily. All errors use event.New*/Wrap*/Wrapf/Newf. Family assignment rules mapped to HTTP status. Dispatch wrapping preserves inner domain family.

05Section E — WHAT WE SHOULD IMPROVE!

Documentation hygiene as a habit

FEATURES.md and ROADMAP.md drifted badly because nobody updated them when features shipped. The fix isn't just updating them once — it's making the update part of the definition of done. Every PR that adds a feature updates FEATURES.md. Every version bump updates ROADMAP.md.

Coverage gate in CI

usermgmt coverage dropped 6 points silently. A CI gate that fails on coverage regression (<85% for usermgmt, <93% for root) would prevent this. Even a simple go test -coverprofile + threshold check in the nix flake would catch it.

Service-level test coverage for identity model

Tenant, Bot, Membership, and Impersonation all have decider-level tests but only Tenant and Bot have service-level tests (added this session). Membership and Impersonation need service-level tests through full dispatch to verify the event → projection → read model → Casbin policy pipeline.

Projection replay test

The manual projection replay (~130 LOC in es_projection_setup.go) replaced the upstream projection.Runner but has no integration test verifying that events replayed from the journal match events received live. A single test that writes events, restarts projections, and verifies read model state would provide confidence.

Consumer migration documentation

The /v2 → /v3 bump is a breaking change for every consumer. Without a migration guide, adoption friction is high. The guide should cover: import path changes (mechanical), bus type change (watermill.EventBus), projection mechanics (manual replay vs projection.Runner), and the Apply vs Fold rename.

Fuzz testing expansion

Only SQLSessionStore has fuzz tests. The projection dedup logic, event payload unmarshaling, and the new identity model decide functions would all benefit from fuzz testing. Property-based testing (rapid) exists for foldUser but not for the new Tenant/Bot/Membership deciders.
