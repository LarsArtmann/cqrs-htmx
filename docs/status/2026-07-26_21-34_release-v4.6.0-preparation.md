## Critical Discovery: Stream Rename Was Unnecessary

The prior session's plan (`docs/planning/2026-07-26_21-05_release-v4.6.0-preparation.md`) proposed renaming `id.StreamRef` → `id.AggregateRef`, `id.StreamID` → `id.AggregateID` across ~35 sites, claiming published `id/v4 v4.0.3` only had `Aggregate*` names.

**Empirical verification proved this FALSE:**

- Root `go.mod` references `id/v4 v4.1.0` (not v4.0.3).
- Published `id/v4 v4.1.0` HAS the `Stream*` symbols.
- GOWORK=off builds PASS for root, identity-model, usermgmt, integration_test, and all examples EXCEPT those affected by the lockstep issue.
- GOWORK=off `go vet` (which compiles test files) PASSES for root.

The rename would have been wasted effort that contradicted the v4.5.0 CHANGELOG entry ("go-cqrs-lite API updates propagated: AggregateID → StreamID"). It was correctly SKIPPED.
