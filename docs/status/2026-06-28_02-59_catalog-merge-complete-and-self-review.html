b) Partially Done

Deferred · Critical

ActorID split brain (root vs usermgmt)

Root module defines type ActorID string; usermgmt defines type ActorID struct{ kind ActorKind; raw string }. Intentionally different — root needs a simple context value, usermgmt needs kind/raw separation for domain logic. The real fix requires a shared identity module both can import. Current bridge: string(actorID) + ParseActorID. See docs/adr/0018-unify-userid.md.

Blocked · Serialization

Email branded type in event payloads

Email branded type exists but 10+ structs (UserState, UserRegisteredPayload, ExternalAccount) still use raw string. Changing them breaks JSON event serialization (existing events in stores have "email": "user@example.com"). Safe for new fields, unsafe for existing payloads. Deferred to next major version with an upcaster.

Blocked · Upstream

WebAuthn *http.Request leak in service layer

go-webauthn/webauthn's FinishRegistration()/FinishLogin() take *http.Request directly to parse attestation/assertion from the body. Can't pass pre-parsed bytes — the library API doesn't accept them. Requires an upstream PR to go-webauthn, or wrapping *http.Request reconstruction (which defeats the purpose). Inherent to the library design.

Deferred · Premature

Snapshot integration for event sourcing

go-cqrs-lite/snapshot/v3 available as indirect dep. Current replay loads all events on startup (works for moderate volumes). Snapshot integration adds complexity (snapshot store, frequency, invalidation) for benefit only at >10K events per aggregate. Defer until production hits limits.

Gap

TenantState struct-level IsValid()

Event handlers clear Suspended on delete (struct-level invariant in fold), but the struct fields are still independent booleans. A struct-level IsValid() method would fully close this. Low-impact: the fold enforces the invariant at the only mutation point.

c) Not Started

Shared identity module (root + usermgmt)

The architectural fix for the ActorID split brain. Extract ActorID, UserID, TenantID into a shared identity/ module both root and usermgmt import. Significant change — reverses root's "no deps" principle unless carefully scoped. See ADR 0018.

CatchUpSubscriber adoption

go-cqrs-lite v3.1.0 ships CatchUpSubscriber. StartProjections still uses manual journal replay + bus.SubscribeAll. Migration is a documented future task — the manual approach works and gives explicit control over replay ordering.

stack.Materialize[V] evaluation

Evaluated but not adopted — usermgmt read models have complex event handling (12-event switches, external account indexes) that don't fit the declarative OnCreate/OnUpdate/OnTombstone pattern. Custom projections remain the right call for this domain.

d) Totally Fucked Up

MUST FIX

ADR number collision: two files share "0015"

docs/adr/0015-identity-model-redesign.md and docs/adr/0015-merge-catalog-into-go-cqrs-lite.md both use the number 0015. The catalog merge ADR should have been numbered 0020 (next free slot). ADR numbers are immutable sequence identifiers — collisions break the cross-reference contract. This was my mistake: I picked 0015 without checking for a collision with the existing identity-model ADR.

Fix: Renumber 0015-merge-catalog-into-go-cqrs-lite.md → 0020-merge-catalog-into-go-cqrs-lite.md, and update the cross-reference in 0008-catalog-sub-package.md.

Process Failure

Declared "done" without a reference sweep

The original catalog migration declared completion at code-green. It left 6 categories of lying docs (ACCEPTED ADR, FULLY_FUNCTIONAL FEATURES section, broken README link, stale CHANGELOG). The self-review caught these reactively, not proactively. The lesson: "done" for a deletion/migration = code green AND zero references to the deleted thing AND all status docs tell the truth. The reference sweep belongs in the original plan.

e) What We Should Improve

1. Make reference sweeps a standard migration step

Any task that deletes/renames a public API must include a grep sweep for all references in docs, comments, and config — before declaring done. Add this to the migration checklist in AGENTS.md.

2. ADR numbering discipline

Always ls docs/adr/ | sort -V | tail -1 before creating a new ADR. The collision happened because I guessed the next number instead of checking.

3. Breaking-change CHANGELOG discipline

Deleting a public Go module is a breaking change. The CHANGELOG entry should be written as part of the migration, not discovered in self-review. Add "CHANGELOG entry for breaking changes" to the migration checklist.

4. Cross-repo coordination runbook

The catalog merge touched two repos (cqrs-htmx + go-cqrs-lite) with a publish gate between them. Document the pattern: port upstream → tag → push → bump consumers → migrate → delete. This will recur for future consolidations.
