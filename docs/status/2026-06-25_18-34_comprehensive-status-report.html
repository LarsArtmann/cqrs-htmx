04Problems (d)

Critical

ActorID/ImpersonatorID stored as raw string in context

context.go:141,147,155,161

The typed usermgmt.ActorID is discarded at the context boundary. Callers pass raw strings — a UserID, a BotID, garbage — with no type checking. The single biggest type-safety hole. Blocked by module boundary: root can't import usermgmt.ActorID.

High

Duplicate sentinel errors across packages

errors.go:20-21 vs usermgmt/errors.go:37,39

cqrshtmx.ErrUnauthorized and usermgmt.ErrUnauthorized are different sentinel values. errors.Is(usermgmt.ErrUnauthorized, cqrshtmx.ErrUnauthorized) returns false. A handler checking errors.Is(err, cqrshtmx.ErrUnauthorized) on a usermgmt-originated error silently fails. Real silent-bug risk at the module boundary.

05What We Should Improve (e)

Architectural Improvements

  • Type the context boundary — The #1 improvement. Define a root-level actor type or accept a typed interface at the context API.
  • Extract ephemeral store interfaces — 6 stores need WebAuthnSessionStore, VerificationTokenStore, TOTPStore, LockoutStore interfaces. Enables Redis adapters for multi-instance.
  • Decouple WebAuthn service from HTTP — Parse request in webauthn_http.go, pass parsed bytes to the service.
  • Reconcile sentinel errors — Either usermgmt re-exports root's sentinels, or the error checker at module boundary unwraps by code string.
  • Wire snapshot store — go-cqrs-lite/snapshot/v3 is already an indirect dep. Wire it to reduce startup from O(n) to O(1).

Type Safety Improvements

  • BotState.OwnerID → UserID — A bot owner is always a user. 4 files to change.
  • Wire the existing Email type — email.go defines Email with ParseEmail but every struct uses raw string. The type exists — just use it.
  • Unexport NewActorID or add validation — The kind/raw pairing must be enforced.
  • TenantState sealed union — Suspended=true, Deleted=true is representable but nonsensical. Use a state enum or sealed interface.
  • Action/Effect/Role validated enums — Currently branded strings with no Parse/Valid methods. Unknown values silently pass through Casbin.

07Blocking Question (g)

How should we type ActorID at the context boundary across module boundaries?

context.go (root module) stores ActorID as string because it cannot import usermgmt.ActorID (zero mutual imports is a core architectural principle). But this creates the single biggest type-safety hole: any string can be passed.

Three options I cannot decide between:

  1. Root-level Actor type — Define type ActorID struct { Kind string; Raw string } in root package. Usermgmt converts at the boundary. Pro: type-safe. Con: duplicates usermgmt's ActorID, potential split-brain.
  2. Generic value interface — WithActorID[T any](ctx, actor T) using Go generics. Pro: no type duplication. Con: context lookup becomes lossy (ActorIDFromContext[T]() needs to know T).
  3. Accept the boundary — Context stores string by design. The typed API is usermgmt's job. Root just passes it through. Pro: no coupling. Con: type hole stays open.

Which approach do you want? This is the #1 type-safety improvement and I cannot pick for you because each has a real tradeoff.
