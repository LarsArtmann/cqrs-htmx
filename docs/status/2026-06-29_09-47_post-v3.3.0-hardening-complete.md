**Which templ CLI version is canonical for this repo, and is the single-line or grouped import form the intended target?**

The `_templ.go` generated files keep oscillating between two import styles:

- **Single-line** (`import "x"` + `import y "z"`) — emitted by the locally installed templ CLI
- **Grouped block** (`import ( ... )`) — the gofmt-canonical form the pre-commit hook normalizes to

`AGENTS.md` says only: _"Module pins `a-h/templ v0.3.1020`; **CLI may be newer**."_ That deliberately leaves the CLI version unpinned, which is exactly why the drift happens. I cannot determine from the repo alone:

1. Which templ CLI version the maintainers intend contributors to use,
2. Whether `_templ.go` files should be committed in single-line or grouped form (both compile identically),
3. Whether the fix is (a) pin the CLI in `flake.nix`, (b) add a `templ fmt` normalization step, or (c) accept the churn and stop trying to commit "sync" commits.

This is the single biggest source of friction I encountered this session, and resolving it requires a decision only the maintainer can make.
