## e) WHAT WE SHOULD IMPROVE

### Process improvements

1. **Run lint DURING development, not after** — the 57-issue debacle proves this. Set up a file-watcher or run `golangci-lint run` after each file change
2. **Always check coverage before AND after** — adding 500 LOC of untested production code dropped coverage below the gate
3. **Self-review every change** — the breaking API change, SecurityHooks gap, and Postgres bug were all self-inflicted and only caught on review

### Architecture improvements

4. **SQL read models need integration tests** — the unit tests prove the SQL store works, but don't test the full event→projection→SQL→restart path for all 4 aggregates
5. **Reduce duplication in SQL read models** — 4 near-identical implementations (User/Membership/Tenant/Bot). A generic helper or code generation would eliminate ~300 LOC of repeated patterns
6. **SecurityHooks + stack preset integration** — the stack Bundle doesn't expose injection points. A future upstream feature request or a post-construction wrapping approach is needed
7. **Adopt CatchUpSubscriber** — replaces ~140 LOC of manual journal replay with `Bundle.CatchUpSubscriber()`. Reduces complexity

### Testing improvements

8. **Coverage gap in new SQL read model code** — `SQLMembershipReadModel`, `SQLTenantReadModel`, `SQLBotReadModel` have no direct tests. Only their constructors are tested via `TestSQLReadModels_ProjectionInterface`
9. **No integration test for Postgres setup** — gated behind `POSTGRES_TEST_DSN` but never actually run
10. **No restart-survival test for Membership/Tenant/Bot** — only User has this
