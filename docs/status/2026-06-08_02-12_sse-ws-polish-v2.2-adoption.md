### 2. Broadcaster Unsubscribe Optimized to O(1)

|| Before | After |
|| --------------------------------------------- | ---------------------------------------------- |
| O(n) map iteration to find channel by identity | O(1) `uintptr` lookup via `reflect.ValueOf(ch).Pointer()` |
| `map[chan SSEEvent]struct{}` | `map[uintptr]chan SSEEvent` |
| Iterate all subscribers on every unsubscribe | Direct map lookup + delete + close |

The trick: Go's `chan SSEEvent` and `<-chan SSEEvent` share the same underlying pointer. `reflect.ValueOf(ch).Pointer()` returns the same `uintptr` regardless of channel direction, enabling direct map key lookup.

## g) Top #1 Question I Cannot Figure Out Myself

**Should `RegisterTyped[T]` / `DispatchTyped[T]` be adopted at the library level, or left as a consumer-side concern?**

The case for adopting it in cqrs-htmx:

- `DecodeJSON[T](mapper)` already produces typed `T` → `command.Command` via mapper. If we also used `RegisterTyped[T]` internally, the entire pipeline would be typed end-to-end with zero `any` assertions
- `query.DispatchTyped[T]` would let `App.Query` return typed results without the consumer doing type assertions
- It's the stated v1.1.0 goal from ROADMAP.md

The case against:

- go-cqrs-lite's `RegisterTyped` wraps the handler with a type assertion (`cmd.(T)`). If cqrs-htmx's decoder already produces a `command.Command` from `T`, the assertion is redundant — it will always succeed. We'd be adding an unnecessary type check.
- `DispatchTyped[T]` is about the handler return type, which cqrs-htmx already handles via `RenderFunc`. The `any` result from `query.Dispatch` is already consumed by the render pipeline.
- It would require importing the typed APIs from go-cqrs-lite, increasing coupling to specific patterns

**My recommendation**: Adopt it, but as opt-in. Add `DecodeTypedJSON[T]` and `DecodeTypedForm[T]` that bypass the `command.Command` interface and use `RegisterTyped` directly. Keep existing `DecodeJSON`/`DecodeForm` for backward compatibility. This gives consumers the choice between the typed path (zero assertions, compile-time safe) and the untyped path (flexible, works with any `command.Command`).
