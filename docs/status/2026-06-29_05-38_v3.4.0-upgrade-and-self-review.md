## e) WHAT WE SHOULD IMPROVE

### Architecture

1. **Replace `StartProjections` with `projectionhost` or `CatchUpSubscriber`** — The 155-line hand-rolled synchronous replay is the single largest piece of "last loop every consumer rewrites" code. v3.4.0's `projectionhost.Host` provides crash restart, checkpoint persistence, DLQ, and per-projection isolation. **This is the highest-impact adoption opportunity.**

2. **Migrate local `idempotency.go` to upstream alias** — Now that `go-cqrs-lite/idempotency/v3` is tagged v3.4.0, the local 200-line copy should become thin type aliases. Verified locally that alias form passes the full suite.

3. **Adopt `scenario/v3` for BDD tests** — The 574 usermgmt test functions contain enormous amounts of boilerplate (setup state, dispatch command, assert events). `scenario.Given[...]().When(...).Then(...)` would compress many by 60-70%.

### Type Safety

4. **The `cmdID` bug reveals a pattern** — 7 of 21 commands silently returned zero IDs. The root cause is that `cmdID` is an _unexported field set only in the constructor_ — if you forget, there's no compile error. **Recommendation**: embed `command.BasicCommand` (which auto-mints `ID()`) instead of re-declaring the field, OR add a test that asserts every command type produces a non-zero `ID()`.

5. **`Storage/memory/v3` version drift** was caught and fixed this session, but MVS still allows modules to silently drift. Consider a version-alignment check in CI.

### Testing

6. **No assertion that command IDs are non-zero** — The bug existed for weeks. A single table-driven test iterating all command constructors would have caught it immediately.

7. **usermgmt coverage at 79.5%** — Below the 80% coverage gate threshold (the gate is 75% for usermgmt). The gap is primarily in OAuth2 HTTP handlers and SQL read model edge cases.

### Developer Experience

8. **`go mod tidy` broken** blocks the standard Go workflow. Document the workaround more prominently or contribute the fix upstream.

9. **30 ADRs but no ADR index** — Finding the right ADR requires `ls docs/adr/`. An `INDEX.md` with one-line summaries would help.

10. **104 open TODO items** — The TODO_LIST.md has grown large. Many are stale or upstream-blocked. A triage pass would reduce noise.

## g) Top #1 Question I Cannot Figure Out Myself

> **Should `StartProjections` adopt `projectionhost.Host` (full managed lifecycle with checkpoint persistence + DLQ) or `watermill.CatchUpSubscriber` (lighter, preserves the bus model)?**
>
> The core tension: the current implementation does **synchronous replay** before returning, which combined with `BlockPublishUntilSubscriberAck` guarantees **read-your-writes consistency** — after `Execute()` returns, the read model is already updated. Both upstream alternatives run replay **asynchronously** in goroutines, which would break this invariant during startup (a command dispatched immediately after `NewService()` might not see its own write).
>
> **What I need from you:** A decision on whether read-your-writes-during-startup is a hard requirement or an acceptable tradeoff for gaining checkpoint persistence (no full journal replay on restart). This determines the entire adoption strategy and whether we need a sync-wait wrapper.
