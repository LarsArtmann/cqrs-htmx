### Bugs found and fixed during release prep

1. **`dashboard-demo/go.mod` missing replace** — The `examples/dashboard-demo` module required `dashboardui/v4 v4.4.0` which doesn't exist as a tag. This poisoned the entire `go.work` workspace graph, making `go build ./...` and `go test ./...` fail from the workspace root. Fixed with `replace github.com/larsartmann/cqrs-htmx/dashboardui/v4 => ../../dashboardui`.

2. **`batch-release.sh` only stripped `cqrs-htmx/*` replaces** — The root `go.mod` has `replace github.com/larsartmann/go-sse => ../go-sse`. The script's grep pattern `github\.com/larsartmann/cqrs-htmx/\S+` missed it. First tag attempt shipped a tagged go.mod with a broken local path replace. Fixed by widening to `github\.com/larsartmann/\S+`.

3. **`batch-release.sh` `go mod tidy -e` destroyed require blocks** — With `GOWORK=off`, `go mod tidy -e` silently removed ALL go-cqrs-lite and go-sse dependencies because their published tags are broken (the known go-cqrs-lite publishing bug). The second tag attempt shipped a root `go.mod` with 6 missing direct dependencies — it would not build for any consumer. Fixed by removing the tidy step entirely.

4. **`batch-release.sh` git reset logic** — Original used `git reset --soft HEAD~1` + `git checkout -- .`. The `--soft` leaves the index pointing at the stripped-replace commit, and `git checkout -- .` then restores files from that index — overwriting the carefully restored originals. Fixed to `git reset --mixed HEAD~1`.

5. **`batch-release.sh` go.sum not backed up** — The backup loop only copied `go.mod`, but the restore loop tried to restore `go.sum` from a backup that didn't exist. Fixed by adding go.sum to the backup step.

## e) WHAT WE SHOULD IMPROVE

### Process improvements

1. **Run `release-checklist.sh` first** — It exists specifically to catch issues before tagging. I bypassed it and discovered problems reactively through 3 tag cycles.

2. **Add a dry-run mode to `batch-release.sh`** — The script should support `--dry-run` that strips replaces, shows the resulting go.mod diff, and exits WITHOUT creating tags. This would have caught the go-sse replace issue and the tidy destruction before any tags were created.

3. **Add a post-tag verification step** — After creating tags, the script should checkout each tag and run `go build ./...` to verify the stripped go.mod actually compiles. Currently it trusts that stripping replaces is safe.

4. **The `go mod tidy` approach is fundamentally broken for this repo** — Until go-cqrs-lite and go-sse publish clean tags, `go mod tidy` with `GOWORK=off` will always destroy dependencies. The script should either skip tidy entirely (current fix) or use `go mod edit` to surgically remove only the replace lines.

5. **Inter-module version references are stale** — usermgmt/v4.5.0 still requires `cqrs-htmx/v4 v4.4.0` (the previous version). dashboardui/v4.0.0 requires root at whatever version. This means consumers pulling v4.5.0 of usermgmt get v4.4.0 of root transitively. This is the same pattern as previous releases, but it's a debt that compounds.

6. **Missing per-module CHANGELOGs for 5 modules** — totp, webauthn, oauth2, identity-model, and loginpage either have no CHANGELOG or weren't updated. The CONTRIBUTING.md documents per-module changelogs as a practice.

7. **`go-sse` is an unpublishable dependency** — Root module depends on a module with no published tag. This makes the root module unpublishable for external consumers. This needs to be resolved (publish go-sse, or vendor it, or remove the dependency).

8. **Tags should point to HEAD, not a child commit** — The current approach creates a temporary commit for the stripped go.mod, tags it, then resets. This leaves tags pointing to orphaned commits. A cleaner approach: strip replaces, commit as a real release commit (not temporary), push that commit, tag it. The "restore originals" dance is fragile.

### Documentation improvements

9. **AGENTS.md release process section** — Should document the `go-sse` pseudo-version issue and the batch-release.sh tidy-removal decision.

10. **CONTRIBUTING.md** — Should warn that `nix run .#build` uses `GOWORK=off` which fails due to the go-cqrs-lite publishing bug. The nix build app cannot currently verify the release.

11. **Release runbook** — There's no step-by-step runbook that a human can follow. The `release-checklist.sh` automates checks but doesn't guide the tagging/pushing/verifying flow.
