## e) WHAT WE SHOULD IMPROVE

1. **Ask the pre-commit hook what it will demand BEFORE cutting the first tag.** The api-golden drift sat in the tree through a dry-run, a real tag, and a compat tag — the hook caught it only when I tried to commit. A release preflight one-liner ("run the hook's api-surface leg now") would have saved a delete-and-recut.
2. **Vendor-hash bumps deserve a scripted loop** (build → parse got-hash → write → rebuild → commit → reinstall → doctor-verify). Hand-rolling it twice produced one silent chain failure (d3) and one rat-race discovery. The loop is deterministic; it should be one flake app.
3. **rc-capture discipline:** in this repo's verification culture, `cmd | tail; echo $?` is a lying instrument — the exact class gotcha 61 documents for gates applies to session one-liners too. Default to `cmd > log 2>&1; rc=$?`.
4. **The dual-shape tag + manifest + smoke + GH-release dance is five steps per release** — proven three times today, all by hand. The fleet helper (c8) removes both the toil and the drift risk.
5. **The escalated gate's self-test stubs hardcode the floor version in two places** (the stub `version` outputs and the refusal-message grep). A future floor bump must edit the gate script AND the self-test — noted in the script header; a shared fixture constant would remove the coupling.
6. **Doctor's BLOCKING binary-freshness is a genuinely excellent guard** — it caught the one real staleness this session (d3) — but its HEAD-at-run-time comparison is structurally unwinnable on daemon-repos (g3). The fix belongs upstream: compare against the install-time rev, or grant a grace window, or let `--dogfood` distinguish "built from an ancestor of HEAD" (fine) from "built from an unrelated rev" (bad).
7. **Escalating a gate surfaces latent upstream bugs the advisory posture was hiding** — the skip-immediate-parent walk and the missing scope flag were both years-old quirks that only mattered once findings had teeth. Corollary: budget for follow-up patch releases when escalating; the "same evening" three-release train was the right shape, not an accident.
8. **Concurrent-session discipline held** (gotcha 47): no tree-wide operations, no touching the sibling's files, spot-checks after every daemon absorption. The cost is constant vigilance; the alternative is destroying a sibling's in-flight work.
