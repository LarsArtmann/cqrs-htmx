## e) WHAT WE SHOULD IMPROVE

1. **Phase-boundary commits beat end-of-run commits** — the daemon race is unwinnable at the end; it is trivially winnable at phase boundaries. Rule for future dependency work: verify → commit → next phase, every time, no batching.
2. **The post-bump gate ladder has a hole**: build/vet/test/lint/check-modules ran; check-cqrs-lint, coverage-gate, race, bench-spike did not. The bump touched dispatchers inside benched serve paths — a bench-spike sanity run was in scope and skipped. Fix: add a documented "dependency bump" gate bundle (the 6 I ran + check-cqrs-lint + bench-spike) so it's one command, not a judgment call.
3. **`cqrs-upgrade` is single-consumer** — for this repo it can only ever bump the root go.mod. Upstream ask (or local wrapper script) to iterate all workspace go.mods with the same tidy+build+vet gate would turn this session's hand-rolled sweep into one command.
4. **Split brain in the drift gate itself** (two checks encoding the replace-exemption differently) was real and I closed it — but the deeper fix is ONE shared exemption helper so the two checks cannot diverge again.
5. **V006 suppression + stale-suppression discipline**: version bumps are exactly when suppressions go stale; running `check-cqrs-lint` should be a hard step in every dependency-bump session (it was not).
6. **Doc-memory freshness for multi-axis claims**: "uniform at vX" claims should carry the upstream-latest in the same sentence (or a pointer to the lag list) so they can't read as "current with the world".
7. **The mvdan/sh `set -e` lesson is now session-proven twice over** (PIPESTATUS gotcha in AGENTS.md, my sweep deaths) — promote to a hard rule in AGENTS.md Gotchas.
