## e) WHAT WE SHOULD IMPROVE!

1. **Fix the linter, not the symptom — twice over.** V006 and D005 are both cqrs-lint rule-model bugs (go-cqrs-lite version trains aren't lockstep; bare version tokens get attributed to the wrong dependency). Every go.mod cqrs-htmx controls now carries a V006 suppression that must be manually deleted once (if ever) the rule learns trains. The suppression is debt; the rule fix is the payoff.
2. **Never let a suppression state an empirical claim without a verification date.** The F019 lie had "(checked v4.10.0)" — good instinct, wrong conclusion, and no re-check when upstream moved. Rule: empirical-claim suppressions get re-verified on every upstream version bump, or they get deleted.
3. **Periodic suppression audit:** a quarterly `cqrs-lint` run with the stale detector (now that it exists) + a manual pass over remaining suppressions claiming API facts.
4. **Docs-vs-go.mod drift should be machine-checked more aggressively,** not just for the one line D005 happens to parse. Three simultaneous drifts in AGENTS.md were found by accident.
5. **Cardinality hints deserve provenance.** My Volume numbers are domain-reasoned orders of magnitude, not measurements. The doc comment explains semantics but not where the numbers came from. Either mark them as "placeholder until production data" or tune them from real deployments.
6. **The "verified gates" list should always be explicit in session summaries** — "all gates green" without naming the gates is how untested categories (coverage, examples, e2e) silently accumulate confidence debt. This report does it properly; the session's final message was only ~90% precise about it.
