03Fully Done SOLID

HTMX Core + Extensions Embedding

HTMX 2.0.10 core + SSE 2.2.4 + WS 2.0.4 + idiomorph 0.7.4 all embedded via go:embed. Full handler API: individual, bundle, CDN tag, version introspection. Same caching as core (ETag, 1yr immutable, 304). Tests cover all paths (200, 304, 405, panic-on-unknown, bundle concat, CDN tags).

CQRS-HTTP Handler Pipeline

App.Command/Query + HandlerOption pipeline: decode (JSON/Form/Query), validate, authz, render (JSON/Templ/Paginated), HTMX response builder, notifications, SSE/WS broadcasting hooks. 94.3% root coverage.

Event-Sourced User Management

12 events, 11 commands, pure domain layer (fold/decide), Casbin RBAC projection, 4 aggregates (User, Membership, Tenant, Bot), impersonation, API tokens. Auth strategies extracted to independent modules (totp/webauthn/oauth2).

Admin Dashboard (adminui)

templ + HTMX dashboard. SuperAdmin + TenantAdmin modes. SSE sync indicator via raw EventSource (not HTMX SSE extension — architecturally correct). Offline command queue SharedWorker. One-call mount.

Middleware Stack

CSRF (nosurf), rate limiting (token-bucket + min-heap LRU), security headers, recovery, request logging (text/JSON/slog), Server-Timing API, context enrichment. All opt-in, composable via Chain().

Module Isolation CI

4 shell scripts enforce module discipline: isolation (GOWORK=off build+vet), dep budgets (root=18, usermgmt=28, adminui=7), version drift detection, replace directive ban. Wired in CI as module-architecture job.

Error Handling Architecture

go-error-family classification → HTTP status mapping (3-layer: HTTPStatusCarrier → sentinels → family). ProblemDetailsErrorHandler (RFC 7807). 5xx detail redaction. StructuredError across HTTP/SSE/WS. Zero stdlib error constructors in root+usermgmt (enforced).

Documentation Infrastructure

36 ADRs, 64 status reports, FEATURES.md, TODO_LIST.md, ROADMAP.md, CHANGELOG.md, DOMAIN_LANGUAGE.md, per-module READMEs, 4 examples, cqrs-htmx SKILL.md with 4 reference files. Migration guide v3→v4.

05Not Started FUTURE

HTMX 4.0 migration

HTMX 4.0.0-beta5 is out (June 2026). Research docs exist (docs/research/htmx-4-*.html) but no migration work started. Extensions system is rewritten in 4.0 — our embedded extensions may need updating. The HTMXScriptHandlerWith API already supports custom JS, so consumers can opt in early.

OPFS for offline command persistence (Phase 2b)

ADR-0029 ships SharedWorker + in-memory queue (Phase 2a). OPFS (Origin Private File System) for disk persistence is deferred. IndexedDB explicitly banned.

CatchUpSubscriber adoption

StartProjections still uses manual journal replay + bus.SubscribeAll. Migration to go-cqrs-lite's CatchUpSubscriber for more robust catch-up is a future task.

More embedded HTMX extensions

33 extensions exist total (7 core, 13 official community). We embed the 3 with server-side counterparts. Candidates for embedding: preload (2.1.1), response-targets (2.0.3), head-support (2.0.4), debug (2.0.1).

Redis-backed idempotency store

idempotency.go re-exports go-cqrs-lite's interface. Only MemoryStore is wired. Redis adapter (SET NX) and SQL adapter (INSERT ON CONFLICT) documented in ADR-0026 but not implemented.

06Totally Fucked Up CRITICAL

Infrastructure

buildflow oxfmt:detect is broken

The oxfmt:detect step fails with "unknown tool name: oxfmt:detect" on every commit. This means the pre-commit hook never succeeds, forcing --no-verify on every commit. This is a systemic bypass of all pre-commit quality gates.

Root cause: Likely a buildflow configuration mismatch — oxfmt binary exists (v0.53.0) but buildflow can't resolve the oxfmt:detect step name.
Technical Debt

usermgmt god-package: 84 prod files in one flat package

~11K LOC in a single package usermgmt. The Service struct is a god object. Three deep Sollbruchstellen identified (domain layer, auth strategies, SQL infra) but extraction not started. The v3 review notes this fails the "Unix pipe test" — the package can't be used for just its domain types without pulling in all infrastructure.

Silver lining: Auth strategy extraction (TOTP/WebAuthn/OAuth2 → independent modules) was completed in v4. The remaining god-package problem is in core usermgmt itself.

07What We Should Improve

1. Fix the oxfmt pre-commit issue

Either fix the buildflow config or remove the oxfmt step. Every --no-verify commit is a quality gate bypass.

2. Break the usermgmt god-package

Extract the 20 pure domain files (fold/decide/event/command structs) into a usermgmt/domain sub-package. Zero I/O, v3-safe, no breaking changes. This is the single highest-impact architectural improvement available.

3. Add HTMXExtensionScriptTag helper for self-hosted paths

We have HTMXExtensionCDNScriptTag but no HTMXExtensionScriptTag(path, name) for generating <script src="/ext/sse.js"> tags. Minor but completes the symmetry with HTMXScriptTag.

4. Consolidate test helpers across modules

Each module has its own test setup boilerplate. Shared test helpers (httptest wrappers, seed builders) could reduce ~2K lines of test duplication.

5. Add extension version tests to integration_test module

The integration_test module verifies cross-module bridges. Adding a test that asserts HTMXExtensionVersion(HTMXExtSSE) matches the actual JS file content would catch version drift between embeds and constants.
