2. **Treat tool-adjacent gotchas as binary-versioned claims**: gotcha 29 was written against the old binary and I applied it as current truth — the exact trap gotcha 23 warns about for cqrs-lint. After ANY linter binary swap, re-verify the suppression-form doctrine before editing (and gotcha text should carry its verifying version — 29 now does).
3. **Commit at phase boundaries** — I knew the ritual (gotcha 4) and still batched. The chained `fmt && add && commit` one-call pattern worked perfectly when I used it (twice); it needs to be the DEFAULT at every phase, not a finishing step.
4. **Check the formatter before the gates**: any line-sensitive ratchet (branching-flow anchors, suppression positions) must see the post-`nix fmt` tree, not the pre-fmt one.
