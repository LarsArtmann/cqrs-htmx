## d) TOTALLY FUCKED UP

### HEAD is NOT the tagged commit — AGAIN

Same problem as the first release attempt. The `batch-release.sh` creates a temporary child commit (`3af30d3`), tags it, then restores the working tree. The tags point to an orphaned commit that is NOT reachable from HEAD's main line (HEAD is `696dad3`, tags are on `3af30d3` which is a sibling).

Wait — actually the topology is correct this time: `3af30d3` IS an ancestor-reachable commit, and HEAD (`696dad3`) is one commit AHEAD of it. So the tags are on a valid historical commit, and HEAD has moved forward by 1 doc-only commit. This is acceptable — the tags point to a real commit in the linear history, not an orphan.

**BUT**: The AGENTS.md update (go-sse v0.2.0 in key deps) is in commit `696dad3` which is NOT in the tagged commit `3af30d3`. So the tagged release's AGENTS.md doesn't mention go-sse as a key dependency. Minor, but inconsistent.

### identity-model pseudo-version in ALL downstream modules

This is the most serious issue. usermgmt, adminui, and loginpage all reference:
```
github.com/larsartmann/cqrs-htmx/identity-model/v4 v4.0.0-20260723162555-beae91131538
```

This pseudo-version was generated because identity-model/v4.0.0 was tagged but the commit it tags doesn't match what downstream modules need — `go mod tidy` resolved to a specific commit hash instead of the tag. This means:
1. External consumers may not be able to resolve identity-model at all (pseudo-version depends on proxy having that exact commit)
2. Even if resolvable, it's NOT v4.0.0 or v4.1.0 — it's an unreleased commit between the two

**This was NOT fixed.** The batch-release.sh skips `go mod tidy`, so these pseudo-versions are preserved as-is in the tagged go.mod files.

## e) WHAT WE SHOULD IMPROVE

### 1. Fix inter-module version references BEFORE tagging

The `batch-release.sh` should update all sibling references to the new versions before creating tags. Something like:
```bash
go mod edit -require=github.com/larsartmann/cqrs-htmx/v4@v4.5.0
```
applied to usermgmt, adminui, loginpage, dashboardui. This ensures consumers get consistent versions transitively.

### 2. Fix identity-model pseudo-version

All three downstream modules reference identity-model via a pseudo-version. This needs to be resolved to either `v4.0.0` or `v4.1.0` (the tagged versions). The pseudo-version exists because the tagged v4.0.0 commit doesn't have the types that downstream modules need — suggesting the v4.0.0 tag was created too early or the downstream modules evolved past it.

### 3. Add a pre-tag validation step to batch-release.sh

Before creating any tags, the script should:
1. Check for pseudo-versions in all go.mod files (not just the root)
2. Check that inter-module references point to versions being released in this batch
3. Run `check-version-drift.sh --strict`
4. Fail if any of the above have issues

### 4. GOPRIVATE / GOPROXY strategy

All `github.com/larsartmann/*` repos are private. The Go public proxy cannot cache them. Consumers MUST set `GOPRIVATE=github.com/larsartmann/*` or use a private GOPROXY. This should be documented prominently in README.md and CONTRIBUTING.md. Without it, `go get` fails with confusing errors.

### 5. Run `release-checklist.sh` before `batch-release.sh`

The release-checklist.sh script exists specifically to catch issues. It was never run. It would have caught the version drift and check-modules failures before any tags were created.
