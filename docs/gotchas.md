# Gotchas

> Enduring, non-obvious traps, extracted verbatim from `AGENTS.md` on 2026-10-24 so the
> always-loaded file stays small. **Numbers are stable identifiers** — each anchor
> (`#gotcha-N`) is linked from `AGENTS.md`'s index and from the notes. When you add a trap,
> append the next number; never renumber.

<a id="gotcha-1"></a>

1. **`GOEXPERIMENT=jsonv2` is mandatory** (build fails without it; never add depguard rules banning `encoding/json/v2`). Manual Go commands outside the devShell also need the 1.27.2 toolchain — `scripts/lib/go-cache-env.sh` (sourced by gates and the pre-commit hook) auto-aligns `GOTOOLCHAIN` to the go.work floor; the toolchain resolves from the local module cache.

<a id="gotcha-2"></a>

2. **`go build ./...` does NOT compile `_test.go` files** — make `go vet ./...` part of every verification pass; run `GOWORK=off go build ./...` (+ tidy + vet) per-module after go.mod changes (workspace mode masks hermetic breakage). AND: `./...` from the repo root only ever matches the ROOT module's packages — it is module-scoped even under go.work, so a root-run `go test ./...` printing a few green packages is a FALSE green (hit live 2026-10-01: 3 packages, 27 modules silently skipped); the full-workspace battery is `nix run .#test` (forEachGoModule over every go.work member), and any hand-rolled loop sweep must PRINT ITS CANDIDATE COUNT and fail loudly on zero.

<a id="gotcha-3"></a>

3. **Shell traps (proven repeatedly):** `PIPESTATUS` breaks in mvdan/sh — capture `cmd > /tmp/f 2>&1; echo $?`, never through pipes (`cmd | tail; echo $?` reports tail's rc); `set -e` does not abort on `grep -q && …` lists — use explicit `rc=$?` checks in multi-module batch loops, never `set -e`; a redirect to a path with a slash in a variable silently skips the command (the `/tmp/sweep-e2e/server.log` class); after version sweeps assert ABSENCE (`grep -rE 'stale-pattern' --include=go.mod` expecting zero), don't sample presence; use unique `/tmp/<repo>-<purpose>-$$-$(date +%s).log` paths — concurrent sessions share /tmp; process substitution `<(...)` is unreliable under mvdan/sh — a `cmp file <(git show HEAD:f)` returned a false EQUAL against differing content (2026-09-22), materialize to a temp file and compare files instead.

<a id="gotcha-4"></a>

4. **Commit at phase boundaries, never at the end** — the auto-commit daemon polls faster than a long verification tail and shreds batched work into heuristic `chore: auto-commit` commits. Verify → commit → next phase. Concurrent sessions share this tree: re-check `git log`/`git status` before assuming attribution; never revert diffs you didn't author (another session made them intentionally). The mechanical guard is `nix run .#preflight-tree-check` (abort-on-surprise before ANY tree-mutating batch step: dirty tree / fresh non-daemon commit / commit-velocity burst — daemon commits are exempt churn) and `nix run .#wait-tree-quiet` (block until clean tree + stable HEAD for a full window, before push retries or release trains); both carry fixture self-tests inside `check-modules` + CI (added 2026-09-22). No tree-mutating verification inside a foreign repo's in-flight release train (the 2026-09-22 templ-components tidy-interference lesson: `go mod tidy` reverted a concurrent session's version pins mid-verify). Micro-ritual (2026-10-09): when a concurrent session is known active, smoke-check `git status --short` for untracked foreign Go files + a 5-second root `go build ./...` BEFORE any hook-committing commit — a foreign mid-flight breakage costs a full dead BuildFlow run (~6 min, hit live); go straight to the documented `--no-verify` + justification for docs-only commits when foreign breakage is visible. Daemon-race corollaries (2026-10-12): chain fmt INTO the single commit call (`nix run .#fmt -- <paths> && git add <paths> && git commit …` in ONE tool call) — the daemon polls during the multi-second nix-run window and captures fmt's output first (hit twice more); NEVER rebase/reword an unpushed heuristic commit while the daemon lives — `reword` runs the FULL pre-commit hook (~2 min) and loses the ref race, self-aborting the rebase (`cannot lock ref 'HEAD'`; hit live, state self-cleaned) — amend HEAD only and leave deeper heuristic titles as accepted debt; and check `uptime` BEFORE choosing full-hook vs `--no-verify`+justification, not after the timeout cascade. Review-vs-concurrent-fix races (2026-10-18, episode-4 full-code-review): agent-reported findings can be STALE by the time you act — a sibling session fixed dashboardui's recent-events/pagination findings mid-review (heuristic commits landing every ~2 min); ALWAYS re-view the exact file:line immediately before fixing, and credit/verify rather than re-fixing. Same session: a codemod fix revealed a SECOND stacked bug under the reported one (dropImportSpecs' lineStart used IndexByte — first newline — instead of LastIndexByte; the reported fuse bug was real but not alone), so instrument (print the actual planned edits) before believing a partial diagnosis. Diagnostic-mutation paired-restore (2026-10-14): a mutation made FOR DIAGNOSIS (a version pin-back, a scratch probe `_test.go`, a temporarily-flipped flag) gets its restore action written in the SAME breath — the daemon captures mid-diagnosis state within minutes (the `zz_scratch_probe_test.go` probe entered history via `57c76ec2` while its one-call create+run+delete flow was still running); chain create→run→rm into one command, or stage the restore note in the tool call that performs the mutation.

<a id="gotcha-5"></a>

5. **NEVER tag a module whose go.mod edits are uncommitted** — always tag via `scripts/tools/verify-tag.sh <module-dir> <version> [--push]`, never raw `git tag` (enforces committed tree, no family dev-replaces/unpublished internal requires, post-push ls-remote). Never re-push a version at a different commit (proxy caches poison it). The `larsartmann/*` repos are PUBLIC — anonymous `git ls-remote` works; CI runners can run the release-train gate.

<a id="gotcha-6"></a>

6. **Release trains:** every internal require must resolve to a PUBLISHED tag (UNPUBLISHED = hard fail — a phantom require poisons the WHOLE workspace module graph; workspace mode masks it forever). Prefer wave-ordered cuts (each commit's requires point at already-published tags — zero `--no-verify`; codified in `docs/guides/release-playbook.md` §4a). A mid-train bump commit fails the pre-commit gate by design; documented fallback: `git commit --no-verify` WITH justification, after independent verification. CI enforces `check-release-train --strict-lag 0` — and since 2026-09-22 the LOCAL script defaults to those exact CI flags too (`--advisory` restores planning mode; the pre-commit hook runs `--advisory` deliberately so lag cannot brick intra-train commits or the auto-commit daemon), with the pre-push hook enforcing the strict flags at the push boundary. The advisory/strict split brain that reddened CI on 2026-09-22 is dead.

<a id="gotcha-7"></a>

7. **nolint directives must survive golines:** a trailing `//nolint:<linter> // reason` only applies while its line stays ≤120 chars INCLUDING the reason — keep reasons short or hoist to its own line. `exhaustruct` → `exhaustruct_v5` rename (golangci 2.13): directives MUST name `exhaustruct_v5`. `exhaustruct_v5` PANICS on promoted-key struct literals (Go 1.27 `modernize` embedlit rewrites) — keep explicit nested `BaseProps: utils.BaseProps{...}` form behind `//nolint:modernize`. **UPDATE 2026-10-14 (embedded-core literals): `//nolint:modernize` does NOT stop BuildFlow's go-fix — it shells toolchain `go fix ./...` (provider hardcodes the args, no per-analyzer knob; `-embedlit=false` exists in `go tool fix` but is unwired), and `go fix` is nolint-unaware: live-proven by it re-breaking febb8ef5's restored nested literals WITH the directives in place. Stable equilibrium: promoted-key literals are CANONICAL for embedded-core types (`ExternalAccountCore`/`readModelCore`); exhaustruct carries the conflict via `exclude` entries (identity-model: `ExternalAccount`; usermgmt: `ExternalAccount` + `Bot/Membership/TenantReadModel`), superseding febb8ef5's code-side restoration (its "modernize not enabled in these modules" assumption died when go-fix began running `go fix` fleet-wide). The nested-BaseProps convention survives only until a go-fix pass touches those literals — same exclude treatment then.**

10. **Formatter division of labor:** treefmt (`nix fmt`) is canonical (golines 120, shfmt 2-space, shellcheck, gofmt, nixfmt, and — since 2026-10-17, plan M03 — **prettier for `*.md` only**; the morning's "NO md formatter" correction is superseded: nixpkgs prettier is wired into treefmt with `proseWrap: preserve` (.prettierrc), `mkForce`-scoped to md (`*.md` + `**/*.md` — a bare `*.md` matches ONLY root-level files, and plain includes MERGE with the module's default extension list, so both glob forms and mkForce are load-bearing), historical corpora excluded via `settings.global.excludes` (status/plans/research/ADR/feedback/analysis/modularization/agents-notes/CHANGELOG/testdata stay byte-identical — annotation shapes never churn), and the md pass re-aligns table pipes only — prose is never re-wrapped); BuildFlow pre-commit formats STAGED files only — no double-format fight. `templ generate` must run from the MODULE dir (bare `FileName:` fields are canonical; repo-root runs emit path-prefixed form and the two FIGHT inside one hook run) — `nix run .#gen` / `.#check-codegen` verify module-canonical form; NEVER regenerate from the repo root. **The AMBIENT templ binary is wrong even in-module** (hit live 2026-10-19, the #19 wave): ambient v0.3.1020 lags go.mod's v0.3.1070 and its output drifted line numbers against the canonical generator, so CI's codegen gate red'd AFTER the drifted regen had been daemon-committed — `nix run .#gen` is the ONLY sanctioned producer. Format ONLY the files you touched with `nix run .#fmt -- <paths>`: a bare `treefmt <paths>` fails (the config is flake-generated into the store), and whole-tree `nix fmt` churns unrelated markdown.
