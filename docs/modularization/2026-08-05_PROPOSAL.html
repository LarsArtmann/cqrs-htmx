04The Method-Receiver Blocker (ADR-0019)

ADR-0019 documents the precise reason a naive sub-package split fails in v4. Go requires methods to be defined in the same package as the receiver type: 

// service_core.go — package usermgmt
type Service struct { ... }  // defined in usermgmt

// service_tenant.go — package usermgmt
func (s *Service) CreateTenant(...) { ... }  // legal: same package

// AFTER naive move to usermgmt/tenant/ — package tenant
func (s *usermgmt.Service) CreateTenant(...) { ... }
// ❌ ILLEGAL: cannot define method on type from another package

This is not a Go bug — it is the language enforcing encapsulation. The fix requires decomposing the Service type itself (ADR-0038), not just moving files. The 74 methods must be redistributed to focused service structs (UserService, TenantService, etc.) that each live in their own package, then composed by the top-level facade.

This is why the split is a v5 major bump, not a v4 minor. Decomposing Service changes the public API surface (callers go from svc.CreateTenant() to svc.Tenants.Create() or similar). That is a breaking change requiring a major version.
