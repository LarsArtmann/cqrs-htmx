# cqrs-htmx

> **THIS IS A LIBRARY/SDK — NOT AN APPLICATION.** Consumers import this package into THEIR projects.

Go library that makes it easy to use go-cqrs-lite with HTMX, templ, and Casbin authorization. Framework-agnostic — works with `net/http`, Gin, Chi, etc.

## Architecture

**Multi-module Go workspace.** 28 independent Go modules under one `go.work`:

- **Root** (`cqrs-htmx/v4`): Core library — HTTP handler builder, HTMX/SSE helpers, authz (Casbin), error mapping, pagination, `openapi/` sub-package (dependency-free OpenAPI 3.1 spec builder + `WithOpenAPI`/`OpenAPISpecHandler`), `transport/` sub-package (canonical SSE domain-event surface: `DomainEventToSSE` + `EventPayload` envelope + `NewJournalSSEStore` + `ServeDomainEvents` — the shared SSE handler lifecycle used by both setup `/sse` and dashboardui; envelope bytes pinned by golden tests, drift = test failure). CSRF, Server-Timing, and keyed rate limiting are now thin re-exports over `httputil` (see `_reexport.go` files). **WebSocket transport removed in v5** — SSE only (see ADR 0046).
- **identity-model** (`identity-model/v4`): Pure domain types for event-sourced identity management — IDs (UserID/TenantID/BotID/ActorID), events (21 payload structs), commands (20 structs with accessor methods), fold functions (FoldUser/FoldMembership/FoldTenant/FoldBot), state structs, Authz engine (Casbin-backed), Session, User, Membership, ExternalAccount, WebAuthnCredential, crypto helpers, domain errors (errorfamily-only, no HTTP dependency), upcaster registry, exported constants (event types, command types, aggregate types, schema version). Casbin is a first-class dependency.
- **usermgmt** (`usermgmt/v4`): Event-sourced CQRS user management — thin re-export layer over identity-model (type aliases + var aliases for fold functions/constants + constructor wrappers + WithHTTPStatus-wrapped errors) plus infrastructure (HTTP handlers, SQL stores, session middleware, read models, CasbinProjection, decide/dispatch functions). Auth via WebAuthn/TOTP/OAuth2 behind interfaces
- **usermgmt/totp**, **usermgmt/webauthn**, **usermgmt/oauth2**: Independent auth strategy modules — satisfy `usermgmt` interfaces via structural typing. oauth2 supports public (secret-less) PKCE clients via `ProviderConfig.ClientType` (`ClientTypePublic`, default `ClientTypeConfidential`) and surfaces `preferred_username` plus the verified raw ID token via `FinishLoginWithToken` (issues #8, #9, 2026-08-22).
- **adminui** (`adminui/v4`): Ready-made admin dashboard (templ + HTMX) — identity ops: users, tenants, members, audit log over a `*usermgmt.Service`, write actions, role-gated. Naming: "admin" = user administration, NOT event-store introspection (that is dashboardui); contrast sections are cross-linked in both READMEs + doc.go files, and v5 rename candidates live in `docs/guides/v5-removal-inventory.md`.
- **loginpage** (`loginpage/v4`): Ready-made passwordless login page
- **datastar** (`datastar/v4`): Optional DataStar frontend adapter — script serving, signal decoding, SSE response builder (ConsoleLog/ConsoleError/DispatchCustomEvent/ReplaceURL/Prefetch etc), signal constructors return `(Patch, error)` (no silent error swallowing), EventBridge with `OnError` callback (go-cqrs-lite events → patches — stays here per go-datastar's documented non-goals). **Broadcaster moved upstream 2026-09-17** into the `go-datastar/broadcast` submodule (`github.com/larsartmann/go-datastar/broadcast` — implementation + behavior tests live there now, stdlib-only test style); this module keeps a deprecated transparent type alias `ds.Broadcaster = broadcast.Broadcaster` + deprecated constructor shims (`NewBroadcaster`/`NewBroadcasterWithBufferSize`/`NewBroadcasterWithReplay`/`NewBroadcasterFromHub` var aliases, `NewBroadcasterFromRaw` delegating to `NewBroadcasterFromHub`) until v5. The `Raw()` method was dropped WITH the move (a transparent alias cannot carry methods; it had zero in-repo consumers). 46 tests, 100% coverage. Depends on go-datastar + go-datastar/broadcast + go-sse (no root dep). See `docs/guides/datastar-integration.md` and `docs/guides/sse-and-datastar.md`.
- **dashboardui** (`dashboardui/v4`): Ready-made CQRS/ES observability dashboard — projection health, event catalog overview, real-time SSE updates. `startEventBridge` fails `New` on `SubscribeAll` error (fail-fast). `Config.SSEMaxReplay` caps first-connect backfill (0 = transport default 1000). SSE handler delegates to `transport.ServeDomainEvents`. CORS: same-origin default; consumers wrap with `httputil.CORS`. Builds HTML via `strings.Builder` + `fmt.Fprintf` (not templ). Has a `core/` sub-package (pure data layer: capabilities, pagination, events, overview, payload, format, DLQ) bridged via type aliases in `core_bridge.go`. CSP-safe: all inline `onsubmit` handlers replaced with `data-confirm` pattern, inline scripts moved to external JS.
- **setup** (`setup/v4`): Optional one-call composition root — `setup.New(Config) (*Bundle, error)` creates shared stores, constructs `usermgmt.Service` with all auth strategies, and builds admin/dashboard/login UI panels. `Bundle.Mount(mux)` mounts all routes with correct middleware ordering; `Bundle.Handler(mux)` mounts + wraps with security middleware in one call; `Bundle.Run(ctx, addr)` / `Bundle.RunHandler(ctx, addr, handler)` do mount→serve→graceful-shutdown→`Close()` in one call (ReadHeaderTimeout 5s + IdleTimeout 60s, deliberately NO Read/Write timeouts — SSE-safe; ShutdownTimeout 30s via `context.WithoutCancel`). The dashboard is session-gated (401) like adminui. Config validation at `New` normalizes trailing slashes, rejects `/` (login page owns root) and colliding paths; custom `AdminPath`/`DashboardPath` are passed to panels as `BasePath` so internal links/HTMX targets match the mount. Health endpoint at `/health` checks projection status (readiness gate under `AsyncStartup`). Config options: SessionTTL, Logger, LogoutURL, SSEURL, SSEHeartbeatInterval, SSEMaxReplay (backfill cap, 0=default 1000), OnProjectionFailed, AsyncStartup, DashboardReadOnly (default true), DashboardPageSize, LoginNoRegistration, HealthPath (`"-"` opts out), LivePath (opt-in public liveness), AdminMode, TenantID, AdminAuthorizer, DashboardAuthorizer, Observability (opt-in `*middleware.OTelBundle` — see the OTel adoption state bullet; conflicts with `Service`/`ServiceConfig`), AuthHandlerConfig (`*usermgmt.HandlerConfig` — HTTP-layer auth hardening: six rate limiters, cookie flags, OAuth2 redirects; the one seam outside the ServiceConfig-verbatim policy, see fullstack-wiring.md), Metrics+Version (appkit `/metrics`+`/version`, RunWithAppkit-only; appkit at v0.5.0), RequestLogging (access lines outermost in `Middleware`), EventCatalogPath/ProjectionStatusPath/DebugPath (opt-in session-gated machine endpoints), SSEScriptPath (`/sse.js` beside SSEPath). Flattened `ReadModelDB` is SQLite-only — a dialect probe rejects non-SQLite handles at `New` with a pointer to `ServiceConfig.ReadModelDialect` (unreachable DBs pass and fail as usermgmt infrastructure errors). `attachSSE` fails `New` on `SubscribeAll` error (fail-fast, not a dead feed). Auth mutations carry no CSRF by design (README security section documents why). Has its own README and `.golangci.yml` (adminui pattern). Uses direct identity-model imports for auth provider types.
- **systemadapter** (`systemadapter/v4`): Bridge module for go-cqrs-lite's `system.New()` composition root + `metaengine` storage planner. Exports `DomainConfig()` (pre-wires all 4 deciders + 20 commands + 21 event TypeDecoder), `EventTypeDecoder()` (maps event types to payload structs for `projectionadapter`), and `NewProjectionLayer(sys)` (creates usermgmt read models, Casbin authz, audit log backed by the system's event store + bus; `WithCheckpointStore`/`WithDeadLetterStore` options). See `docs/guides/leveraging-system-metaengine.md`.
- **health** (`health/v4`): Optional bridge to the go-health ecosystem — `NewProbe(provider, opts...)` builds a `gohealth.Probe` with one named check per projection (live/stopped pass, drain transient, failed infrastructure — mirrors `ProjectionReadinessCheck`), `Recorder(provider)` merges projection checks with a samber/do injector's own service checks, `NewDashboard(probe, opts...)` returns the go-health-dashboard UI. Depends on published root + go-health + go-health-dashboard — zero local replaces. Has its own README/`.golangci.yml`/`.cqrs-lint.json`. 100% coverage.
- **auditlog** (`auditlog/v4`): Optional bridge to samber-do-auditlog — `WithAuditLog(auditCfg, viewerCfg)` returns a `Setup` (do.InjectorOpts for `do.NewWithOpts`, plugin handle, live SSE viewer as http.Handler) in one call. Depends on samber-do-auditlog + do/v2 + errorfamily — zero local replaces. Has its own README/`.golangci.yml`/`.cqrs-lint.json`. 100% coverage.
- **integration_test**: Cross-module bridge tests (incl. fullstack UI suite: seeded admin render, dashboard projection health, login auth-button matrix)
- **e2e/server**: Playwright E2E test server for offline-sync browser testing
- **examples/**: `basic`, `datastar-demo`, `catalog-demo`, `admin-demo`, `dashboard-demo`, `middleware-demo`, `middleware-showcase`, `observability-demo`, `async-startup-demo` (server binds immediately, `/health` 503→200 while projections replay), `samber-do-demo` (best-practice samber/do v2 DI wiring: composition root, lazy singletons, named auth providers, lifecycle adapter for `Service.Close()`, test container with `do.OverrideNamed`), `setup-demo` (one-call `setup.New` full-stack demo: dev-login seeds super_admin via the real authz path, e2e test asserts 401 gates + authenticated flow; imports identity-model directly — lint-clean, unlike older examples), `system-demo` (full `system.New()` integration with introspection, health checks, and declarative projections)

**Dependency direction:** identity-model ← usermgmt (type aliases). Root → usermgmt is zero imports (clean boundary). Auth strategies → root/usermgmt via interfaces only. adminui/loginpage → root + usermgmt + templ-components. dashboardui → root + usermgmt + templ-components (icons). datastar → go-datastar + go-sse only (no root dep). systemadapter → usermgmt + identity-model + go-cqrs-lite system/metaengine. health → root types (published, see health/go.mod) + go-health/dashboard. auditlog → samber-do-auditlog + do/v2 (no cqrs-htmx dep). Nothing depends on adminui, loginpage, dashboardui, datastar, setup, systemadapter, health, or auditlog.

**Key dependencies:** go-cqrs-lite per-module version trains (root currently: command/v4 v4.10.0, event/v4 v4.11.0, id/v4 v4.6.0, query/v4 v4.8.0 — CQRS/event sourcing; per-module trains, not lockstep, see Gotchas; bumped to the 2026-09-08 trains 2026-09-09 via `cqrs-upgrade`), casbin/v3 (authz), httputil v1.2.0 (HTTP middleware: CSRF, Server-Timing, rate limiting; swept repo-wide 2026-09-17), go-error-family (error classification), go-branded-id (typed IDs), go-sse v0.6.0 (SSE broadcaster, stream, replay), go-datastar v0.5.0 (DataStar protocol library — published, no replace) + go-datastar/broadcast (Broadcaster submodule, v0.6.0 require satisfied by TEMPORARY sibling replaces until the lockstep tag is pushed), a-h/templ (HTML templating), ginkgo/gomega (BDD testing). `justinas/nosurf` and `golang.org/x/time` are now transitive deps via httputil (no longer direct root deps).

## Key Patterns

- **Library principle:** Never enforce defaults consumers might disagree with (no mandatory CSP/HSTS/CSRF — all opt-in)
- **No stdlib error constructors:** `errors.New`/`fmt.Errorf` banned in non-test code. Use `event.New*/Wrap*/Wrapf/Newf` from go-cqrs-lite.
- **Error families → HTTP status:** Rejection(400), Conflict(409), Transient(503), Corruption(500), Infrastructure(503)
- **Duck-typing for external libs:** `Enforcer` (← casbin), `TemplComponent` (← templ), auth provider interfaces — consumers import what they need
- **authMode enum:** `authNone`/`authRequired`/`authAuthorized` — impossible states unrepresentable
- **templ `_templ.go` committed:** Generated files are committed so consumers run no codegen
- **Coverage gate:** Root ≥90% (actual 93.7%, verified 2026-09-18), usermgmt ≥74% (actual 82.1%), identity-model ≥70% (actual 75.5%) (CI-enforced)
- **Projection lifecycle via projectionhost:** `StartProjections` uses `projectionhost.Host` from go-cqrs-lite — per-projection goroutines, per-projection checkpoint keys (by projection `Name()`), DLQ, crash-restart. Read-your-writes preserved via `waitForDrain`. Returns `(*projectionhost.Host, error)`; all setup structs and `Service` hold it and stop it on `Close()`. ADR-0031 (Superseded). Shared `startProjectionHost` factory used by both `StartProjections` and `RebuildProjection`.
- **Event catalog (Published Language):** `cqrshtmx.EventCatalog` + `EventCatalogHandler` serve event schemas as immutable JSON (1-year cache, FNV-1a ETag). `usermgmt.DefaultEventCatalog()` pre-registers all 21 events. `EventCatalog()` method on both `EventSourcedSetup` and `Service`.
- **Projection health monitoring:** `cqrshtmx.ProjectionStatusHandler(provider)` serves live projection status as JSON (`no-cache`, per-request ETag). `ProjectionStatusProvider` interface implemented by `*usermgmt.Service` and `*usermgmt.EventSourcedSetup`. See `docs/guides/projection-health-monitoring.md`.
- **Async projection startup (`AsyncStartup`):** `ServiceConfig.AsyncStartup` / `EventSourcedConfig.AsyncStartup` / `setup.Config.AsyncStartup` (all default `false` = backward-compatible synchronous drain). When `true`, `NewService`/`setup.New` returns immediately after `host.Start()` — the HTTP server binds while projections replay the journal in the background, eliminating multi-minute restart outages. `cqrshtmx.ProjectionReadinessCheck(provider)` is the readiness gate (returns 503 while any worker is `idle`/`running`/`backoff`/`draining`/`failed`, 200 when all are `live`/`stopped`); `setup.Bundle` mounts it at `/health` automatically. In async mode projection failures during drain surface via `ProjectionStatuses()`/`/health`/`OnProjectionFailed` — not as a `NewService` error. Mechanism: `startProjectionHost(..., block bool, ...)` skips `waitForDrain` when `block=false`. See `docs/guides/async-projection-startup.md`.
- **Projection rebuild:** `RebuildProjection(ctx, name)` on both `EventSourcedSetup` and `Service` — stops host, resets checkpoint + read-model, creates fresh host, replays journal. See `docs/guides/event-replay-and-rebuild.md` and `docs/guides/rebuild-projection-runbook.md`.
- **Checkpointed restarts via SQL hydrate (2026-08-16):** setting `CheckpointStore` (+ `ReadModelDB`/`ReadModelDialect`) is now SAFE and is the intended production config. Two cooperating pieces in usermgmt: (1) `Hydrator` interface — all 4 SQL read models rebuild their in-memory maps + secondary indexes from the view store before the host starts (`hydrateProjections` runs in `NewEventSourcedSetup` AND `StartProjections`; `RebuildProjection` deliberately skips it so a rebuild heals corrupted SQL rows via clean full replay). (2) `hydrationAwareCheckpointStore` — applied inside the shared `startProjectionHost` factory (rebuilds get it too), it never persists/honors checkpoints for non-Hydrator projections: `casbin-projection` and the default in-memory `AuditLog` always full-replay, so authz policies and the audit trail stay complete after restarts (empirically verified — without the wrapper casbin comes back empty). Crash semantics are at-least-once: the append handlers (`CredentialAdded`/`ExternalAccountLinked`/`MemberAdded`) were made idempotent for convergence; `MemberAdded.AddedAt` uses event time, not wall clock. TOTP secrets persist in `users_view.data` (`totp_secret` via alias-marshal — `User.TOTPSecret` keeps `json:"-"` publicly). **TOTP migration gotcha:** rows written by pre-hydrate versions lack the secret — run `RebuildProjection(ctx, "user-read-model")` once after upgrading an existing SQL read model, or affected TOTP users must re-enroll.
- **go-cqrs-lite leveraging (the #1 undocumented capability):** the `*command.Dispatcher`/`*query.Dispatcher` passed to `Config.Commands`/`Config.Queries` ARE go-cqrs-lite dispatchers — they implement `Use(mw ...)`, so all 27 factories from `go-cqrs-lite/middleware/v4` (logging, recovery, retry, circuit breaker, metrics, OTel tracing, validation, idempotency) compose with zero glue. This is strictly richer than `BeforeDispatchHook`/`AfterDispatchHook` (which only see the HTTP request, not the command type). Full capability-vs-usage map + recipes: `docs/guides/leveraging-go-cqrs-lite.md`. Runnable proofs: `examples/middleware-demo/` (retry/logging) and `examples/observability-demo/` (OTel tracing + Prometheus /metrics). Underused upstream modules worth knowing: `middleware` (dispatch-level), `otel`+`prometheus` (observability), `scheduling` (durable timers — usermgmt expiry is currently in-process, not durable), `deriver` (reactive sagas), `schema.VersionedSeekableJournal` (store-layer upcasting for projections — identity-model only upcasts at decode time).

- **OTel adoption state (sprint 64→90 landed 2026-09-14, audit `docs/research/2026-09-13_otel-deep-dive.html`):** the library stays otel-free by design (zero `go.opentelemetry.io` imports in root/usermgmt/setup — verify with `rg -l go.opentelemetry.io root/ usermgmt/ setup/` outside go.mod/go.sum; ROADMAP rejects middleware re-export) and every version is current (otel SDK v1.46.0, go-cqrs-lite/otel v4.4.0, prometheus/v4 v4.3.0). KEY FACT most consumers miss: go-cqrs-lite's decider + storage layers emit `decider.execute`/`decider.load`/`event.store.save`/`event.store.load` spans via the GLOBAL tracer, so a single `cqrsotel.Setup()` call auto-traces the entire identity domain with zero middleware (decider/otel.go; storage/command_store_save.go:26). All audit gaps are closed and API-verified in `docs/guides/leveraging-go-cqrs-lite.md` §2.1–§2.6 (hooks / dispatch tracing / Prometheus / FREE DOMAIN SPANS / HTTP root spans via otelhttp / two-mechanism correlation) — runnable proofs: `examples/observability-demo` (otelhttp root span + `TestOtelHTTPRootSpanAndTraceparentExtraction` via SpanRecorder) and `examples/middleware-demo` (live stdout spans + typed metrics + Prometheus /metrics). `setup.Config.Observability` accepts an upstream `*middleware.OTelBundle` (publish+handler middleware prepended into `SecurityHooks`, applied to the bus before projections subscribe, bundle outermost; nil = legacy behavior; conflicts with `Service`/`ServiceConfig` — those users set `SecurityHooks` directly, which BOTH `ServiceConfig` and `EventSourcedConfig` expose and `NewService` honors via its `NewEventSourcedSetup` delegation, ordering-pinned in `service_security_test.go`). ## Benchmarks

**Adoption-benchmark pattern (`setup/run_appkit_test.go:BenchmarkSpikeBaselineVsAppkit`):** the canonical 5× benchstat-friendly comparison between the bundle's two serve paths (`RunHandler` vs the appkit spike `RunWithAppkit`). Use this pattern for any new cross-stack comparison — the components are load-bearing for getting honest numbers:

- `-benchtime=2s -benchmem -count=5` so `benchstat` can compute per-metric p-value deltas.
- `b.Loop()` (Go 1.24+) instead of `for i := range b.N`.
- `b.ReportAllocs()` + `b.ReportMetric(b.N/b.Elapsed().Seconds(), "req/s")` for benchstat-compatible columns.
- `b.Cleanup(func() { b.StopTimer(); stop() })` so the server shutdown drain never counts toward ns/op.
- For any bench where the stack under test emits per-request logs (appkit does — httputil does not): either pass the noise-suppression flag (`appkit.LogLevelError`) to the production code path, OR pin `slog.SetDefault(slog.New(slog.DiscardHandler))` for the sub-bench and restore on cleanup. Skipping this turns per-request formatted log lines into the dominant measurement (comparison-report finding 7 — the original 16178 vs 45049 ns/op delta was almost entirely per-request INFO logging).
- Invocation pattern + baseline numbers live in `setup/README.md#benchmarks` and `docs/benchmarks/setup-baseline-2026-08-17.txt`.

**Don't hand-rolled timing:** every serious comparison in this repo uses `b.Loop()` + `b.ReportAllocs()` + benchstat. One-off `time.Since` blocks in tests are forbidden — they belong in `*_bench_test.go` files.

## dashboardui full-templ migration (2026-09-22)

- **Trigger:** the user asked "dashboardui STILL doesn't use templ?!?!" — the same question recorded in the 2026-07-30 decision matrix. The deferral decision doc (`dashboardui/docs/planning/templ-migration-evaluation.md`) had pinned a revisit threshold of ~5,000 lines of HTML-generating code; the tree measured ~4,840 lines across 20 files with 155 manual `esc()` calls, so the document's own revisit criterion was effectively met. Executed the same day instead of re-deferring.
- **Byte-identical escaping is the load-bearing fact:** `templ.EscapeString` in a-h/templ v0.3.1020 is literally `func EscapeString[T ~string](s T) string { return html.EscapeString(string(s)) }` — the 155 manual `esc()` call sites transcribed to `{ expr }` produce identical bytes, so `strings.Contains` assertions and CSS classes carried over unchanged. Verified with a throwaway old-vs-new layout diff test before committing to the approach (removed after).
- **Three accepted cosmetic deltas (all HTML5-equivalent):** templ emits lowercase `<!doctype html>` (hardcoded in its parser), drops the self-closing slash on void elements (`<meta charset="utf-8">`), and expands SVG paths to explicit `</path>` close tags; inter-element whitespace in the source layout appears in output (inert everywhere — flex/grid contexts, collapsing text). Eight test assertions updated from `<!DOCTYPE html>` to `<!doctype html>`.
- **Security upgrade for free:** templ's `href={ expr }` goes through `templ.JoinURLErrs` → `templ.URL()`, which allows only http/https/mailto/tel/ftp(s) schemes and rewrites others to `about:blank#blocked`. The old raw interpolation would have rendered a `javascript:`-bearing stream-type/event-ID as a clickable link; templ makes it inert. No test regressed.
- **Architecture:** 9 `.templ` files (`layout`, `components` shared leaf wrappers, one per panel page), generated `_templ.go` committed. Handlers now load data and call `renderPage(w, r, somePage(p, ...))` where `renderPage`/`writeHTML` take a `templ.Component` and render straight to the ResponseWriter. `d.config` is NEVER touched inside templ components (they only see params) — payload bytes are computed in the handler and passed in. Go helpers the templates call live in `detail_items.go` (definition-item builders), `pagination.go` (href/info/options builders), `tables.go` (plainHeaders), `stats.go`/`badges.go` (pure enum mappings). `templ helper` is NOT a syntax for Go funcs in .templ files — data builders belong in .go files (first draft tried `templ helper foo(...)`, compile error).
- **Dead code removed:** `buttons.go`, `format.go` (encodingBadge bridge), the string bridges in `tables.go`/`stats.go`/`badges.go`/`definitions.go`/`render.go` (tableHTML/tableHTMLRaw/textCell/rawCell, statCardHTML, badgeHTML, buttonLink/buttonSubmit/copyButtonHTML, emptyState/emptyStateIcon, listNoteCountHTML, filterInput, definitionListHTML, renderPagination/renderPaginationInfo/renderPageSizeSelector, formatLinks, renderErrorShell, renderLayout/renderSidebar/renderHeader/renderToastContainer/renderErrorHandling/navIconSVG + all per-page render* methods).
