htmx 4.0 — What's New & What Changed

A comprehensive deep-dive into the next major version of htmx — covering breaking changes, new features, the rewritten extension system, and migration implications for cqrs-htmx. Sources: four.htmx.org docs, pnpm registry, and migration guide.

Overview

htmx 4.0 is the next major version, skipping v3 entirely. It's currently in beta (4.0.0-beta4) under the pnpm next tag. The docs site at four.htmx.org carries a prominent banner: "htmx 4.0 is under construction."

Transport

Replaced XMLHttpRequest with the native fetch() API across all requests. Irreversible.

Philosophy

Explicit over implicit. Attribute inheritance, error swapping, and extension loading all moved from implicit to opt-in.

Distribution

New htmax.js bundle ships htmx + 8 popular extensions in one file. ESM builds now first-class.

Modern Web

View Transitions API, Web Components / Shadow DOM support, and a reactive layer (hx-live).

Version skip: There is no htmx 3.x. The jump from 2.x to 4.x aligns the version number with the major rewrite. The htmx-2-compat extension restores v2 defaults for incremental migration.

Breaking Changes

Nine behavioral changes between htmx 2.x and 4.x. Most can be reverted with config flags, except fetch() which is permanent.

Change htmx 2.x htmx 4.x Revertible
HTTP transport XMLHttpRequest → fetch() API No
Inheritance Implicit by default → Explicit (:inherited) implicitInheritance=true
Error responses 4xx/5xx not swapped → Swapped into target noSwap=[...]
hx-delete form data Includes form inputs → Excludes (like hx-get) Manual hx-include
History cache localStorage caching → Re-fetches on back/fwd history="reload"
OOB swap order OOB before main → Main first, then OOB No
Trigger queue modifier queue:all → Use hx-sync No
Default timeout 0 (none) → 60000ms (60s) defaultTimeout=0
Extension loading hx-ext attribute → Script include, page-wide No

Explicit Inheritance Detail

htmx 2.x — Implicit
<div hx-confirm="Are you sure?">
  <button hx-delete="/item/1">
    Delete
  </button>
</div>
→
htmx 4.x — Explicit
<div hx-confirm:inherited="Are you sure?">
  <button hx-delete="/item/1">
    Delete
  </button>
</div>

The :inherited suffix works on any attribute. Use :append to add to an inherited value instead of replacing it. Revert globally with htmx.config.implicitInheritance = true.

Error Response Swapping

Behavioral shift: In v2, 4xx/5xx responses were silently dropped (no swap). In v4, the HTML body of any response — including 422 validation errors and 500 server errors — gets swapped into the target element. Design error responses as valid swap content, or configure htmx.config.noSwap.
// Restore v2 behavior — don't swap error responses htmx.config.noSwap = [204, 304, '4xx', '5xx'];

Renames & Removals

Attributes renamed, removed, or replaced. The hx-disable rename is particularly tricky — do it before upgrading to avoid semantic conflicts.

Renamed Attributes

Old (v2) → New (v4) Notes
hx-disable → hx-ignore Skip htmx processing on element
hx-disabled-elt → hx-disable Disable form elements during requests
hx-request → hx-config Per-element request configuration
Migration order for hx-disable: Rename hx-disable → hx-ignore first, then rename hx-disabled-elt → hx-disable. Doing it in the wrong order causes semantic conflicts.

Event System Renames

All events follow a new pattern: htmx:phase:action[:sub-action]. Error events consolidated to htmx:error and htmx:response:error.

htmx 2.x → htmx 4.x Phase
htmx:afterOnLoad → htmx:after:init Init
htmx:afterProcessNode → htmx:after:init Init
htmx:beforeOnLoad → htmx:before:init Init
htmx:afterRequest → htmx:after:request Request
htmx:afterSettle → htmx:after:swap Swap
htmx:afterSwap → htmx:after:swap Swap
htmx:beforeCleanupElement → htmx:before:cleanup Cleanup
htmx:beforeHistorySave → htmx:before:history:update History
…and more. Error events consolidated to htmx:error + htmx:response:error

New Events Not in v2

htmx:response:error

HTTP error status (4xx/5xx) received. Separate from network errors.

htmx:before:response

After response received, before body consumed. Last chance to inspect raw Response.

htmx:after:implicitInheritance

Fires after implicit inheritance is applied (when compat mode is on).

htmx:process:{type}

Custom template processing hook for non-standard HTML templates.

htmx:before/after:viewTransition

View Transitions API lifecycle hooks.

htmx:after:history:push/replace

Granular history manipulation events.

HCON — htmx Configuration Object Notation

A new mini config language for attribute values. Designed to feel natural in HTML attributes — no outer braces, flexible quoting, flag-style booleans. Falls back to JSON when a value starts with {.

Syntax Rules

  • Separators: spaces or commas between pairs
  • Booleans: bare keyword = true
  • Numbers: parsed as integers
  • Strings: double or single quotes (needed for spaces/special chars)
  • Nesting: dot-notation (sse.reconnect:true)
  • JSON fallback: values starting with { parsed as JSON

Where HCON is Used

  • hx-swap modifiers
  • hx-trigger modifiers
  • hx-config (new)
  • hx-vals / hx-headers
  • <meta name="htmx-config">
  • HX-Location response header

HCON form

<!-- swap modifiers --> <div hx-swap="innerHTML swap:200ms settle:100ms scroll:top"> <!-- trigger modifiers --> <input hx-trigger="keyup delay:300ms"> <!-- per-element config --> <button hx-config="timeout:5000"> <!-- global config via meta --> <meta name="htmx-config" content="defaultSwap:outerHTML transitions:true"> <!-- nested keys --> <meta name="htmx-config" content="sse.reconnect:true sse.reconnectDelay:1000">

JSON form (also accepted)

<!-- swap modifiers as JSON --> <div hx-swap='{"swap":"200ms","settle":"100ms"}'> <!-- explicit style override --> <div hx-swap='{"style":"outerHTML","swap":"200ms"}'> <!-- global config as JSON --> <meta name="htmx-config" content='{"defaultSwap":"outerHTML","transitions":true}'> <!-- server-rendered JSON injected directly --> <button hx-config='{"credentials":"include","timeout":5000}'>
Mixing rule: JSON and HCON are not mixed — the entire attribute value is parsed as one or the other. If it starts with {, it's JSON. Otherwise it's HCON.

New Features

Seven additions that expand htmx's expressiveness without breaking the core model.

New hx-action + hx-method — Decoupled URL/Method

Separate the URL from the HTTP method, enabling dynamic method selection. The shorthand attributes (hx-get, hx-post, etc.) still work and are equivalent.

<!-- Decoupled form — method can be set dynamically --> <button hx-action="/api/users" hx-method="post">Create User</button> <!-- Equivalent shorthand --> <button hx-post="/api/users">Create User</button>
New hx-status — Per-Status-Code Swap Control

Route different HTTP status responses to different targets. Fine-grained control over how 200, 422, 500, 503, etc. are handled — per element.

<form hx-post="/submit" hx-target="#result" hx-status:422="target:#validation-errors" hx-status:500="target:#server-error" hx-status:503="none"> <input name="email"> <button type="submit">Submit</button> </form>
New hx-config — Per-Element Request Configuration

Replaces the old hx-request attribute. Merges into the request context before the request is issued. Uses HCON or JSON for fetch options like timeout, credentials, CORS mode.

<button hx-get="/slow" hx-config="timeout:30000">Load</button> <button hx-get="https://api.example.com/data" hx-config='credentials:"include" mode:"cors"'> Cross-origin </button>
New Web Components & Shadow DOM Support

Explicit support for htmx inside Shadow DOM. Call htmx.process() after creating shadow DOM. New targeting keywords: host (target shadow host) and global:<selector> (break out of shadow DOM).

customElements.define('my-counter', class extends HTMLElement { connectedCallback() { const shadow = this.attachShadow({mode: 'open'}) shadow.innerHTML = ` <button hx-post="/increment" hx-target="#count">+1</button> <div id="count">0</div> ` htmx.process(shadow) // Initialize htmx for shadow DOM } })
New htmax.js — Bundled Extensions Distribution

A single file bundling htmx with the 8 most popular extensions. Extensions are automatically available — just use their attributes directly (hx-sse:connect, hx-ws:connect, etc.).

<script src="/js/htmax.min.js"></script> <!-- Includes: SSE, WebSockets, preload, browser-indicator, download, optimistic, targets, live -->
New HX-Request-Type Header

New request header: "partial" for targeted swaps, "full" for body-level or hx-select requests. Lets the server distinguish between partial and full-page AJAX requests.

New Upgrade Checker CLI

Built-in migration scanner that checks templates and JS files for v2 code that needs updating. Scans .html, .php, .js, .ts, .jinja, .erb, .hbs by default.

pnpm dlx htmx.org@next upgrade-check -- ./path/to/project/root pnpm dlx htmx.org@next upgrade-check --ext .vue ./path/to/project/root

Multi-Target Updates: OOB + Partials

Two ways to update multiple elements from a single response. Out-of-band swaps match by ID; <hx-partial> tags give explicit control via CSS selectors.

OOB

Out-of-Band Swaps

Match elements by their id attribute. Add hx-swap-oob="true" to any element in the response.

<div id="message" hx-swap-oob="true"> Form submitted! </div> <form id="my-form"> <!-- Updated form content --> </form>

Best for: consistent IDs, notification areas, counters, status indicators.

New

<hx-partial> Tags

Explicit targeting via CSS selectors. Each partial accepts hx-target, id (shorthand), and hx-swap.

<hx-partial hx-target="#messages" hx-swap="beforeend"> <div class="message">New message</div> </hx-partial> <hx-partial id="notifications"> <span class="badge">5</span> </hx-partial> <form id="my-form"> <!-- Main content --> </form>

Best for: elements without IDs, class targeting, complex update patterns.

Swap order change: In v2, OOB elements swapped before main content. In v4, main content swaps first, then OOB/partials in document order. If OOB swaps create DOM that the main swap depends on, restructure so each swap is independent.
Template language compatibility: For template engines that strip unknown tags, use the equivalent <template hx type="partial" hx-target="..."> form. htmx converts <hx-partial> to this internally.

Rewritten Extension System

Completely rewritten from callback-based to event-based hooks. Extensions are lightweight with no performance penalty. They apply page-wide without hx-ext.

Defining an Extension

htmx.registerExtension("my-ext", { init: (internalAPI) => { // Called once on registration }, htmx_before_request: (elt, detail) => { // Before each request if (!isValid(detail.ctx)) { return false; // Cancel request } }, htmx_after_request: (elt, detail) => { // After request completes }, handle_swap: (style, target, fragment, spec) => { // Custom swap strategy }, });

Loading & Restricting

<!-- Load: just include the script --> <script src="/path/to/htmx.js"></script> <script src="/path/to/ext/hx-sse.js"></script> <!-- Restrict via allow-list --> <meta name="htmx-config" content='{"extensions":"sse, ws"}'> <!-- Or via bundler --> import 'htmx.org'; import 'htmx.org/dist/ext/hx-sse';

Spotlight: hx-live

The most significant new extension — a lightweight reactive scripting layer inspired by _hyperscript:

<!-- Reactive expression auto-reruns on DOM changes --> <input id="name" value="world"> <output hx-live="this.textContent = 'hello, ' + q('#name').value"></output> <!-- Debounced live search with async/await --> <output hx-live=" await debounce(200); this.textContent = await fetch('/q?term=' + q('#search').value).then(r => r.text()); "></output> <!-- q() selector grammar with directionals --> q('.foo') // every .foo q('closest .field') // nearest ancestor q('next .row') // first match after this element q('.tab').take('selected', '.tab') // class juggling

Features: q() with directional grammar (closest, next, prev, first, last), debounce(), forEvent(), nextFrame(), take(), async/await support, swap-aware recompute scheduling, auto-cleanup.

Migration Path

Most v2 apps work with either a two-line config restore or the htmx-2-compat extension. Then migrate incrementally.

Option A: Two-Line Config Restore

<script> htmx.config.implicitInheritance = true; htmx.config.noSwap = [204, 304, '4xx', '5xx']; </script> <script src="...htmx.min.js"></script>

Restores implicit inheritance and old error-swapping defaults. Minimal, surgical.

Option B: htmx-2-compat Extension

<script src="/path/to/htmx.js"></script> <script src="/path/to/ext/htmx-2-compat.js"></script>

Restores implicit inheritance, old event names, AND previous error-swapping defaults. Broader coverage.

Migration Checklist

Before Upgrading

  • Rename hx-disable → hx-ignore
  • Rename hx-disabled-elt → hx-disable
  • Run pnpm dlx htmx.org@next upgrade-check
  • Remove hx-ext attributes (not needed)
  • Remove hx-vars, hx-params, hx-prompt

After Uploading

  • Add compat config or extension if needed
  • Design error responses as valid swap content
  • Update event listeners to new naming pattern
  • Check OOB swap ordering dependencies
  • Update queue: triggers to use hx-sync
  • Consider new features: hx-status, hx-config, <hx-partial>

Impact on cqrs-htmx

Our library currently embeds htmx v2.0.9 via go:embed in htmx_embed.go (~49KB). Here's what a future upgrade would touch.

Component Current (v2.0.9) v4 Impact Severity
HTMXVersion() Returns "2.0.9" Change to "4.0.x" Trivial
htmx_embed.go Embeds v2 minified JS Replace embedded file with v4 dist Trivial
Response headers (sse.go) HX-Redirect, HX-Trigger, etc. All still supported — no changes needed None
Request headers (htmx.go) Reads HX-Request, HX-Target Still present. New: HX-Request-Type, HX-Source Additive
SSE/WS protocol helpers sse.go, ws.go hx-sse/hx-ws now separate scripts — still compatible Low
Error response handling Error handlers return text/HTML v4 swaps 4xx/5xx by default — must return valid swap HTML Medium
CSRF middleware Expects specific request behavior fetch() changes cookie/cred handling — verify CSRF token flow Medium
WebSocket message parsing (ws.go) WSMessage, ParseWSMessage Still protocol-level — unaffected by transport change None
Recommendation: No rush — v4 is still beta. Stable v2.0.10 remains the pnpm latest. Wait for v4 stable release, then:
  1. Run upgrade-check against any example apps
  2. Replace embedded htmx.min.js with v4 dist
  3. Update HTMXVersion() return value
  4. Verify CSRF token flow with fetch() transport
  5. Consider exposing HX-Request-Type in context helpers
  6. Test SSE/WS bridges with separate extension scripts loaded
Key risk: The fetch() transport changes how credentials and cookies are sent by default. Our CSRF middleware (csrf.go) relies on reading tokens from requests — verify that fetch() with default credentials mode still sends cookies correctly, especially for cross-origin scenarios.
