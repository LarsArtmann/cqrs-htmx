httputil v0.11.0 — Adoption & Utilization Audit

cqrs-htmx depends on httputil for CSRF, security headers, production serving, and Server-Timing. This audit maps every httputil capability against actual usage to find missed opportunities, hand-rolled duplicates, and broken references.

Anti-patterns
The bottom line cqrs-htmx has solid adoption of the four features it migrated to httputil (CSRF, security headers, production server, Server-Timing) and is on the latest v0.11.0. However, it misses almost every advanced middleware feature httputil offers — Nonce, Compression, CORS, ETag, Decompression, Metrics, and RegisterErrorClassifications are all unused. Three compiler-breaking references to httputil.ServerTimingMiddlewareWhen / httputil.MeasureServerTiming (which live in the server_timing sub-module, not the httputil root) break go test ./... for the root module and go build for admin-demo. adminui hand-rolls a NonceFunc callback that duplicates httputil’s entire Nonce/CSP system — the same pattern that caused a CSP bug in another consumer.

Current Usage

cqrs-htmx is a library, not an application. It follows a duck-typing philosophy: CORS, compression, body limits, and other everyday HTTP middleware are intentionally not re-exported — consumers import httputil directly. This is a sound design decision documented in doc.go and docs/guides/leveraging-httputil.md. However, the audit evaluates both internal usage (does cqrs-htmx use httputil where it should?) and example coverage (do the examples demonstrate the full range?).

  • CSRF protection — deep integration: ValidateCSRF, ErrCSRFInvalid, CSRFTokenFormField, CSRFTokenHTMLMeta, CSRFResponseHeaderMiddleware. Properly wired through the handler pipeline with per-handler validation.
    csrf_handler.go, errors.go, adminui/handler.go, loginpage/handler.go, csrf_reexport.go
  • Security headers — SecurityHeaders(DefaultSecurityHeadersConfig()) used in adminui and dashboardui. Deprecated alias in security.go delegates correctly.
    adminui/handler.go:185, dashboardui/handler.go:34, security.go
  • Production server — all 7 examples use httputil.NewServer with ServerConfig. Never bare http.ListenAndServe.
    examples/basic, admin-demo, dashboard-demo, middleware-demo, observability-demo, catalog-demo, datastar-demo
  • Server-Timing — servertiming.WrapServerTiming used in app.go for opt-in timing via Config predicate. Correct sub-module import.
    app.go:335
  • ParseUintQuery — used in usermgmt for pagination parameter parsing.
    usermgmt/credential_http.go, usermgmt/verification_totp_http.go
  • httpspec compliance — 18-spec behavioral suite runs against the recommended middleware stack and the full App dispatch pipeline.
    httpspec_compliance_test.go
  • Version currency — on latest v0.11.0 (released same day as this audit).

Usage Architecture

httputil is imported across 14 module go.mod files and 30+ Go source files. The root module uses httputil for: CSRF (validation + token helpers + error integration), security headers (delegated wrapper), Server-Timing (WrapServerTiming in the App pipeline), and ParseUintQuery (pagination). The server_timing sub-module is imported directly in app.go and re-exported via deprecated aliases. All 7 examples use httputil.NewServer. Three re-export files (csrf_reexport.go, ratelimit_reexport.go, server_timing_reexport.go) provide 39 deprecated backward-compat aliases planned for v5 removal.

Hand-rolled alternatives exist for: Request ID (ContextEnrichmentMiddleware), Recovery (RecoveryMiddleware with errorfamily), Logging (RequestLoggingSlog with dispatch-error capture), Body Size (decoder.go inline LimitReader), Nonce (adminui NonceFunc callback), Health (HealthHandler + readiness.go), and StatusRecorder (with ErrorRecorder). Several of these are intentionally richer than the httputil equivalent — see the Not Applicable section.

Critical Findings

Anti-Pattern · Breaks compilation

Broken compiler references — httputil.ServerTimingMiddlewareWhen does not exist in httputil root

example_app_test.go:299,303 · examples/admin-demo/main.go:130

Three call sites reference httputil.ServerTimingMiddlewareWhen and httputil.MeasureServerTiming, but these symbols live in the server_timing sub-module (package servertiming), not the httputil root package. The root module’s go test ./... fails to compile, and examples/admin-demo fails to build. This appears to have been introduced when Server-Timing was extracted into a sub-module in v0.10.0 — the call sites were never updated.

Recommendation Import github.com/larsartmann/httputil/server_timing and use servertiming.ServerTimingMiddlewareWhen and servertiming.MeasureServerTiming. Alternatively, use the deprecated cqrs-htmx aliases cqrshtmx.ServerTimingMiddlewareWhen and cqrshtmx.MeasureServerTiming. 
// Before (broken):
handler := httputil.ServerTimingMiddlewareWhen(func(r *http.Request) bool {
    return r.URL.Query().Has("debug")
})(mux)

// After (fixed):
import servertiming "github.com/larsartmann/httputil/server_timing"

handler := servertiming.ServerTimingMiddlewareWhen(func(r *http.Request) bool {
    return r.URL.Query().Has("debug")
})(mux)

Missed Opportunity · High impact

Nonce middleware (v0.10.0) unused — adminui hand-rolls a weaker NonceFunc callback

adminui/config.go:73-76 (NonceFunc) · adminui/handler.go:78-84 (nonce()) · httputil/nonce.go (unused)

httputil v0.10.0 added a complete CSP nonce middleware: Nonce(cfg) generates a cryptographically random nonce (20 bytes / 160 bits default), stores it in request context, optionally sets the Content-Security-Policy header, and provides NonceFromRequest, NonceAttr (returns nonce="..." for templates), RecommendedCSPWithNonce, and ProductionCSPWithNonce. All validated, fuzz-tested, and benchmarked.

adminui instead exposes NonceFunc func(*http.Request) string — pushing nonce generation, CSP header construction, and context propagation entirely to the consumer. When NonceFunc is nil (the default), no nonce is generated and no CSP header is set. This is the exact same pattern that caused a CSP bug in another consumer (see httputil’s docs/feedback/new/2026-08-09_consumer-reinvents-nonce-csp-system.md).

Recommendation Replace adminui’s NonceFunc with httputil.Nonce(httputil.DefaultNonceConfig()) in the middleware chain. Use httputil.NonceFromRequest(r) in the page data struct instead of the callback. This gives adminui per-request nonces with CSP headers, NonceAttr for templates, and bomb-proof CSP construction for free. 
// Before: consumer must implement nonce generation
panel, _ := adminui.New(adminui.Config{
    NonceFunc: func(r *http.Request) string {
        // consumer hand-rolls crypto/rand + base64 + context storage...
        return generateMyOwnNonce(r)
    },
})

// After: httputil.Nonce middleware + NonceFromRequest
handler := cqrshtmx.Chain(
    httputil.SecurityHeaders(httputil.DefaultSecurityHeadersConfig()),
    httputil.Nonce(httputil.DefaultNonceConfig()),  // CSP nonce per request
    panel.Mount,
)(mux)

// In adminui handler:
nonce := httputil.NonceFromRequest(r)  // replaces h.nonce(r)
Missed Opportunity · High impact

Compression middleware unused — all JSON, HTML fragments, and SSE sent uncompressed

Not used anywhere · httputil/compression.go (unused) · documented in leveraging-httputil.md but no example

httputil provides pooled gzip/deflate response compression with RFC 7231 q-value negotiation, automatic skipping of small responses and already-compressed content types, and configurable compression levels. For a library whose primary use case is serving HTML fragments over HTMX and JSON API responses, compression is a significant performance win (typically 5-10x smaller payloads for text-heavy responses). No example demonstrates the pattern.

Recommendation Add httputil.Compression(httputil.DefaultCompressionConfig()) to at least one example’s middleware chain (e.g., examples/basic/main.go) and document it as a recommended default.

Missed Opportunity · Medium impact

ETag middleware (v0.10.0) unused for dynamic responses

Not used anywhere · httputil/etag.go (unused) · cqrs-htmx has its own static-asset ETagging only

cqrs-htmx has its own FNV-1a ETagging for static assets (htmx.js, OpenAPI spec, event catalog — 1-year immutable cache). But dynamic query responses (JSON API, paginated lists) do not get ETagged. httputil.ETag(etag.DefaultETagConfig()) buffers GET/HEAD responses, computes an FNV-64a hash, and returns 304 Not Modified on If-None-Match match. This would eliminate redundant data transfer for repeated query responses.

Recommendation Add httputil.ETag(etag.DefaultETagConfig()) to the middleware chain in examples that serve query responses. Document the ordering constraint: ETag must be inside (after) Compression.
Missed Opportunity · Medium impact

Decompression middleware (v0.9.0) unused — no bomb protection for compressed request bodies

Not used anywhere · httputil/decompression.go (unused)

httputil’s Decompression middleware transparently decompresses gzip/deflate request bodies based on Content-Encoding, with built-in bomb protection (MaxDecompressionSize, default 16 MiB). cqrs-htmx’s decoder.go uses io.LimitReader for body size, but this does not handle decompression bomb attacks — a 1 KB gzipped body can decompress to gigabytes, and the LimitReader sees the compressed stream.

Recommendation Document httputil.Decompression(httputil.DefaultDecompressionConfig()) in the leveraging-httputil guide as a security hardening step for endpoints that accept compressed bodies.

httputil provides a MetricsRecorder interface and Metrics(cfg) middleware that records method, path, status, and duration per request. This is a clean plug-in point for Prometheus, OpenTelemetry, or any custom metrics backend. No example or integration shows how to wire it.

Missed Opportunity · Medium impact

RegisterErrorClassifications() never called — httputil error codes won’t classify through MapError

Not called anywhere · httputil/errors.go (RegisterErrorClassifications)

httputil classifies its internal errors (write failures, hijack failures, compression failures) with behavioral families via go-error-family. RegisterErrorClassifications() registers stdlib HTTP error sentinels and error message templates so they classify through cqrshtmx.MapError via errorfamily.Classify. Without this call, http.write_failed, http.compress_write_failed, http.hijack_unsupported, and http.hijack_failed won’t get proper error family classification — they’ll fall through to the default 500 instead of being classified as Transient (retryable) or Infrastructure.

Recommendation Call httputil.RegisterErrorClassifications() once at startup in App initialization (or document it as a consumer responsibility in the leveraging-httputil guide).
Missed Opportunity · Low impact

MiddlewareStack unused — examples use bare Chain without validation

Not used anywhere · httputil/stack.go (unused) · cqrs-htmx uses its own Chain

httputil.NewMiddlewareStack() provides a named, validated middleware stack builder: it enforces “Recovery outermost”, rejects duplicate names, and validates the stack before building. cqrshtmx.Chain is a bare composition helper with no validation. Examples that compose 6+ middleware would benefit from the safety guarantees.

Recommendation Not urgent — cqrshtmx.Chain works fine for library code. Consider demonstrating MiddlewareStack in one example as a “safer alternative” pattern.
Missed Opportunity · Low impact

Health handlers duplicated — cqrs-htmx hand-rolls what httputil provides

app.go:411-425 (HealthHandler) · readiness.go:1-136 (ReadinessHandler, NamedCheck, DebugHandler) · dashboardui/handlers_health.go:1-80 · httputil/health.go (unused)

cqrs-htmx hand-rolls HealthHandler() (checks dispatcher availability), ReadinessHandler (parallel health checks with JSON response, 136 lines), and DebugHandler. dashboardui hand-rolls healthzHandler, readyzHandler, and versionzHandler. httputil provides HealthHandler(), LiveHandler(), ReadyHandler(), ReadyHandlerWithProbe(func() bool), and RegisterHealth(mux) (mounts /health, /health/live, /health/ready in one call).

The hand-rolled version is partially justified — cqrs-htmx’s HealthHandler checks dispatcher availability (domain-aware). But ReadyHandlerWithProbe could replace the simpler readiness checks, and RegisterHealth would standardize the endpoint paths.

Recommendation Use httputil.RegisterHealth(mux) for the standard liveness/readiness endpoints. Keep cqrs-htmx’s domain-aware HealthHandler for the dispatcher-availability check, but compose it as the probe function: httputil.ReadyHandlerWithProbe(func() bool { return app.HasDispatchers() }).
Missed Opportunity · Low impact

MaxBodySize middleware unused — decoder.go hand-rolls inline LimitReader

decoder.go:59-68 (readBody with io.LimitReader) · httputil/maxbodysize.go (unused)

cqrs-htmx’s decoder.go reads request bodies with io.ReadAll(io.LimitReader(r.Body, maxBodySize+1)) — a hand-rolled body size limit. httputil’s MaxBodySize(maxBytes) provides middleware-level enforcement that rejects oversized bodies before they reach the decoder (immediate 413), with MaxBodySizeConfig.Validate() and DefaultMaxBodySizeConfig() (1 MiB default).

The current approach is partially justified — the per-handler WithMaxBodySize(n) option needs inline limiting, not middleware. But a middleware-level guard as a safety net (rejecting oversized bodies before any processing) would be defense-in-depth.

Recommendation Document httputil.MaxBodySize(1 << 20) as a recommended outer middleware guard in the leveraging-httputil guide. Keep the per-handler WithMaxBodySize for fine-grained control.
Missed Opportunity · Low impact

RequestID middleware unused — ContextEnrichmentMiddleware hand-rolls 40+ lines of ID logic

middleware.go:18-63 (ContextEnrichmentMiddleware) · httputil/requestid.go (unused)

cqrs-htmx’s ContextEnrichmentMiddleware extracts X-Request-ID, parses or generates a ULID, stores it in context, and writes it back to the response header — 40+ lines. httputil’s RequestID(cfg) provides the same with RequestIDConfig.GenerateID for custom ID generation, RequestIDConfig.IncomingHeader / ResponseHeader for configurable header names, and RequestIDFromContext.

The hand-rolled version is partially justified — it also handles correlation IDs and user ID extraction in the same middleware, which httputil.RequestID does not. But the request ID portion could delegate to httputil and compose the correlation/user logic on top.

Recommendation Low priority — the current implementation works and is domain-aware. Consider delegating the request ID generation to httputil.RequestID with GenerateID: func() string { return NewRequestID().String() } in a future refactor, composing correlation/user ID extraction on top.

Not Applicable (Intentionally Hand-Rolled)

These features are hand-rolled in cqrs-htmx for good reason — the hand-rolled version is domain-aware and strictly richer than the httputil equivalent. Switching to httputil would lose functionality.

Feature cqrs-htmx version Why httputil’s is weaker
Recovery RecoveryMiddleware — errorfamily integration, dispatch error handler, request ID recovery from response headers httputil.Recovery just logs + 500; no errorfamily, no dispatch error handler
Logging RequestLoggingSlog — captures dispatch errors, request/correlation/user IDs httputil.Logging only logs method/path/status/duration/clientIP
ResponseRecorder StatusRecorder — embeds ErrorRecorder for dispatch error capture httputil.ResponseRecorder captures status only
Chain cqrshtmx.Chain — same signature, same behavior Identical; no benefit to switching
Timeout App.timeout — per-dispatch (CQRS-level) timeout httputil.Timeout is per-request; different concern (use both)

Conclusion

cqrs-htmx is on the latest httputil v0.11.0 and has solid adoption of the four features it migrated (CSRF, security headers, production server, Server-Timing). The duck-typing philosophy of not re-exporting everyday HTTP middleware is sound for a library. However, the project misses nearly every advanced middleware feature added in v0.9.0-v0.11.0 (Nonce, Compression, CORS, ETag, Decompression, Metrics), hand-rolls a weaker nonce system in adminui, and has three compiler-breaking references that prevent go test ./... from passing. The single highest-leverage next step is fixing the broken references (5-minute fix, unblocks the test suite), followed by calling RegisterErrorClassifications() and adopting httputil.Nonce in adminui.
