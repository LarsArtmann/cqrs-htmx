00Summary

DataStar’s client has matured exactly into what ADR-0045 bet on in August: a stable (v1.0.0, April 2026; now v1.0.4), zero-dependency, ES2021 hypermedia runtime whose defaults — SSE-first transport, backend as source of truth, server-morphed DOM, no optimistic updates — mirror this library’s CQRS/event-sourcing posture. The server-side story here is already excellent and current: the datastar/v4 adapter, the upstream go-datastar patches-as-values SDK (pinned at its latest tag), the shared-hub dual transport, and the one-flag setup.DataStarPath mount. The client-side story is where the gap is: the repo ships ~1,975 lines of hand-rolled client JS across four surfaces (sync-client, sync-worker, dashboardJS, admin.js) doing work DataStar’s signal and fetch machinery now does declaratively — and the one shipped DataStar example is broken in a real browser (verified below), silently, because nothing exercises the client at all.

The highest-value improvements are small and ungated: fix the demo’s dead data-on:load attributes (an RC.6 rename trap), add one browser-level Playwright spec to the e2e battery, and ride the bundle to v1.0.4. The larger moves stay correctly parked behind ADR-0050’s demand gate — this report supplies the client-side fact base those parked milestones (M11–M16) were waiting on, without reopening the gate.

The bottom line Adopt-by-fixing, not adopt-by-building: repair the demo, browser-test the one real DataStar surface we ship, keep the bundle current, and let the parked panel variants stay parked. DataStar complements the sync assets — it cannot replace IndexedDB persistence, and ADR-0050’s route-split Model A remains the right strategy.

◆What already fits

Before the gap analysis: the alignment between DataStar’s client design and this library’s architecture is real, documented upstream, and shipped here in the right shape.

+
Philosophy is a mirror of the CQRS posture The Tao of Datastar names backend-as-source-of-truth, SSE as default transport, and no optimistic updates as first principles — the same three laws ADR-0056 wrote for frontend sync (“clients sync intent, never facts”). Nothing in the client fights the decider-owns-truth model.
+
SSE is native, not an extension Any @get/@post/… action whose response is text/event-stream becomes a long-lived stream with built-in exponential-backoff retry, last-event-id replay header, and visibility-aware reconnects. That is precisely the reconnect/replay contract broadcast.Broadcaster serves — the two halves were built for each other (ADR-0049’s shared hub proves it).
+
The server-side adapter is current and correct go-datastar v0.6.3 is the latest tag (repo pushed 2026-11-07); the embedded v1.0.3 bundle carries the wire-format goldens; the adapter’s EventBridge, Response builder, and deprecated-alias discipline match the repo’s v5 posture.
+
Self-hosting posture is right The SDK embeds the client bundle verbatim from the upstream release tag and serves it with ETag + 1-year immutable caching. Upstream’s npm package is frozen at 1.0.0-beta.11 and never published a stable — the CDN-or-self-host choice this repo already made is the only reliable one.
+
The strategic frame already exists ADR-0045 (optional module), ADR-0049 (layer split), ADR-0050 (route-split Model A; dual-mode rejected; panel variants demand-gated). This report changes none of those decisions — it feeds them.

01The client, studied

Everything in this section is verified against the v1.0.4 source tree and the data-star.dev reference unless marked otherwise. Sizes for the embedded v1.0.3 bundle were measured locally (gzip -c | wc -c).

Release status

v1.0.0 stable shipped 2026-04-16 after a beta/RC year; v1.0.4 (2026-09-21) is current. Browser floor: ES2021 (Chrome/Edge 93+, Firefox 91+, Safari 15.4+). Five bundles ship per release: datastar.js (33,553 B, ~13.1 KiB gzipped), datastar-core.js (signals-only, 10,480 B), datastar-rocket.js (web components), and *-aliased variants using the legacy data-star-* prefix. Zero dependencies; TypeScript; the morph engine is purpose-built (Idiomorph was dropped during the RCs).

Signals — the client state model

One global signal tree addressed by dot paths. data-signals declares or patches it (data-signals:foo.bar="1", object syntax allowed); setting null removes a signal; __ifmissing sets defaults only. Signals starting with _ are local and never sent to the backend. data-bind is two-way binding with type preservation (predefine 0 and a select yields numbers; file inputs encode to base64 {name, contents, mime} signals). data-computed derives memoized read-only signals; data-effect runs side effects on change. Reactivity is alien-signals-derived and fine-grained: only dependents of a changed signal re-run — there is no vdom.

Crucially for this repo: all signals ride every backend request (JSON body, or the datastar query param on GET/DELETE, plus a Datastar-Request: true header) — the client ships its whole state to the decider each time — and server patches flow back with RFC 7396 JSON Merge Patch semantics. That is the ADR-0056 “sync intent, never facts” law expressed as a wire default.

Expressions and CSP

Attribute values are JavaScript with DataStar namespacing: $foo reads a signal, @post(...) calls an action; el and evt are in scope. The default evaluator compiles expressions via the Function() constructor — strict CSP therefore requires the opt-in CSP mode added in v1.0.3: a data-nonce attribute on <html> makes DataStar compile expressions into nonce’d script tags, with Trusted Types support (policy name datastar). The embedded v1.0.3 already has this mode. This matters here: the repo’s RecommendedSecurityMiddleware is nonce-per-request CSP, and dashboardui spent a whole migration purging inline JS — any panel adoption must document the data-nonce contract or it will look broken under the default security posture.

The attribute vocabulary (free tier)

Backend actions and the SSE contract

There is no @sse() any more (removed in 2025’s beta.1). Every backend action — @get @post @put @patch @delete, plus v1.0.4’s @query() (HTTP QUERY) — is SSE-capable: if the response is text/event-stream, the fetch becomes a stream. Options: contentType json|form (form validates and uses the closest form), headers, filterSignals, retry (auto/error/always/never) with 1 s interval ×2 scaler, 30 s cap, 10 attempts, requestCancellation auto|cleanup|disabled (same method+URL aborts the prior in-flight request), and openWhenHidden (GET streams close on tab-hide and reopen on visibility, resending full state). Reconnects resend current signals and carry the last SSE id: as a last-event-id header — exactly what broadcast.NewBroadcasterWithReplay and transport.NewJournalSSEStore answer server-side.

Every action also emits datastar-fetch DOM events (started/finished/error/retrying/retries-failed) — retry observability without writing a line of JS.

The wire protocol (what the Go side emits)

# element patch — event names, data lines, key-value with repeated-key joining
event: datastar-patch-elements
data: selector #todo-list
data: mode inner          # default outer = morph; also replace/prepend/append/before/after/remove
data: elements <li class="empty-state">No todos yet</li>

# signal patch — RFC 7396 JSON Merge Patch; null removes; onlyIfMissing for defaults
event: datastar-patch-signals
data: signals {"notification":{"level":"err","message":"conflict"}}

# non-SSE responses are dispatched by content type:
# text/html → patch elements (datastar-selector/-mode response headers)
# application/json → patch signals · text/javascript → execute · 204 → no-op

The client processes only SSE events whose name starts with datastar; default element targeting matches top-level elements by ID (put IDs on elements whose state should survive a morph). Script execution over SSE is an elements patch with mode append, selector body — the old datastar-execute-script event is gone (the Go helpers still emit the equivalent patch).

Plugins, Rocket, Pro

Everything except signals is a plugin (attributes, actions, watchers; apply/load/setAlias exports, ~250-line core engine). Rocket (web components, scoped signals) went free in v1.0.4, still beta. DataStar Pro is commercial ($349 solo / $1,299 team, lifetime): data-persist (the only signal-persistence story), data-query-string, data-animate, data-custom-validity, @clipboard() and friends live behind it. Every recommendation in this report is deliberately free-tier-only.

02Where cqrs-htmx stands

The shipped server surface (current)

The datastar/v4 adapter is thin by design (ADR-0045): ScriptHandler/ScriptTag (embedded bundle, ETag), ReadSignals, the patch constructors (ElementsPatch/SignalsPatch/RemovePatch/ScriptPatch/RedirectPatch …), the fluent Response builder, and the domain-coupled EventBridge (go-cqrs-lite events → patches, with OnError). Fan-out/replay/hub-sharing live upstream in go-datastar/broadcast (ADR-0049). setup.DataStarPath mounts a session-gated feed on the same hub as /sse plus the script, in one flag (ADR-0050). All verified green in this tree.

The shipped client surface (thin — and one defect)

Exactly one HTML surface speaks DataStar today: examples/datastar-demo (signals, two-way bind, computed notification state, indicator flags, SSE patch feeds, a 10-bot multi-user simulation). Its Go handlers are correct — but see finding 1: its bootstrap attributes never fire in a real browser.

04Findings

Ordered by impact. Finding 1 is verified empirically, not inferred.

Blocking · Verified empirically

The DataStar demo never boots its UI in a real browser

examples/datastar-demo/main.go:291,322 · the RC.6 rename trap

The demo drives its initial load and its SSE subscription with data-on:load on a <ul> and a <div>. Under the embedded DataStar v1.0.3 that attribute binds the DOM load event — which never fires on those elements. The correct post-RC.6 attribute is data-init (data-on-load was renamed in RC.6, and the colon form data-on:load is the event-binding attribute, not the init hook). Result: no initial todo list, no live event stream — the demo looks alive only because its Go handlers are exercised by an HTTP-level smoke test that never runs the client.

Verification (headless Chromium, 2026-11-07): dumping the live demo’s DOM after an 8 s virtual-time budget leaves #todo-list and #stats empty; the identical page with data-on:load → data-init swapped (served same-origin through a proxy) populates both — the empty-state <li> lands in #todo-list and Total: 0 renders in #stats. The server’s patch stream is byte-identical in both runs; only the trigger differs. 

<!-- shipped: load event on a ul — never fires -->
<ul id="todo-list" data-on:load="@get('/api/todos')"></ul>

<!-- correct since RC.6: expression runs when the element enters the DOM -->
<ul id="todo-list" data-init="@get('/api/todos')"></ul>
Fix Two attribute swaps in examples/datastar-demo/main.go (plus the HTML comment), then add the guard that was missing: one Playwright spec in the e2e battery that opens the demo and asserts the list populates — the repo already runs Playwright; this is the first spec with a DataStar page in it (finding 2).
Important · Structural

Zero browser-level coverage on every DataStar surface

e2e/tests/*.spec.ts · datastar module, examples/datastar-demo

The e2e battery covers admin, dashboard, loginpage, and the sync worker (deeply — IndexedDB inspected from Playwright). Nothing executes DataStar client behavior; datastar_demo_test.go is HTTP-smoke only, and go-datastar/datastartest (correctly used here) is wire-format assertions, not a browser. Finding 1 survived every gate for exactly this reason — and will recur on any future adoption (signals wiring, CSP-mode interactions, morph edge cases are all browser-only behaviors). Upstream has the same blind spot (headless E2E is on go-datastar’s ROADMAP, not shipped).

Fix One datastar.spec.ts asserting three behaviors: list populates on load, a POST round-trips a patch, and the SSE feed updates a second tab. The F1 verification spec for this report is 90% of the work already.
Important · Chore

Embedded client is one patch release behind

go-datastar/static v0.6.1 · upstream v1.0.4

v1.0.4 (2026-09-21) adds @query() and frees Rocket, and the go-datastar repo already carries the v1.0.4 bundle on master — it is waiting on a static-module tag. The upgrade ritual is documented upstream (replace the file, bump static.Version, run the wire-format goldens) and the treadmill gate will surface the tag. Nothing in this repo depends on v1.0.4 behavior; this is currency hygiene, not urgency.

Nice to have · Docs

Stale size claims and a historical SDK attribution

docs/guides/datastar-integration.md, docs/guides/sse-and-datastar.md, docs/adr/0045

Both guides say “11.76 KiB”; the embedded v1.0.3 measures 13.07 KiB gzipped (33,538 B raw). ADR-0045 says the adapter “wraps the datastar-go SDK” — doubly historical now: go-datastar is a from-scratch reimplementation, and the official SDK it referenced has itself moved repos (starfederation/datastar-go). Two-line truthing on the next docs pass.

Nice to have · Latent

CSP contract is undocumented for adopters

future guide section · datastar-integration.md

DataStar’s default expression evaluator needs unsafe-eval; the nonce-mode alternative (v1.0.3+, data-nonce on <html>) is the only posture compatible with RecommendedSecurityMiddleware’s per-request nonce CSP. Any consumer who mounts the adapter under the default security middleware without that contract gets a silently dead page — the finding-1 class again, but self-inflicted by configuration. A short “CSP” section in the integration guide (mirroring the sync guide’s CSP section) closes it.

05What DataStar can improve client-side — ranked

Each item states what changes, what it costs, and which gate applies. Items 1–3 are ungated (defect/chore/docs); items 4–6 feed the parked ADR-0050 Tier-4 milestones (M11–M16, demand-gated; W17 verdict 2026-10-25: stays parked) without reopening them.

1

Fix the demo + browser-guard it ungated · defect

The two data-init swaps and one e2e spec (findings 1–2). ~1 h, and the only DataStar page we ship becomes actually demonstrable. This is the single highest-value action in the report.

2

Ride the bundle to v1.0.4 ungated · chore

When go-datastar tags static past v0.6.1: bump, run wire goldens, done. The treadmill gate tracks it; no repo code changes.

3

True the docs + write the CSP contract ungated · docs

Fix the KiB claims, annotate ADR-0045’s SDK attribution, add the data-nonce CSP section (findings 4–5). ~30 min.

4

Signals as an optional status/indicator layer over the sync assets feeds M14 evidence

The sync worker stays (it is the ADR-0056 asset; DataStar has no free persistence). But the presentation layer around it — data-sync-status DOM mutation, announce() toasts, per-command row states — maps one-to-one onto data-signals-sync.status + data-bind + data-on-signal-patch with a filter. Ship it as a documented variant recipe in the sync guide (the worker already broadcasts plain DOM events; a 20-line shim translating them into signal patches is the whole bridge), not as a second blessed asset. That is exactly the M14 evaluation’s missing half, answered without replacing anything.

5

dashboardui signal-patch spike (M11) demand-gated

The parked spike — projection health as SignalsPatch, payload comparison vs HTMX polling — is now cheap to run: the client facts are in section 01 (JSON signal patches vs HTML fragment patches; ID-based morph preservation; view-transition support), and dashboardJS’s ~85-line SSE client is the concrete deletion target. Honest trade-off to measure: signals shrink payloads but move formatting to the client; elements patches keep templ’s XSS-safe server rendering. The spike’s go/no-go question is unchanged — this report is its evidence pack, and the demand gate still decides.

6

loginpage signal forms (M13) demand-gated

Client-side validation via data-bind + data-computed (free tier) with server round-trip on submit — but loginpage’s zero-datastar-dependency posture and CSP hooks (finding 5) make this a real variant module, not a patch. Stays parked with the rest of Tier 4.

What DataStar deliberately cannot improve here The sync worker’s IndexedDB queue, cursor monotonicity, and conflict outcomes (ADR-0056’s laws have no DataStar equivalent — signal persistence is Pro-only and there is no SharedWorker story). Dual-mode handlers stay rejected (ADR-0050 Model B: the two render functions are not derivable from each other). And adminui’s 100-line companion JS is not worth a rewrite at any gate.
