The Three Transports

Each transport has distinct capabilities and limitations. A complete HTMX-aware CQRS library must speak each one fluently — pushing events, accepting commands, reporting errors, and surviving disconnection — using the right tool for each direction.

HTTP — the contract

Every interaction begins and ends here. Request body carries commands and queries; response body carries results. Status codes encode outcomes; MapError already maps CQRS error families to HTTP statuses. This is the baseline the other transports must match in expressive power, not duplicate.

SSE — the push

Pure server-to-client stream built on HTTP. The browser handles reconnection and replays Last-Event-ID automatically. Perfect for broadcasting domain events, live updates, and progress. Cannot receive commands from the client — by spec.

WebSocket — the channel

Bidirectional, persistent, lowest latency. The only transport that can carry commands and push events without polling. Comes with connection lifecycle, framing, ping/pong, and reconnection complexity that must be surfaced explicitly.

The Full Landscape

HTTP, SSE, and WebSocket are the three core transports this library targets — but the web offers more. This catalogues every other browser-native communication technology plus the server-to-server options, with a verdict on whether each belongs in cqrs-htmx. Items marked In scope are candidates for future matrix columns; the rest are documented so the exclusion is a decision, not an oversight.

How this maps to the matrix

WebTransport and Fetch Streaming are the legitimate candidates to become 4th and 5th matrix columns — they extend the live-transport story with QUIC datagrams and true bidirectional HTTP/2 streaming respectively. Web Push is a distinct capability (reach-the-closed-tab) that no current transport provides. gRPC-Web and Webhooks serve a different audience (S2S / typed RPC) and are documented here for completeness, not for inclusion in the HTMX transport matrix.

⚠ Critical: SSE silently swallows errors

North Star

A consumer of cqrs-htmx should be able to swap transports without rewriting their CQRS handlers. The same command struct flows in via HTTP body, SSE-bridged POST, or WS frame; the same event struct flows out as HTTP response, SSE event, or WS message — with errors carried consistently by the same structured payload type.

Critical Gaps

The four holes that prevent cqrs-htmx from claiming "full transport coverage." Ranked by blast radius — every consumer hits them.

1. SSE Error Channel

Critical

No BroadcastOnError / BroadcastOnErrorFunc. Failed commands produce zero feedback to subscribed clients. Forces consumers into HTTP polling for error feedback, defeating the point of SSE.

0% implemented · ~20 min of work · unblocks the entire error-reporting story

2. SSE Heartbeat

High

No comment-frame ping. Nginx, Cloudflare, AWS ALB, and corporate proxies kill idle SSE connections after 30–60s of silence. Production deployments will break without this — and the failure mode is silent (client thinks it's connected).

0% implemented · ~15 min · SSEStream.Heartbeat(ctx, interval)

3. WS Outbound Encoder

High

Only ParseWSMessage (inbound) exists. No WriteWSMessage[T], no WSBroadcaster, no equivalent of SSEStream.Send. Without this, WS cannot push domain events back to the client at all.

WSOOBHTML is the only encoder · ~45 min for full encoder + broadcaster

4. WS Dispatch Bridge

Medium

No WSDispatchHandler(app). The parser exists but doesn't wire into the CQRS dispatcher. Consumers must hand-roll the bridge. This is what would make WS a first-class transport instead of a parser library.

Parser exists (25%) · ~90 min for dispatch + query routing + error framing

Pareto-Ordered Roadmap

80% of the value in 20% of the work. Items 1–2 close the SSE error/keepalive story in under an hour combined. Items 3–4 lift WebSocket to parity with SSE. Item 5 unifies the error vocabulary across all transports.

1

BroadcastOnError / BroadcastOnErrorFunc

Symmetric to BroadcastOnSuccess. Fires when err != nil. Carries structured error payload (RFC 7807 shape). Closes the largest hole in the real-time story: SSE clients finally learn when commands fail.

Critical ~20 min
2

SSEStream.Heartbeat(ctx, interval)

Sends SSE comment-frame pings (: keepalive\n\n) on a ticker. Default 15s. Stops on ctx.Done(). Without this, reverse proxies and corporate firewalls silently sever SSE connections after 30–60s of idle.

High ~15 min
3

WSMessage encoder + WSBroadcaster

WriteWSMessage[T] / WriteWSMessageInto[T] symmetric to the parser. A WSBroadcaster mirror of the SSE Broadcaster for fan-out to multiple connected clients. Unlocks push events over WebSocket.

High ~45 min
4

WSDispatchHandler(app)

Bridge incoming WS → CQRS dispatcher. Routes by message shape (command vs query), dispatches, and frames the response — success or error — back over the same socket. Makes WebSocket a first-class transport.

Medium ~90 min
5

Structured error payload type (SSEError / WSError)

RFC 7807-shaped type (Type, Title, Status, Detail) used uniformly across HTTP, SSE, and WS error responses. Lets clients render and handle errors consistently regardless of transport.

Low ~30 min
Total estimated effort

~3.5 hours of focused implementation to take cqrs-htmx from "HTTP complete, SSE partial, WS receive-only" to full transport parity with consistent error reporting across all three.

Proposed Payload Contracts

Concrete shapes for the new APIs. RFC 7807 alignment for errors so client code can be transport-agnostic.

Structured Error Payload

Used by BroadcastOnError, WSError frames, and optionally HTTP error bodies. Shape follows RFC 7807.

// Transport-agnostic structured error. Serialized as JSON for SSE data / WS payload. type StructuredError { Type string // URI or token: "about:blank", "https://errors/rejection" Title string // Short human-readable summary Status int // HTTP status code (carries family semantics) Detail string // Specific explanation of this occurrence Instance string // Request ID / correlation ID for tracing }

SSE Error Hook Signatures

// Symmetric to BroadcastOnSuccess. Fires when err != nil. func (b *Broadcaster) BroadcastOnError(eventName string, errPayload StructuredError) AfterDispatchHook func (b *Broadcaster) BroadcastOnErrorFunc(errFunc func(r *http.Request, err error) SSEEvent) AfterDispatchHook

SSE Heartbeat

// Sends SSE comment-frame pings on a ticker until ctx is cancelled. // Safe to run in a goroutine alongside stream.Send. func (s *SSEStream) Heartbeat(ctx context.Context, interval time.Duration)

WebSocket Encoder + Broadcaster

// Symmetric to ParseWSMessage. Writes an HTMX-shaped WS message. func WriteWSMessage[T any](w io.Writer, msg T) error // Fan-out for WS clients, mirroring SSE Broadcaster. type WSBroadcaster struct{ /* ... */ } func NewWSBroadcaster() *WSBroadcaster func (b *WSBroadcaster) Subscribe() <-chan WSMessage func (b *WSBroadcaster) Broadcast(msg WSMessage)

WS Dispatch Bridge

// Wire incoming WS messages into the CQRS dispatcher. // Consumers call this from their WS library's OnMessage callback. func WSDispatchHandler(app *App) func(data []byte) WSMessage
