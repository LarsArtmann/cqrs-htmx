00Summary

This audit covers every module in the 27-module cqrs-htmx workspace that imports github.com/larsartmann/httputil (47 files), github.com/larsartmann/go-sse (37 files), or github.com/larsartmann/go-etag (1 file). Capabilities were verified against each library's own FEATURES.md, CHANGELOG.md, and source at the local trees; version currency was verified against the pushed git tags on 2026-09-17.

httputil is deeply and correctly adopted — the CSRF, keyed-rate-limit, security-header, nonce, server, and health suites are all in production use, and cqrs-htmx even runs httputil's 18 HTTP-spec compliance checks as its own test (httpspec_compliance_test.go). It is one minor version behind. go-sse is adopted down to its advanced surface (predicate push-down replay via ReplayFiltered + FilteredEventStore, hub embedding, heartbeats with cancellable contexts) but leaves its graceful-shutdown drain and reconnect-backoff hint unused. go-etag is effectively unused while the project hand-rolls its core feature five times.

The bottom line cqrs-htmx hand-rolls ETag generation and If-None-Match handling in 5 production sites (≈60 lines) while its sibling library go-etag exists precisely to do this — and the hand-rolled exact-string comparison silently mishandles the RFC 7232 cases (*, validator lists, weak W/ tags), turning valid conditional requests into full-body 200s. One library call per site fixes both the duplication and the correctness gap.

02Findings — go-etag (adoption 25/100)

Missed Opportunity · High impact

Five hand-rolled ETag/conditional-GET sites duplicate go-etag's core feature

event_catalog_handler.go:72-84 · options_openapi.go:66 · htmx_serve.go:44-46 · sync_serve.go:25,51 · projection_status_handler.go:64-70

go-etag's server package exists to "generate entity-tags and answer If-None-Match with 304 Not Modified" (go-etag README). cqrs-htmx implements this by hand in five places: the shared serveImmutableJSON (behind EventCatalogHandler and OpenAPISpecHandler), the HTMX script handler, both sync-worker handlers, and the projection-status handler — plus a hand-written inline FNV-1a-64 in hashTag ("implemented inline rather than hash/fnv to avoid the hash.Hash.Write" overhead). go-etag gives all of this away: body-buffering ETag generation (FNV-64a default), RFC 7232 weak comparison, HEAD/Content-Length compliance, 304 Content-Length stripping, SkipIfPresent for handler-set strong tags, and a Skip route predicate. Adopting it deletes ≈60 lines of duplicated logic across 5 files and makes the sibling family the single owner of conditional-request semantics.

Recommendation For the immutable-bytes handlers, keep the eager precomputed tag (it is better than per-response hashing) and delegate only the conditional check. For the dynamic projection-status handler, use the middleware outright. 
import etag "github.com/larsartmann/go-etag/server"

// immutable handlers: keep eager tag, swap the check (event_catalog_handler.go:77)
tag, ok := etag.ParseETag(etagStr) // parses "…" incl. W/ form
if ok && etag.MatchesIfNoneMatch(tag, r.Header.Get("If-None-Match")) {
    w.WriteHeader(http.StatusNotModified)
    return
}

// dynamic handler (projection_status_handler.go): middleware does everything
cfg := etag.DefaultETagConfig()
cfg.SkipIfPresent = true // handler may still pin its own strong tag
statusHandler = etag.New(cfg)(statusHandler)
Misused / Anti-Pattern · Correctness

Hand-rolled If-None-Match check is spec-incomplete (exact-string comparison)

event_catalog_handler.go:77 · htmx_serve.go:46 · sync_serve.go · projection_status_handler.go:70

All four copies evaluate match == etag on the raw header string. RFC 7232 §3.2 allows If-None-Match: *, comma-separated validator lists (If-None-Match: "a", "b" — what layered proxies and some CDNs send), and weak validators (W/"abc", which must match a strong tag under weak comparison). Each of these silently fails the exact-string check, so the client receives a full 200 body instead of a 304. No data is corrupted — but the cache layer quietly stops working for exactly the clients that need it most, and go-etag ships fuzz-tested parsing for precisely these cases (server/entity_tag.go: ParseETagList honors quoted commas and escapes; MatchesIfNoneMatch handles the wildcard; BDD-pinned in etag_bdd_test.go).

Recommendation Same one-call fix as above — etag.MatchesIfNoneMatch is a drop-in replacement for the four string comparisons, with the RFC corner cases already fuzz- and spec-pinned upstream.
Missed Opportunity · Medium impact

go-etag/client (conditional GET transport) unused anywhere

not used anywhere · capability: go-etag/client (v0.2.0+, RFC 9111-conformant)

The client package turns any http.Client into a caching client: it replays stored validators as If-None-Match, rebuilds 304s as 200s, freshens per RFC 9111 §4.3.4, invalidates after unsafe methods, and bounds memory (MaxEntries, MaxBodyBytes). cqrs-htmx consumers poll dashboard JSON endpoints (projection status, event catalog) that are purpose-built for conditional GETs — a documented recipe showing etagclient.NewTransport against /health and the catalog would hand every Go consumer free bandwidth savings. The e2e and integration suites, which repeatedly fetch these endpoints, could adopt it too.

Recommendation Add a recipe to docs/guides/leveraging-httputil.md (or the catalog guide) and use the transport in one integration test as the executable proof.
Partially Used · Low impact

ETag observability hooks ignored — no cache-hit visibility

not used anywhere · capability: ETagConfig.OnETagGenerated / On304 / OnBufferOverflow (go-etag v0.2.0)

go-etag's hooks exist to derive cache-hit ratios ("pairs with On304 to derive cache hit ratios" — go-etag CHANGELOG v0.2.0). Once the middleware guards the catalog/status endpoints, wiring On304 into the existing log/metrics path would answer "how much traffic do the immutable endpoints actually save" with one function literal. Low priority because it only becomes relevant after the adoption above.

03Findings — go-sse (adoption 80/100)

Fully Leveraged

Advanced replay surface in production: predicate push-down + hub embedding

transport/serve.go:49,102 · sse_broadcaster.go:75 · datastar/broadcaster.go:16,46,131

Most projects stop at Replay. cqrs-htmx implements the FilteredEventStore interface with a custom adapter and serves filtered streams via ReplayFiltered (predicate push-down to the store), embeds the hub in both adapters per the go-sse canonical vocabulary, and exposes buffer tuning through WithBufferSize. This is the capability most consumers never find — here it is load-bearing.

Missed Opportunity · Medium impact

Graceful Shutdown(ctx) drain never used — Bundle.Close abrupt-closes the hub

setup/bundle.go:166 · capability: Broadcaster.Shutdown(ctx) drain with deadline (go-sse FEATURES, "Graceful Shutdown")

go-sse's Shutdown(ctx) drains all subscribers with a deadline, rejects new subscribers while draining, and is idempotent — it is the library's answer to "server is shutting down while 500 dashboard tabs hold open SSE connections". cqrs-htmx calls b.Broadcaster.Close() instead, which closes subscriber channels immediately: in-flight events are dropped and clients see an abrupt stream end rather than a final event + clean close. The method is already promoted on both adapters (documented in docs/guides/sse-and-datastar.md:15) — it is one call away in the exact place shutdown ordering is already handled.

Recommendation 
// setup/bundle.go Close(): drain before close
ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
defer cancel()
if err := b.Broadcaster.Shutdown(ctx); err != nil {
    b.Logger.Warn("sse drain incomplete", "err", err)
}
Missed Opportunity · Medium impact · trivial effort

retry: reconnect hint never sent to browsers

transport/serve.go, sse_broadcaster.go — no WriteRetry anywhere · capability: WriteRetry (go-sse event.go:213) + reconnection guide layer 2

go-sse ships WriteRetry(w io.Writer, ms uint) and its own reconnection guide ranks the retry: hint as layer 2 of the 5-layer reconnection model (go-sse/docs/guides/reconnection-and-retry.md, shipped in v0.6.0). cqrs-htmx's SSE endpoints send event: connected and heartbeats but no retry hint, so browsers fall back to their default ≈3s reconnect cadence — a restart of the server produces a synchronized stampede of reconnects from every connected dashboard. One line after NewStream sets a deliberate, jitter-friendly backoff.

Recommendation 
// transport/serve.go, right after NewStream:
_ = sse.WriteRetry(w, 5000) // milliseconds; browsers honor it per-connection
Partially Used · Medium impact

Hub observability documented as a recipe but wired nowhere

docs/guides/sse-and-datastar.md:200-207 (recipe) · zero production OnSubscribe/OnUnsubscribe/Health wiring · capability: fanOut hooks + BroadcasterHealth

cqrs-htmx's own guide contains the recipe ("hub.OnSubscribe(fn) → connected-clients gauge") and immediately concedes "the SSE push path emits no spans or metrics of its own". Meanwhile go-sse provides Health() (subscriber counts, buffer sizes, drop counts) and the subscribe/unsubscribe hooks; only datastar reads SubscriberCount today (datastar/broadcaster.go:131). dashboardui — the observability dashboard — shows projection health but nothing about the SSE hub its live updates depend on. The data is one promoted method call away.

Recommendation Add an "SSE hub" card to dashboardui backed by broadcaster.Health(), and register OnSubscribe/OnUnsubscribe gauges in setup's optional observability path.
Partially Used · Low impact

ssetest.RequireDataJSON unused — tests hand-unmarshal event payloads

12 × ssetest.Event assertions in SSE tests · capability: RequireDataJSON(tb, evt, want) (ssetest v0.3.0)

ssetest v0.3.0 added RequireDataJSON: structural JSON compare (key-order and whitespace insensitive), type inferred from want, fatal-with-payload on invalid JSON. The SSE suites still unmarshal payloads by hand before comparing, which produces worse failure messages and more test code. Small DX win, zero risk.

Not Applicable (justified non-use)

SendJSON / SendLines / SendKeyed conveniences — correctly skipped

transport/serve.go:165,196 · sse_broadcaster.go:164,175

cqrs-htmx events carry a named event plus a JSON envelope (Event: name, Data: json). SendJSON sends with an empty event name and SendLines/SendKeyed target key-value protocols, so raw stream.Send with a marshaled envelope is the correct call here. Honest non-use — not a gap.

07Conclusion

httputil and go-sse are used the way their author intended — deeply, on current APIs, with the advanced surfaces (compliance-test embedding, filtered replay, hub embedding) actually load-bearing. go-etag is the exception: one demo call site while five production sites hand-roll the library's core feature, one copy spec-incompletely. The single highest-leverage change is mechanical: swap the four string comparisons for etag.MatchesIfNoneMatch and let the middleware own the dynamic handler. That plus a graceful-drain call and a one-line retry hint closes every medium-impact finding in this report.
