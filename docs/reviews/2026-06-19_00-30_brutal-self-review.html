What I Found

1. OAuth2 callback returned JSON to a browser redirect FIXED

The OAuth2 callback handler (handleOAuth2Callback) returned a JSON response body. But this endpoint is invoked by the browser as a full-page redirect from the identity provider (Google/GitHub). The user would see raw JSON in their browser instead of being sent back to the application. This is a fundamental UX bug — the callback was never usable in a real browser flow.

Fix: Added OAuth2SuccessURL and OAuth2ErrorURL to HandlerConfig. On success: set session cookie + 302 redirect. On error: 302 redirect with error query param. Falls back to JSON when URLs are empty (for HTMX/SPA flows).

2. Dead code: startEviction method left behind FIXED

After extracting the OAuth2StateStore interface and moving eviction to startPeriodicEviction directly, the oauth2StateStore.startEviction() method became dead code. It was never called — initOAuth2 uses startPeriodicEviction(stateStore.EvictExpired, ...) directly. The LSP caught it (unusedfunc hint), but it was ignored.

Fix: Removed the method.

3. ExportUser didn't include ExternalAccounts FIXED

When an admin exports users, the ExportUser struct omitted ExternalAccounts. Admins had no way to see which OAuth2 providers were linked to which users. For security auditing (e.g., "which users have Google linked?"), this is a blind spot.

Fix: Added ExternalAccounts []ExternalAccount to ExportUser and populated it in exportAllUsers().

What's Good

wrapcheck error properly wrapped

The Consume interface method returns an error, and FinishOAuthLogin was returning it unwrapped — violating wrapcheck. Fixed by wrapping with fmt.Errorf("consume oauth2 state: %w", err).

Subject-first matching is working correctly

The matchOrCreateUser lookup order (provider+subject first, then email, then auto-register) is sound. Tests confirm it handles changed emails, multi-provider linking, and cross-user uniqueness correctly. This was the critical fix from round 1.

Deferred (Lower Impact)

Provider is still a raw string

Provider in ExternalAccount, OAuth2ProviderConfig, and all method signatures is string instead of a branded type like type Provider string. This means typos like "gogle" vs "google" aren't caught at compile time. Medium impact (type safety), medium work (10+ files to change).

BeginOAuthLogin discards context

BeginOAuthLogin(_ context.Context, ...) discards the context. The logAuth helper doesn't take context, and oauth2.GenerateVerifier() doesn't accept it. This is a pre-existing pattern across all auth methods (36 callers of logAuth). Low impact (the context is there for API consistency), high work to fix properly (need context-aware logger).
