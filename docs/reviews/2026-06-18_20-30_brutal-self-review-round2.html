1. What Did I Forget?

Version mismatch in integration_test/go.mod FIXED

signing/v2 and encryption/v2 were pinned at v2.4.0 while every other go-cqrs-lite module was at v2.5.0. Go MVS resolved it at build time, but LSP/gopls showed persistent errors about missing modules. Fixed by aligning to v2.5.0 and running go mod tidy.

EventSourcedSetup.Store silently nil when wrapped FIXED

The Store field was typed *memory.MemoryStore (concrete). When StoreWrapper returned an encrypted store, the type assertion store.(*memory.MemoryStore) failed silently, leaving result.Store = nil. A consumer accessing setup.Store after wrapping would get nil with no error. Fixed by changing to event.Store interface and assigning directly.

Stale ADR test counts FIXED

ADR 0011 said "6 unit tests" and "3 integration tests" but there were actually 8 and 4. Fixed counts and added description of Ed25519 test.

2. What Was Stupid?

Duplicated security config fields across two structs FIXED

ServiceConfig and EventSourcedConfig both defined StoreWrapper, PublishMiddleware, and HandlerMiddleware with identical types and ~20 lines of documentation each. Adding a 4th security field would require updating both places. Fixed by extracting SecurityHooks struct embedded in both configs.

Inconsistent error wrapping FIXED

NewEventSourcedSetup used fmt.Errorf("...: %w", err) while NewService used event.NewTransient("internal", "...").WithCause(err). Same package, two error styles. The event.NewTransient approach provides error classification (Transient family) for downstream retry logic. Aligned all errors in NewEventSourcedSetup to use event.NewTransient.

waitForUser polling anti-pattern FIXED

Used time.Now().Before(deadline) + time.Sleep(20ms) polling, violating the project's flaky-test guidance. Fixed to use context.WithTimeout + select on ctx.Done(). The polling itself is unavoidable — StartProjections runs the projection runner in a goroutine with no "replay complete" signal.

3. Ghost Systems & Split Brains

EventSourcedSetup.Store/Bus type assertion block — Ghost System ELIMINATED

The code at the end of NewEventSourcedSetup that tried to assert *memory.MemoryStore and *memory.MemoryBus from the store/bus interfaces was a ghost system: it existed to populate fields that would be nil when wrapping was active. The type assertions were silently failing for the exact use case (encryption) they were supposed to support. Removed entirely by using interface types directly.

SecurityHooks duplication — Split Brain FIXED

Two config structs with copy-pasted fields and documentation, with EventSourcedConfig's docs saying "See ServiceConfig.X for full documentation" — a code smell indicating the duplication was known but not addressed. Single source of truth now in SecurityHooks.

6. How Are We Doing on Tests?

Test coverage is strong

8 unit tests in service_security_test.go cover: StoreWrapper application, nil-result handling, error propagation, PublishMiddleware/HandlerMiddleware ordering, and both setup paths (NewService + NewEventSourcedSetup). 4 integration tests cover: encryption-at-rest with ciphertext verification, decrypt-on-load via second Service, bus-level sign+encrypt, Casbin projection survival, and Ed25519 asymmetric signing. All pass with -race.

Missing: property-based tests for crypto round-trips

No property-based tests verifying that sign→encrypt→decrypt→verify is an identity transformation for arbitrary event payloads. Would catch edge cases like empty payloads, large payloads, binary data. Deferred — current tests cover the main patterns adequately.

7. What Could Still Improve?

StartProjections has a time.Sleep(50ms)

es_projection_setup.go:56 sleeps 50ms after starting the projection runner goroutine, hoping replay finishes. This is the root cause of the waitForUser polling pattern. The proper fix would be a synchronous "replay complete" signal from the projection runner — but that's in go-cqrs-lite/projection/v2, not cqrs-htmx.

Root App security hooks question

The root cqrs-htmx package doesn't own a bus or store, so signing/encryption hooks are only in usermgmt. Consumers using root without usermgmt wire their own bus/store. This is documented in ADR 0011 but may warrant a convenience helper in the root package.
