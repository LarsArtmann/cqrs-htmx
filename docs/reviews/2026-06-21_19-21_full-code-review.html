01Critical Findings (8)

Critical Concurrency SSE Heartbeat races with Send on the ResponseWriter
sse_stream.go:68-76 (Send) · sse_stream.go:120-137 (Heartbeat)

Send() and Heartbeat() both call s.w.Write() + s.fw.Flush() from different goroutines with zero synchronization. The doc explicitly shows go stream.Heartbeat(...). http.ResponseWriter is documented as not safe for concurrent use. A keepalive comment (: keepalive\n\n) can interleave between data: lines of an in-flight event, corrupting the SSE wire format.

Fix: Add a sync.Mutex to SSEStream and serialize all writes through writeRaw(), or route heartbeats through the same select loop as events.

Critical Security Rate limiter uses r.RemoteAddr (includes port) — completely bypassable
usermgmt/http.go:237 · usermgmt/verification_totp_http.go:57

r.RemoteAddr in Go is host:port. Every new TCP connection gets a different ephemeral port → a fresh key in the rate-limiter map. An attacker who opens new connections gets unlimited budget. The rate limiter is decorative. Additionally, zero X-Forwarded-For handling — behind a proxy, all clients share one key.

Fix: Strip the port via net.SplitHostPort. Reuse the root module's httputil.ClientIP(r) / KeyExtractorFromClientIP() which already solves this.

Critical Memory / DoS perIPRateLimiter map grows unbounded — no eviction
usermgmt/http.go:104-138

Every other ephemeral store in this package (webauthnSessionStore, verificationTokenStore, oauth2StateStore, pendingTOTPStore) has EvictExpired + background goroutines. The perIPRateLimiter was forgotten — a rotating attacker causes unbounded memory growth until OOM.

Fix: Add periodic sweep or max-entries cap consistent with the eviction.go pattern.

Critical Security / MFA TOTP is never enforced as a second factor during login
usermgmt/webauthn_service.go:154-204

FinishLogin (WebAuthn) creates a session immediately on successful assertion — it never checks user.TOTPEnabled or calls VerifyTOTP. A user with TOTP enabled authenticates purely via WebAuthn. MFA is advisory-only. For a passwordless system, this defeats the purpose of the second factor.

Fix: After FinishLogin succeeds, if user.TOTPEnabled, return a "TOTP challenge required" intermediate response; only createSession after VerifyTOTP succeeds.

Critical Security Verification token leaked in API response
usermgmt/verification_totp_http.go:101

handleSendVerificationEmail always returns {"token": token} in the response body, even when sendVerificationEmail is configured (production). The entire point of email verification is that the token is delivered only via email. Any authenticated user trivially bypasses verification.

Fix: Only return the token when sendVerificationEmail == nil (dev mode). In production, return a success message without the token.

Critical Security Session.Token exposed via JSON serialization
usermgmt/user.go:97

Session.Token string json:"token". If a *Session is ever marshaled to JSON (logging, error envelope, HTTP response, audit trail), the bearer token is serialized in cleartext. TOTPSecret correctly uses json:"-" but the most security-sensitive field does not.

Fix: Token string json:"-". Provide an explicit Token() accessor for callers that need it.

Critical Architecture AsEnforcer bridge is structurally broken — 3-value Enforce vs 4-field Casbin model
usermgmt/authz_types.go:196-198 · authz.go:49

The Casbin model defines r = sub, dom, obj, act (4 request fields). But the root module's Enforce calls enforcer.Enforce(subject, resource, action) — only 3 values. Casbin receives 3 rvals for a 4-field model; the domain is silently missing. The bridge test (TestUsermgmtBridge_AsEnforcer) never calls Enforce, so the mismatch is untested.

Fix: Provide a domain-aware Enforcer interface in root, or have AsEnforcer() inject a default domain.

Critical Security Import/Export has zero authorization checks
usermgmt/import_export.go:73-211

ImportUsersFromJSON/CSV, ExportUsersToJSON/CSV are methods on *Service with no authorization parameter. exportAllUsers() dumps every user's ID, email, display name, roles, and external accounts. Any caller with a *Service reference can exfiltrate the entire user database.

Fix: Add an authorization gate (require admin role or explicit caller identity) before reading/writing user data.

05Cross-cutting Themes

Theme 1: Split-brain pattern — 6 instances The same logic exists in two places with divergent behavior: authorization (per-handler vs middleware), UserIDExtractor error handling, recovery (package vs App method), CSRF header names (config vs hardcoded helpers), roles (User aggregate vs Membership), and notify methods (3× duplication). This is the #1 architectural smell — every bug fix must be applied twice, and the copies drift.
Theme 2: Security defenses built then bypassed SSEEventID has a branded type with newline rejection — bypassed at the HTTP boundary. Email has ParseEmail validation — bypassed in the ES command path. Rate limiter exists — bypassed by using RemoteAddr with port. TOTP exists — never enforced at login. CSRF token check exists — bypassed by token-presence shortcut. Theme 4: Strong foundations worth preserving The event-sourcing domain layer (foldUser/decide pattern), branded ID types, typed enums (authMode, NotificationLevel, SwapStrategy), the fanOut[T] generic core, RFC 7807 StructuredError, constant-time token comparison, and the open-redirect sanitizer are all excellent.
