01Bugs Fixed

Bug — Fixed

SSEStream.OnDisconnect data race

sse_stream.go:162-164

OnDisconnect() appended to the onDisconnect slice without holding s.mu, while Close() iterated the same slice after releasing the lock. Concurrent registration and close = data race on the slice header.

Fixed OnDisconnect now acquires s.mu before append. Close snapshots the slice under the lock, nils it, then iterates the snapshot outside the lock (so user callbacks don't block other Send/Heartbeat calls).
Bug — Fixed

StartCleanupSweeper double-close panic

usermgmt/eviction.go:25

The stop function returned by startPeriodicEviction called close(done) unconditionally. A second call (e.g. double-defer, or explicit stop + Service.Stop) panics with "close of closed channel".

Fixed Wrapped close(done) in sync.Once.Do(). Safe to call multiple times.

WebAuthn Service Leaks *http.Request — High

webauthn_service.go:52,154 — FinishRegistration and FinishLogin take *http.Request directly. This is a dependency inversion violation: the service layer should accept parsed credential response bytes, not HTTP request objects. Makes the service untestable without *http.Request and unusable from non-HTTP transports.

Recommendation Extract request body parsing into webauthn_http.go, pass []byte or parsed webauthn.CredentialCreationResponse to the service.

Service is a God Object — Medium

service_core.go:23-57 — Service has 24 fields spanning 4 aggregates (User, Membership, Tenant, Bot) plus WebAuthn, TOTP, OAuth2, sessions, audit, and authorization. ADR-0019 documents that decomposition was attempted and blocked.

Scalability: 6 In-Memory Stores Without Interfaces — High

WebAuthn sessions, verification tokens, pending TOTP, account lockout, rate limiter, and read models are all in-memory with no interface or SQL alternative. Only SessionStore and SQLEventStore have production-ready backends. Multi-instance deployment is impossible without custom implementations.

O(n) Event Replay on Startup — Medium

service_core.go:149-159 — journalFromStore replays all events through projections on every NewService. No snapshot integration visible despite go-cqrs-lite/snapshot/v3 being an indirect dependency.
