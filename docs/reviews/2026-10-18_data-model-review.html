01Series Context

This is episode 3 of a continuing series: episode 1 (2026-07-19) catalogued the model and recommended the closed-union pattern (now visible in SessionOrigin, authMode); episode 2 (2026-08-05) scored identity-model 4.5/5 with four Low findings and the verdict "no action required on the domain core." Since then three things changed: the ActorID consolidation (ADR-0111) removed episode-era hazards, the frontend sync protocol (ADR-0056) added the largest new wire surface since the SSE envelope, and the StreamID display-form rule (gotcha 25) made wire-form choices load-bearing. This episode audits exactly those deltas.

+
ActorID consolidation (ADR-0111) — hazard resolved NewActorID(string) (which accepted anything, including a display-form "StreamMarker:…" string) is gone. Today: five kinds (User/Bot/System/Service/Unknown) via NewActorID(kind, raw), strict ParseActorID("kind:raw") returning an error, unexported fields. The closed union got tighter while gaining expressiveness.
+
Cursor: opaque on the wire, typed at the parse boundary ?after= is a bare string in the URL, but the server re-parses it with id.ParseEventID (ULID-validated) and rejects garbage with a 400 (sync_pull.go:225). This is exactly the right division: the wire stays stringly for JS, the Go boundary stays typed.
+
Honest encoding degradation When an event's stamp promises JSON but its bytes are not valid JSON (the metadata-only WithEncoding trap), the pull reports payloadEncoding: "opaque" and base64-carries the bytes instead of promising a framing the bytes cannot keep. The wire never lies.
+
Error model (P12) solved at the source identity-model's sentinels are errorfamily-constructed (NewRejection/NewConflict) with stable codes and no HTTP dependency — consumers get errors.Is plus a typed retry contract across module boundaries.

All nine findings are Low. None blocks a release train. Four are carried open from episode 2 (re-verified this episode at the exact same lines); five are new, all on the ADR-0056 sync surface.

Low · Carried

identity-model/external_account.go:8

The OAuth2 provider name ("google", "github", …) is untyped. Episode 2 recommended a typed enum or accepting an open consumer-defined set; the second reading won by inaction, and it remains defensible — providers are consumer-configured, so a closed enum would be wrong. What would still help: a Valid()-style normalization helper at the linking boundary.

identity-model/session.go:15

A security primitive as a raw field. Mitigations remain: constant-time comparison (TokenMatches, subtle.ConstantTimeCompare), generated-not-parsed lifecycle. Branding (type SessionToken string) is still the cheap hardening if the field ever grows a second stringly sibling.

Low · Carried

identity-model/credential.go:10-11

WebAuthn protocol mirrors; the real validation lives in usermgmt/webauthn. Carried open, unchanged, still no-action. Defensive copying on construct/clone (append([]string(nil), …)) is correctly done.

Low · New

N1 — SyncPushResult status/error union enforced by convention only

sync_push.go:57-62

confirmed should imply Error == nil and rejected should imply a non-nil Error — but both incoherent combinations are representable, and nothing validates them on parse. Today the only producer is the library itself (safe by construction: dispatchSyncPushEnvelope / rejectedSyncPushResult), so this is a consumer-parsing hardening item, not a live bug.

Fix Typed status + a coherence-checking UnmarshalJSON (see §03). Wire bytes unchanged.
Low · New

N2 — SyncEvent Payload/PayloadB64 exclusive-or by convention only

sync_pull.go:31-52

"Exactly one of Payload/PayloadB64 is set" is a comment, not a type. newSyncEvent honors it by construction (both clear paths return immediately), and encoding-honesty is even degraded correctly — but a Go consumer decoding a response can represent both-set and neither-set. Same class as N1, same fix shape.

Low · New

N3 — Half-branded wire vocabulary

sync_pull.go:321,328 · sync_push.go:27-30

SyncPayloadEncodingOpaque is a named constant, but its sibling value "json" appears as bare literals at the two comparison sites, and SyncPushStatusConfirmed/Rejected are untyped string constants. A typo in any literal compiles fine and silently breaks protocol semantics. Typed constants cost nothing and change zero wire bytes.

Low · New

N4 — SyncPushError.Family re-encodes a typed concept as raw string

sync_push.go:48-52

The field is the client's retry contract ("rejection"/"conflict" permanent, "transient" retry, "corruption"/"infrastructure" drop-and-log) — a faithful re-encoding of errorfamily.Family, which exists, is typed, and is already a dependency of this very file. The server converts via family.String() (with an unknown→Rejection fallback). For the JS client a string is right; for Go consumers parsing responses, a typed mirror with Valid() would carry the documented contract into the type system.

Low · Watch

N5 — Two client-facing wire surfaces disagree on streamId form

transport/event_sse.go:41 vs sync_pull.go:306

The SSE envelope (EventPayload) emits evt.StreamID().String() (display form, adjudicated legitimate by the gotcha-25 rule; the dashboardui goldens were regenerated to carry the branded form 2026-10-06); the sync pull emits evt.StreamID().Get() (bare form). Under the workspace's local go-cqrs-lite replaces the branding is already live (ParseUserID documents the "StreamMarker:" prefix), so in workspace mode the two JS surfaces already spell one stream two ways; against published tags the bytes are still identical, so nothing consumer-visible ships until the id-module change publishes. When it does: either unify both on .Get() (breaking the pinned goldens deliberately, once) or document the two-form rule in the sync guide.

03Go Data Model

The redesign for N1–N3 is deliberately small: brand the vocabulary, enforce the two unions at the parse boundary. Nothing here changes a single wire byte. 

// N3: brand the wire vocabulary (wire bytes identical — a typed string
// marshals to the same JSON as its untyped twin).
type SyncPushStatus string

const (
	SyncPushStatusConfirmed SyncPushStatus = "confirmed"
	SyncPushStatusRejected  SyncPushStatus = "rejected"
)

func (s SyncPushStatus) Valid() bool {
	return s == SyncPushStatusConfirmed || s == SyncPushStatusRejected
}

// N1: the union becomes unrepresentable-at-parse — a confirmed result
// carrying an error (or a rejected one without) fails decode.
func (r *SyncPushResult) UnmarshalJSON(data []byte) error {
	type plain SyncPushResult // avoid recursion
	var p plain
	if err := json.Unmarshal(data, &p); err != nil {
		return err
	}
	if !SyncPushStatus(p.Status).Valid() {
		return event.Newf("cqrshtmx.sync.push.status_invalid", "unknown sync push status %q", p.Status)
	}
	if (p.Status == SyncPushStatusConfirmed) != (p.Error == nil) {
		return event.Newf("cqrshtmx.sync.push.result_incoherent", "status %q contradicts error presence", p.Status)
	}
	*r = SyncPushResult(p)
	return nil
}

N2 gets the same treatment on SyncEvent: decode into a shadow struct, reject both-set and neither-set payload fields, and reject PayloadEncoding == "json" with an empty Payload. The producer side is already safe by construction — the parse side stops trusting the server.

06Decision Log

DecisionRationaleRejected alternative
Keep wire DTO fields as strings The primary sync client is JS; Go enums buy it nothing. Validation belongs at parse time, not in the field type. Branded StreamID/EventID wire types — would force every Go consumer through constructors for data the server already validated.
Typed constants + UnmarshalJSON coherence Zero wire-byte change, drift-proof literals, incoherent decode becomes an error. Rides a normal root train. Full interface-union result types (ConfirmedResult/RejectedResult) — over-models a wire DTO whose only Go consumer is tests.

07Anti-Patterns

Traps to avoid when hardening the sync DTOs

Do not brand the wire strings themselves. The finding is about the vocabulary constants and parse-time coherence, not the field types. Replacing StreamID string with a branded type on a wire DTO re-imports the domain into every client-side parse for no safety the server has not already provided. — Do not validate what you cannot reject. If a future consumer decodes SyncEvent strictly, both-set payloads must be an error, not a best-effort merge. — Do not "fix" N5 early. The goldens pin the SSE envelope bytes (to the branded display form, since 2026-10-06); touching .String() before the id-module branding publishes buys a broken golden and nothing else.

09Conclusion

"The domain core answered episode 2's question — impossible states unrepresentable — with a yes, and the sync wire answers the harder follow-up honestly: strings on the wire where JS needs strings, typed validation at every boundary Go controls. What remains is to make the wire's two-by-two unions fail loudly when parsed, not silently when read."
