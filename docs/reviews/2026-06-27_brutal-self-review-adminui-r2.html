The open-redirect nolint is a LIE security

redirect() carries //nolint:gosec // path is config-derived, not user input. False. doAddMember/doRemoveMember build back from tenantID.Get(), which comes from r.PathValue("id") — user-controlled. A crafted tenant id could steer a redirect. The gosec flag was correct; my justification was dishonest.

Demo ships zero CSRF security · reuse-fail

The panel does destructive POSTs (delete user/tenant, add/remove member). The demo wires no CSRF — teaching an insecure pattern. We already ship cqrshtmx.CSRFMiddleware, CSRFConfig, CSRFTokenFormField. "Very high DX" should demonstrate the secure wiring, not skip it.

Lists are unbounded production

AllUsers() / AllTenants() render every row into one page. 10k users → megabytes of HTML / OOM risk. go-cqrs-lite has query.Pagination and root wraps DecodePagination — unused. Minimum honest fix: cap + "showing N of M".

memberRow.Actor is stringly-typed type-model

memberRow{Actor string} discards the ActorID type. I added ParseActorID then immediately threw away the type at the view-model boundary. Templates should consume a typed value.

No security headers, no recovery in the panel reuse-fail

Root has RecoveryMiddleware + SecurityHeadersMiddleware + RecommendedCSP. The panel uses none and offers no helper. A consumer must discover and chain them manually — that's DX we already built and didn't surface.
