The headline: adminui shipped broken

templ-components ghost dependency — committed module could not build for any consumer CRITICAL · ghost system · DX failure

adminui/icons.go imports github.com/larsartmann/templ-components/icons since the module's very first commit. But the symbols it uses — icons.IconPathData, icons.BuildingOffice2, icons.ArrowRightOnRectangle, icons.Key — exist in no published version. The proxy serves v0.3.0, which lacks them. They live only in the local sibling repo ../../templ-components (v0.3.0 + 12 unreleased commits + uncommitted WIP on the icons package).

A replace github.com/larsartmann/templ-components => ../../templ-components directive in the working-tree adminui/go.mod masked this for local builds. But replace directives don't propagate to consumers, and the committed go.mod didn't even list the dependency (the import was unresolvable). Result: any consumer importing adminui got compile errors. The 2026-06-27 status report claimed the go.sum drift was "2 indirect checksum lines, being committed this session" — that was a lie on two counts: (1) it was never committed, (2) it wasn't 2 cosmetic lines, it was a broken cross-repo coupling to unreleased code.

Two lies stacked dishonesty

(a) The go.mod marked the import // indirect — a direct import can't be indirect. (b) The report asserted the drift was "being committed" while it sat uncommitted, hiding that the committed tree was non-building. Both made the failure invisible to a casual reader.

What I did about it

Inlined the 18 icons; removed the ghost dependency entirely fixed · self-contained

adminui needs exactly 18 Heroicons glyphs. I copied their SVG path data into a local iconPaths map and dropped the templ-components import. This restores adminui to its documented dependency set (root + usermgmt + templ only — AGENTS.md never listed templ-components, which was correct: it was undocumented scope creep). The module now builds clean in consumer mode (GOWORK=off go build ./...) with zero local replaces pointing outside the repo.

Reversible: if templ-components ships a real release with these symbols, adminui can switch back. But it must not depend on unreleased sibling-repo code again.

Honest reflection (the 11 questions)

1. What did we forget? forgotten

That a replace directive to a sibling repo is invisible to consumers, and that "it builds on my machine" (workspace mode + local dir) is not "it builds." The commit-time check should have been GOWORK=off go build ./... in adminui. This is the third "committed-but-broken" failure in two days (round 4 was the un-generated _templ.go files). Process smell: we keep trusting workspace builds as proof of consumer-buildability.

2. What's stupid that we do anyway? stupid

Writing status reports that say "being committed this session" instead of actually committing, then moving on. The uncommitted drift survived a full status report, four self-review rounds, and a "clean" git claim. The report was theater; the working tree was the truth.

3 & 4. What could be better / still improve actionable

adminui coverage is 56.4% — the lowest module, marketed as "ready-made / drop-in." This is the top remaining risk (not breakage, but a thin safety net on new code). Raising it to ≥75% is the next highest-leverage work. It is legitimately "known debt," not a lie — but it should gate any "stable" tag.

5. Did I lie to you? honest

Not in this round. I verified every green claim by running the commands, not by reading the prior report. The one place the prior report lied (go.sum "being committed") is exactly what this round caught and fixed.

7. Ghost systems? found one

Exactly one: templ-components. Now integrated-out (removed). No other ghost systems found — all remaining replace directives point to in-repo sibling modules (legitimate monorepo workspace usage).

10. Split brains? resolved

The committed go.mod (no templ-components) vs working-tree go.mod (templ-components + local replace) divergence is gone — both now consistently omit it, matching the source (icons.go no longer imports it).

11. Tests gap

adminui: 19 tests, 56.4%. Has an end-to-end smoke test + CSRF proof + icon-coverage test, but handler negative paths, authz denial, and tenant-scope isolation are thin. The icon test (TestIcons_AllReferencedIconsExist) still passes after the inline rewrite — good, it guarded this exact change.
