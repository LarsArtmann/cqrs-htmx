The codebase demonstrates genuine CQRS/ES discipline with excellent error taxonomy, strong typing, and comprehensive test coverage. However, there are security-critical issues in CSRF defaults, SSE concurrency, and session handling that should be addressed before production deployment. The v3 migration documentation drift (README/AGENTS.md still referencing v2 paths) affects every new consumer.

01Critical Findings

Security

CSRF origin validation bypass by default

csrf_middleware.go:152-153

isTrustedProxy returns true when no proxies are configured (the zero-value default). Combined with setPlaintextHTTPOrigin, ANY non-TLS request without Origin/Referer/Sec-Fetch-Site headers gets Sec-Fetch-Site: same-origin injected, bypassing nosurf's origin check entirely. A plain-HTTP deployment using CSRFConfig{} is wide open to origin-spoofing CSRF attacks.

Fix: Default to false when no proxies configured. Add explicit opt-in flag (AllowPlaintextBypass bool).
Security

CSRF validation failure silently ignored

csrf_middleware.go:37-38

CSRFMiddleware logs the Validate() error but proceeds to build and return a middleware with a broken config. SameSite=None without Secure is a real misconfiguration that the code detects but doesn't prevent.

Fix: Return a middleware that panics, or change the API to return an error.
Concurrency

SSE concurrent writes to ResponseWriter race condition

sse_stream.go:68-76, 120-137

Send() writes to s.w from the event-loop goroutine while Heartbeat() writes to the same s.w from a separate goroutine (as the doc explicitly instructs: go stream.Heartbeat(...)). http.ResponseWriter is not safe for concurrent use. Data race will corrupt the SSE wire stream or panic under the race detector.

Fix: Add a sync.Mutex to SSEStream; guard every s.w.Write / Flush pair under s.mu.
Security

SSE protocol injection via Event field

sse_event.go:96-100

WriteSSEEvent writes evt.Event directly into the event: line with no newline validation. If Event contains \n (e.g. "foo\ndata: <script>"), it injects arbitrary SSE fields. The Data field is properly line-split, but Event and ID are not.

Fix: Validate evt.Event and evt.ID for \n, \r, \x00 in WriteSSEEvent.
Data Integrity

Non-deterministic replay in membership readmodel

usermgmt/es_membership_readmodel.go:55

AddedAt: time.Now().UTC() uses wall-clock time instead of evt.OccurredAt(). Every journal replay produces different timestamps. UserReadModel correctly uses evt.OccurredAt() everywhere.

Fix: AddedAt: evt.OccurredAt().
Logic Bug

TenantDeleted cleanup is a no-op in Casbin projection

usermgmt/es_casbin_projection.go:102-110

On TenantDeleted, RemoveAllRolesForUser(tenantID) is called, but member policies are stored as g, actorID, role, tenantID (subject=actorID, domain=tenantID). No policies have the tenant as subject. The comment claims it "cascades role cleanup for all members" — it does not. Deleted tenants leave orphaned member policies.

Fix: Need a domain-scoped cascade like RemoveAllPoliciesInDomain(tenantID).
Data Loss

SQL session store permanently loses impersonation origin

usermgmt/sql_session_store.go:166

SQLSessionStore.Find always reconstructs sessions with Origin: DirectLogin{...}. Impersonation sessions stored in SQL permanently lose their Impersonation origin. The middleware check session.Origin.(Impersonation) will never match for SQL-stored sessions, breaking impersonation detection and audit trails.

Fix: Add originType + OriginData columns to the schema. Serialize/deserialize SessionOrigin.
Security

Verification token leaked in production HTTP responses

usermgmt/verification_totp_http.go:101

handleSendVerificationEmail always returns the raw verification token in the JSON response: {"token": token}. Even when SendEmail is configured (production mode), the token is exposed to the HTTP client. Any XSS or log interceptor captures the verification token.

Fix: Only return the token when sendVerificationEmail == nil (dev mode).
Performance

Double session store lookup per authenticated request

usermgmt/middleware.go:115+122

authenticateRequest calls service.Authenticate() (which internally calls sessions.Find), then immediately calls service.sessions.Find() again. Every authenticated request hits the session store twice. With SQLSessionStore, that's two SQL queries per request.

Fix: Refactor Authenticate to return both *User and *Session.
Documentation

README.md Quick Start uses v2 import paths — won't compile

README.md:53,59,70-72

Quick Start import paths use /v2 but go.mod is github.com/larsartmann/cqrs-htmx/v3. go get commands also missing /v3. Every consumer following this README gets broken imports.

Fix: Change all import paths and go get commands to /v3.
Documentation

AGENTS.md stale v2/error-family v0.4 references

AGENTS.md:144,198 · catalog/README.md (entire file) · TODO_LIST.md:48 · flake.nix:43

AGENTS.md states go-error-family v0.4.0 and event/v2, but all go.mod files use v0.5.0 and event/v3. Catalog README references /v2 throughout. flake.nix says version = "2.4.0" but module is v3.0.0.

Fix: Update all documentation to v3 paths and versions.
Documentation

GONOSUMCHECK is a no-op since Go 1.16

flake.nix (all apps: test, build, lint, coverage, fuzz)

Every Nix app sets GONOSUMCHECK='github.com/larsartmann/*'. This environment variable was removed in Go 1.16 and is a complete no-op on Go 1.26.3. The correct variable is GOPRIVATE.

Fix: Replace with GOPRIVATE='github.com/larsartmann/*'.

♦Strengths

What this codebase does exceptionally well — preserve and protect these patterns.

+
Pure decide/fold functions Every decide function is a closure with no I/O — only event construction. Folds are pure value-in/value-out. Genuine CQRS/ES discipline across all 4 aggregates.
+
Consistent error taxonomy Every error uses event.NewRejection/NewTransient/NewInfrastructure/NewConflict. No bare errors.New or fmt.Errorf in non-test code. Error→HTTP status mapping centralized via MapError.
+
fanOut[T] generic hub Correctly shared between SSE and WS broadcasters. RLock-during-broadcast + non-blocking-select + close-in-Unsubscribe prevents "send on closed channel" panic without complex coordination.
+
Strong typed IDs throughout UserID, TenantID, BotID, ActorID, CorrelationID, RequestID, SSEEventID — all branded types preventing compile-time mixing. Context keys use unexported struct types.
+
OAuth2 PKCE + single-use state tokens Cryptographically random, single-use (Consume deletes on read), TTL-expired, provider-validated. PKCE S256 challenge. Textbook CSRF protection for OAuth2.
+
HMAC-peppered bot tokens API tokens never stored raw — only HMAC-SHA256 with server-side pepper. DB leak alone doesn't compromise tokens.
+
Defensive slice copying everywhere Every decider copies slices before embedding in events. User.Clone(), WebAuthnCredential.Clone() deep-copy. No aliasing of caller data into events.
+
Session origin as sealed interface SessionOrigin with unexported isSessionOrigin() — only DirectLogin and Impersonation can implement it. Impossible auth states unrepresentable.
+
Catalog module is exemplary 471 lines total, zero external deps beyond go-cqrs-lite/catalog + go-error-family. Build()/BuildValid() dual API well-designed.
+
WriteSSEEvent zero-allocation fast path append-based buffer building with strconv.AppendInt and direct byte literals. Well-optimized for SSE hot path.
+
Rate limiting per endpoint group Registration, TOTP, verification, WebAuthn, OAuth2, import/export each have independent per-IP rate limiters — granular brute-force protection.
+
Deterministic membership IDs deriveMembershipID uses id.DeriveAggregateID — idempotent by construction. Same actor+tenant always maps to same aggregate.
+
Documentation quality is consistently high Every exported symbol has a doc comment. Many include usage examples. doc.go package overviews are comprehensive.
+
File sizes well-controlled Almost all files under 350 lines. Most are 50-200 lines. Clear, focused, single-responsibility files.
