What's stupid / forgotten

My own demo bypasses my own default authorizer dishonest

The panel ships a role-based defaultAuthorizer (super_admin/admin in domain *). But examples/admin-demo uses RequireAuthenticated() instead — because satisfying the real default means wiring a Casbin global role, which I didn't bother to do. So I shipped a "default" I never proved works. A user who copies the demo gets the wrong mental model.

Memberships are read-only core gap

You can see tenant members but not add, remove, or re-role them. A "Tenant Admin UI" that can't manage its own members is half a feature. The commands (AddMember/UpdateMemberRoles/RemoveMember) already exist and are wired — only the Service methods + UI are missing.

No pagination scale

AllUsers() / AllTenants() / Recent(100) render everything into one page. Fine for demos, broken past a few hundred rows. go-cqrs-lite has pagination primitives the root module already wraps — not yet used here.

Dashboard "Tenant" stat shows a raw ID polish

Tenant-admin mode renders TenantID.Get() (a slug string) as a big stat value instead of the tenant's display name. Looks like a bug to a user.

Silent icon fallback latent bug

A typo in an icon name (e.g. "usr") silently renders a grey dot — no error, no test catching it. The Go side now uses icon* constants, but the .templ files still use raw strings.

CSRF is 100% the consumer's problem production gap

The panel issues state-changing POSTs with no CSRF token, and the demo ships none. Documented, but "very high DX" would at least show the pattern in the demo.

What's good — keep it

templ with committed generated files

Consumers import _templ.go directly — zero codegen on their side. First module to adopt templ; flake already formats it.

Clean leaf boundary

adminui → root + usermgmt + templ. Nothing depends on it. Mode-based routing genuinely hides global routes in tenant mode (404, not hidden-by-CSS).

Self-contained modern design system

Embedded CSS, light/dark, configurable accent. No Tailwind, no JS framework, no build step. Genuinely good-looking.

Correct HTMX patterns

Search returns a fragment on HX-Request; destructive actions use HX-Redirect; toasts via HX-Trigger. GET /{$} anchoring prevents the dashboard catch-all bug.

Prioritized execution plan (work vs. impact)

  1. Make the demo honest — assign super_admin to the demo admin and switch the demo to the real defaultAuthorizer. LOW work · HIGH impact
  2. Member management — add Service.AddMember/UpdateMemberRoles/RemoveMember; UI to add/remove members and change roles (tenant detail + tenant-admin members). MED work · HIGH impact
  3. Dashboard tenant stat → display name. TINY · polish
  4. Icon-name validation test — assert every icon string used in .templ exists in the icon map. TINY · prevents silent bugs
  5. Log render errors instead of swallowing them as "render error". TINY · debuggability
  6. Flow tests — tenant create/delete/reactivate, user delete, member add/remove via HTMX. LOW-MED · coverage

Deferred (noted, not creep): pagination (needs paginated read-model query methods); CSRF wiring in the demo; favicon.
