The headline bugs

Three findings could corrupt or compromise consumers: an open-redirect bypass in SafeRedirectPath (backslash protocol-relative URLs), a codemod path in cqrs-htmx-upgrade that emitted unparseable Go for single-line imports (two stacked bugs: a wrong lineStart byte scan plus a fuse that deleted the import keyword), and an OAuth2 pre-account-takeover vector (email-match linking without EmailVerified). All three are fixed with regression tests.

The systemic theme

Split brains between paired implementations that were never cross-checked: fold vs projection (TOTP reset on email change), docs vs code ("atomic" Apply, "immutable" 1-year caches on mutable content, "same audit log" claims in systemadapter), and cap-vs-filter composition in the SSE replay path. Each pair was correct alone; the pair drifted.

01Fixed in-session

Critical · Fixed

SafeRedirectPath backslash bypass

redirect.go:31 · commit 571b9953

SafeRedirectPath("/\\/evil.com") passed the guard (index 1 is a backslash, not a slash) — but WHATWG URL parsing treats \ as / in special schemes, so browsers followed it off-site. The guard is the documented open-redirect defense for adminui, dashboardui, and loginpage. Fixed by rejecting /\ prefixes; first root-owned unit tests for this security primitive (a documented 2026-07-26 process gap).

Critical · Fixed

Codemod corrupted consumer files on single-line imports

cmd/cqrs-htmx-upgrade/rewrite.go · commit c7d23d9b

Two stacked bugs on the never-tested unparenthesized-import path: dropImportSpecs' lineStart used IndexByte (first newline) instead of LastIndexByte, producing garbage drop offsets for any import not on line 1 — the output began p"github.com/...", the package clause eaten. Even with correct offsets, the fuse replacement emitted a bare spec line, deleting the import keyword. Fixed: true line start, whole-decl fuses open a fresh import (...) block, blank/dot imports are never drop candidates, and -apply now re-parses output and refuses to write unparseable files.

Critical · Fixed

OAuth2 pre-account-takeover + live credentials in error contexts

usermgmt/service_oauth2_extracted.go · usermgmt/oauth2/provider.go

Email-match linking ignored EmailVerified: any provider reporting unverified user-controllable emails (GitHub noreply, generic OIDC) let an attacker link their identity to the victim's account and receive a session (NIST 800-63B forbids this). Unverified identities now auto-provision instead. Companion fixes: matchVerifiedEmail extraction also killed a nil-deref shadow bug and the complexity lint regression; all code/pkce_verifier echoes were stripped from error contexts (a code+verifier pair read from failure logs is redeemable, RFC 7636 §7.1 — resolves owner decision D10).

High · Fixed

TOTP read-model/fold split brain locked users out of MFA

usermgmt/es_readmodel.go:108 · commit 571b9953

FoldUser resets TOTP on EmailChanged; the projection did not. After a ChangeEmail, DisableTOTP saw the fold's TOTPEnabled=false and emitted nothing — the read model kept the secret forever, login still demanded TOTP, EnableTOTP was rejected, DisableTOTP silently no-oped: an undisableable second factor. The projection now mirrors the fold, pinned by a regression test.

High · Fixed

SSE replay cap dropped events and starved scoped feeds

transport/journalsse.go · transport/serve.go · commit 0e3f33a0

Three correctness bugs: (1) a capped reconnect delivered [cursor+1, cursor+limit] then jumped to live — the gap was silently and permanently lost (head-truncation where tail semantics were documented); the seekable path now pages ReadFrom with a rolling tail (also killing the per-connection full ReadAll), and the full-scan fallback tail-truncates; (2) WithSSEFilter + WithSSEMaxReplay composed cap-before-filter, so a burst of non-matching events could zero out a scoped feed's backfill — filters now run first and the cap counts only matches; (3) a panicking consumer predicate killed the replay goroutine (go-sse guards the live path only) — now recovered and treated as non-match. Four regression tests pin the semantics.

02Open findings (queued)

High · Open

Casbin g2 role hierarchy is disconnected from Enforce

identity-model/authz_model.go:20

User→role grants live in domain-scoped g; role→role hierarchy in g2. Casbin RMs do not compose across the two, so g2(r.sub, p.sub) never fires for a user subject — an admin does not inherit user/viewer policies except via the admin wildcard. ImplicitPermissionsForUser and ImplicitRolesForUser disagree about the hierarchy (one walks only g, the other walks both). Fixing needs a design pick (hierarchy into the same g, two-step matcher, or named-RM merge) — queued with the analysis, not fixed blind.

High · Open

WebAuthn clone detection is dead: sign counter never persisted

usermgmt/webauthn/provider.go:267 + identity-model/interfaces.go:47

go-webauthn's FinishLogin returns the updated credential (advanced Authenticator.SignCount); the module discards it, the interface can't carry it, and no credential-update command exists. The stored counter stays at its registration value forever, so the clone check (new ≤ stored) can never fire — WebAuthn L3 §7.2 step 21 requires updating it. Same cluster: stored UP/UV flags are fabricated true on every reload (poisons go-webauthn's UV latch used for step-up decisions); registration and login challenge sessions share one key namespace (concurrent ceremonies overwrite each other). Cross-module API change — queued as one coherent work item.

High · Open

Authz.Apply is not atomic despite its contract

identity-model/authz_policies.go:8

Sequential adds/removes with early return on first error and no rollback: a failed batch leaves the enforcer partially mutated — stuck grants or revocations in an authorization engine. Fix: staged copy + swap (casbin e.Copy()), or stop claiming atomicity.

Medium · Open

systemadapter's declarative path is not the equivalence it claims

systemadapter/queries.go:167 · declarations.go:552 · views.go:86

Three divergences from the legacy path whose deprecation note claims "the same": the Enforce ladder grants viewer→read/user→write where legacy Casbin grants those roles nothing (migration silently widens permissions); the audit Action vocabulary drifts from usermgmt.AuditAction* constants; declarative audit entries drop ActorID entirely — "who did it" is a compliance regression. Must be fixed (or loudly documented) before the v5 retirement of NewProjectionLayer.

Medium · Open

RunWithAppkit silently drops the bundle's health composition

setup/run_appkit.go:77-92

appkit's default health endpoints win the longest-prefix match; the bundle's HealthPath mount — the one carrying Config.HealthChecks and the sse-hub built-in — is unreachable inside the / catch-all. A consumer who validated HealthChecks at New gets zero effect on this serve path. Companion queued items: config.go god-file split (1186 lines, five hand-maintained path lists), LoginRedirect default not following a customized AdminPath.
