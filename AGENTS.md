# cqrs-htmx

> **THIS IS A LIBRARY/SDK — NOT AN APPLICATION.** Consumers import this package into THEIR projects.

Go library that makes it easy to use go-cqrs-lite with HTMX, templ, and Casbin authorization. Framework-agnostic — works with `net/http`, Gin, Chi, etc.

> **Orientation.** This is a Go **library**, not an application — consumers import it.

## Architecture

**Multi-module Go workspace.** 30 modules under one `go.work`:

- **Root** (`cqrs-htmx/v4`): HTTP handler builder, HTMX/SSE helpers, authz (Casbin), error mapping, pagination, `openapi/` (dependency-free OpenAPI 3.1 builder + `WithOpenAPI`/`OpenAPISpecHandler`), `transport/` (canonical SSE domain-event surface: `DomainEventToSSE` + `EventPayload` envelope + `NewJournalSSEStore` + `ServeDomainEvents` + `WithSSEFilter` + `WithSSEMaxReplay`; envelope bytes pinned by golden tests, drift = test failure), **frontend sync protocol (ADR-0056, 2026-10-09): `SyncPullHandler` (cursor + permission-filter + ETag event pull WITH payloads; delivery encoding is honest — `"opaque"`/`SyncPayloadEncodingOpaque` when a json stamp's bytes are invalid, the gotcha-24 third victim) + `App.SyncPushHandler` (batched push, per-command classified outcomes, replays registered pipelines via the internal `commandRegistry` — zero new registration surface) + sync assets v1.6.0 (pull cache, batch flush, cursor-monotonicity guard, IndexedDB v1→v2 upgrade pinned, `window.cqrsSync`)**; guide `docs/guides/frontend-sync.md`. ## Key Patterns

- **Library principle:** never enforce defaults consumers might disagree with (no mandatory CSP/HSTS/CSRF — all opt-in).
- **Direct imports only (ADR-0062, 2026-11-06):** a cross-package alias is never a permanent API. A move ships repointed consumers, not a shim; a compatibility alias must carry `// Deprecated:` naming the owning import path and its removal release; there is exactly ONE breaking window per major version (v5 is this generation's). Four exemption classes exist and must be argued in the ADR. The gate — not the convention — is what keeps it monotone: without `check-reexport-policy` the next extraction re-creates the façade, which is exactly how the 2026-11-02 split shipped 336 LOC of aliases labelled "not deprecated".
- **No stdlib error constructors:** `errors.New`/`fmt.Errorf` banned in non-test code; use `event.New*/Wrap*/Wrapf/Newf` from go-cqrs-lite. Error families → HTTP status: Rejection(400), Conflict(409), Transient(503), Corruption(500), Infrastructure(503).
- **Duck-typing for external libs:** `Enforcer` (← casbin), `TemplComponent` (← templ), auth provider interfaces — consumers import what they need.
- **authMode enum:** `authNone`/`authRequired`/`authAuthorized` — impossible states unrepresentable.
- **Authorization contract + durable grants (ADR-0057, 2026-11-02):** `cqrshtmx.Request{Subject, Domain, Resource{Type,ID}, Action}` + `Decide(PermissionChecker, Request) (Decision, error)` is the ONE decision surface; `Decision.Reason` separates `allowed` / `denied_by_policy` / `no_matching_policy` / `not_authenticated`, and an engine failure is an error (503), never a silent denial. `PermissionChecker` is primitive-shaped so `identitymodel.Authz.Check` satisfies it structurally — root still imports no Casbin, identity-model still imports no HTTP; the compile-time assertion lives in usermgmt (the only module seeing both). `Service.GrantRoles`/`RevokeRoles`/`HasAdminGrant` are the durable write path (membership commands → event → projection replay); `Authz.AddGroupPolicy` is DEPRECATED in v4 (ephemeral, gotcha 45) with `Authz.ApplyGroupPolicy` as the projection-only seam. `EnforceIn` is the shipped 4-arg shape (`Enforce` keeps 3 args + wildcard domain and falls back on a request-size mismatch — the 403-not-503 fix). Denials share codes `forbidden`/`unauthorized`; `IsForbidden`/`IsUnauthorized` walk the whole unwrap chain. `AuthorizeIn`/`AuthorizeRequest` are the tenant-aware handler options. **Route postures (L4, 2026-11-03):** `cqrshtmx.Posture` (`public`/`authenticated`/`role-gated`/`ungated` = "this layer adds no gate") + `RoutePosture{Method, Pattern, Posture, Why}` are the shared vocabulary; adminui's mux AND manifest generate from ONE routeSpec table (`Handler.Routes()`, mode-scoped rows absent in the other mode, forgotten mode = served by NO mode; `Config.AuthorizerPosture` declares custom-authorizer truth, validated at New), dashboardui's `Route` carries derived `Posture`+`Why`, loginpage exposes its public row, setup's `Bundle.RoutePostures()` aggregates one row per mounted layer; authztest aliases the constants and REFUSES `ungated` in the matrix. Gates: `check-permission-surface` (4 anti-patterns) + `check-permission-maturity` (docs/PERMISSIONS.md level ratchet; cqrs-htmx row is L4) + `check-route-postures` (manifest pins per module, HERMETIC `GOWORK=off` since the v4.16.0 train — workspace mode insta-fails in CI because the tracked `go.work` carries `/home/lars/projects` local-dev replaces; hermetic also makes the pins tag-lag sensitive, so they red until our own train lands, gotcha 30) — all in check-modules + CI. Guides: `docs/guides/authorization-system.md`, `docs/guides/route-posture.md`, `docs/PERMISSIONS.md`, ADR-0058 (ReBAC deferred, numeric trigger).

- **Auth route posture is library-enforced (ADR-0055, 2026-10-04):** WebAuthn enrollment ceremonies enforce the owner-match rule (401 no session / 403 mismatched `user_id`; no HTTP opt-out — headless enrollment goes through the service-level API), and every `currentUser`-reading `/auth/*` route self-wraps with an enrich-only session pass inside `RegisterRoutes` — the "context-only handler + bare mount = dead route" class is dead. loginpage's register→begin→finish flow depends on the register-issued cookie riding `credentials: "same-origin"` fetches (same-origin mount required; proven by `TestBareMount_LoginPageFlow_WorksUnderGate`). `setup.RequireSession`/`RequireSessionRedirect` are the exported gates for consumer surfaces. Invariant mechanized: `scripts/checks/check-session-route-wrappers.sh` (`nix run .#check-session-route-wrappers`, in check-modules + CI).
- **Projection lifecycle via projectionhost:** per-projection goroutines, per-projection checkpoint keys (`Name()`), DLQ, crash-restart, read-your-writes via `waitForDrain`. `AsyncStartup` (opt-in) returns before drain — failures surface via `ProjectionStatuses()`/`/health`/`OnProjectionFailed`, not as a `NewService` error; `cqrshtmx.ProjectionReadinessCheck` is the readiness gate. `RebuildProjection(ctx, name)` swaps in a fresh host (projectionhost hosts are one-shot). Guide: `docs/guides/async-projection-startup.md`, `docs/guides/event-replay-and-rebuild.md`.
- **Checkpointed restarts via SQL hydrate:** `CheckpointStore` + SQL read models rebuild in-memory state before the host starts; `hydrationAwareCheckpointStore` (applied by the shared `startProjectionHost` factory) forces casbin-projection + the default in-memory AuditLog to full-replay, so authz policies and the audit trail stay complete after restarts. Append handlers are idempotent (at-least-once convergence); `MemberAdded.AddedAt` uses event time. TOTP secrets persist in `users_view.data` — rows written by pre-hydrate versions lack the secret: run `RebuildProjection(ctx, "user-read-model")` once after upgrading an existing SQL read model, or affected TOTP users re-enroll.
- **go-cqrs-lite is richer than the hooks:** the `*command.Dispatcher`/`*query.Dispatcher` passed to `Config.Commands`/`Config.Queries` implement `Use(mw ...)` — every factory from `go-cqrs-lite/middleware/v4` (logging, recovery, retry, circuit breaker, metrics, OTel, validation, idempotency) composes with zero glue. Capability map + recipes: `docs/guides/leveraging-go-cqrs-lite.md`; runnable proofs in `examples/middleware-demo` + `examples/observability-demo`.
- **go-cqrs-lite utilization audited 2026-11-03** (`docs/research/2026-11-03_go-cqrs-lite-deep-dive.html`, third in the series): adoption 73/100 high (47 capabilities, 22/37 fully leveraged, 0 anti-patterns), all 15 pinned trains at latest tags. - **Set `BaseProps.ID` on every library component the JS/tests target** — `EnsureID` randomizes un-pinned IDs (keep DOM hooks stable across regenerations).
- **Table-fragment contract:** partials for `hx-swap=innerHTML` targets contain rows but NOT the wrapper; polled-region partials re-render the REGION itself (outerHTML contract — bare children would kill polling after one refresh).
- **htmx attribute INHERITANCE leaks the boost wrapper onto every ajax element (2026-10-18, the overview-blanking bug):** dashboardui's `.app-layout` wrapper carries `data-hx-boost/target/select/swap="#main-content"` for boosted navigation, and htmx resolves `hx-target` AND `hx-select` through the ancestor chain for EVERY ajax element (verified in the embedded 2.0.10's `ne()` resolver; byte-identical logic confirmed in the 2.0.11 bump, 2026-11-07). Any `hx-get`/`hx-post` element inside the subtree without its own pins selects `#main-content` from a partial response that has none → htmx swaps an EMPTY fragment into `#main-content` → the page blanks within a second (first SSE event fires the `refresh` trigger). Defense: EVERY self-fetching element inside a boosted wrapper must pin its own attrs — `hx-target="this"` + `hx-select="unset"` (`ne()` treats the literal "unset" as no-selection; the events filter form already self-defends with explicit target/select/swap, and the projection-health PolledRegion now carries `hx-target="this" hx-select="unset"` via `BaseProps.Attrs`, pinned by the overview golden). Also: journal reads from a ZERO cursor return the OLDEST events (`ReadFrom(zero, n)` = head, not tail) — newest-N views must page the journal keeping a rolling tail (`core.LoadTailEvents`), never trust a zero-cursor read for "recent".
- **CSP:** inline `--tc-sidebar-w` style attributes are dropped by nonce CSP — redefine in consumer CSS; the library's popover/dialog CSS and dark-surface classes may need vendoring into the consumer's compiled CSS (the library's own bundle never loads in these modules).
- **Popover anchoring is a two-layer contract and the CSS layer must be vendored CORRECTED (2026-11-05, the dropdown e2e red):** since templ-components v1.27.0 the `tcPopoverPosition` JS singleton exits early on anchor-positioning engines (Chromium ≥ 125), deferring to CSS — but the library's `custom.css` layer is broken on Chromium 156: its compound `position-area` values (`bottom span-inline-*`, `bottom start|end`) are REJECTED by the engine (declaration drops → popover parks at the viewport corner), and `anchor()` cannot see the implicit `popovertarget` invoker (only explicit `anchor-name` declarations resolve; single-keyword bands like `position-area: bottom` are the only valid generic form, self-aligned anchor-centered by default — all verified empirically on nix Chromium 156). adminui's `tailwind.css` vendors the corrected layer: single-keyword bands + an explicit `anchor-name`/`position-anchor` pair for the known `#admin-user-menu-*` flush-end instance (stylesheet-declared, so CSP holds). When vendoring library CSS, engine-validate the VALUES, not just the `@supports` gate — `@supports (anchor-name: --x)` passes while the compound value syntax silently drops.
- **Dark-mode surfaces:** if the consumer's `@theme` remaps gray-800/900 (e.g. to `--text`), pin them back to literal darks in dark mode — library `dark:` variants assume literal darks (all library `text-gray-800/900` occurrences carry `dark:` overrides, so the pin is safe). Dark mode itself is CLASS-driven in both UI modules (adminui + dashboardui, 2026-09-23): `@custom-variant dark` + `html.dark` tokens + `layout.ThemeScript`/`ThemeToggle`; the old media-query token flip is gone (no-JS degrades to light).
- **Hybrid (strings.Builder) rendering:** templ `{children...}` renders EMPTY in the hybrid path — use props-based components or the `templ.WithChildren(ctx, child)` escape hatch (v1.19.1); `display.Grid`/`htmx.PolledRegion` need a real templ path. Ends here: dashboardui converted to full templ (2026-09-22); no remaining repo consumer renders library components through strings.Builder.
- **loginpage ADOPTED the library** (2026-10-04): `layout.Base`, `forms.Input`, `display.Button`, `feedback.Alert`, `utils.Class`/`utils.Ternary` — the former "adoption opportunities" list is fully consumed; loginpage's page compiles through templ, its JS-injected spinner uses only scanned Tailwind utilities (see loginpage/README.md § Styling).
- **Adoption inventory:** the grep-able adopted/custom/divergent table lives in `dashboardui/README.md` (§ Styling and templ-components Adoption); audit series in `docs/research/` — `2026-09-17_templ-components-dashboardui-deep-dive.html` (14/100) with the series entry point `2026-10-04_templ-components-deep-dive.html` (repo-wide 94; the comparable rubric §06 lives there — the 09-23 audit was evicted as uncited, its outcome recorded in the research README's series table).

## Benchmarks

Every serious comparison uses `b.Loop()` (Go 1.24+) + `b.ReportAllocs()` + `b.ReportMetric(req/s)` + benchstat (`-benchtime=2s -count=5`), with `b.Cleanup` stopping timers before server drain. Suppress per-request logging in benches (`appkit.LogLevelError`, or pin `slog.SetDefault(slog.New(slog.DiscardHandler))` for the sub-bench + restore on cleanup) — skipping this makes log lines the dominant measurement. One-off `time.Since` blocks in tests are forbidden — they belong in `*_bench_test.go`. Canonical pattern: `setup/run_appkit_test.go:BenchmarkSpikeBaselineVsAppkit`. The machine-pinned raw baseline (`docs/benchmarks/setup-baseline.raw.txt`) is the ONLY gate-comparable artifact; human markdown records are not comparable.
