# cqrs-htmx

> **THIS IS A LIBRARY/SDK — NOT AN APPLICATION.** Consumers import this package into THEIR projects.

Go library that makes it easy to use go-cqrs-lite with HTMX, templ, and Casbin authorization. Framework-agnostic — works with `net/http`, Gin, Chi, etc.

## Architecture

**Multi-module Go workspace.** 26 independent Go modules under one `go.work`:

- **Root** (`cqrs-htmx/v4`): Core library — HTTP handler builder, HTMX/SSE helpers, authz (Casbin), error mapping, pagination, `openapi/` sub-package (dependency-free OpenAPI 3.1 spec builder + `WithOpenAPI`/`OpenAPISpecHandler`). CSRF, Server-Timing, and keyed rate limiting are now thin re-exports over `httputil` (see `_reexport.go` files). **WebSocket transport removed in v5** — SSE only (see ADR 0046).
- **identity-model** (`identity-model/v4`): Pure domain types for event-sourced identity management — IDs (UserID/TenantID/BotID/ActorID), events (21 payload structs), commands (20 structs with accessor methods), fold functions (FoldUser/FoldMembership/FoldTenant/FoldBot), state structs, Authz engine (Casbin-backed), Session, User, Membership, ExternalAccount, WebAuthnCredential, crypto helpers, domain errors (errorfamily-only, no HTTP dependency), upcaster registry, exported constants (event types, command types, aggregate types, schema version). Casbin is a first-class dependency.
- **usermgmt** (`usermgmt/v4`): Event-sourced CQRS user management — thin re-export layer over identity-model (type aliases + var aliases for fold functions/constants + constructor wrappers + WithHTTPStatus-wrapped errors) plus infrastructure (HTTP handlers, SQL stores, session middleware, read models, CasbinProjection, decide/dispatch functions). Auth via WebAuthn/TOTP/OAuth2 behind interfaces
- **usermgmt/totp**, **usermgmt/webauthn**, **usermgmt/oauth2**: Independent auth strategy modules — satisfy `usermgmt` interfaces via structural typing
- **adminui** (`adminui/v4`): Ready-made admin dashboard (templ + HTMX)
- **loginpage** (`loginpage/v4`): Ready-made passwordless login page
- **datastar** (`datastar/v4`): Optional DataStar frontend adapter — script serving, signal decoding, SSE response builder (ConsoleLog/ConsoleError/DispatchCustomEvent/ReplaceURL/Prefetch etc), Broadcaster with replay via `godatastar.MemoryStore` (`NewBroadcasterWithReplay`), `Raw()` accessor + `NewBroadcasterFromRaw` for cross-transport hub sharing with root `cqrshtmx.Broadcaster` (see `docs/guides/sse-and-datastar.md`), signal constructors return `(Patch, error)` (no silent error swallowing), EventBridge with `OnError` callback. 57 tests, 97.4% coverage. Depends on go-datastar + go-sse (no root dep). See `docs/guides/datastar-integration.md`.
- **dashboardui** (`dashboardui/v4`): Ready-made CQRS/ES observability dashboard — projection health, event catalog overview, real-time SSE updates. Builds HTML via `strings.Builder` + `fmt.Fprintf` (not templ). Has a `core/` sub-package (pure data layer: capabilities, pagination, events, overview, payload, format, DLQ) bridged via type aliases in `core_bridge.go`. CSP-safe: all inline `onsubmit` handlers replaced with `data-confirm` pattern, inline scripts moved to external JS.
- **setup** (`setup/v4`): Optional one-call composition root — `setup.New(Config) (*Bundle, error)` creates shared stores, constructs `usermgmt.Service` with all auth strategies, and builds admin/dashboard/login UI panels. `Bundle.Mount(mux)` mounts all routes with correct middleware ordering; `Bundle.Handler(mux)` mounts + wraps with security middleware in one call; `Bundle.Run(ctx, addr)` / `Bundle.RunHandler(ctx, addr, handler)` do mount→serve→graceful-shutdown→`Close()` in one call (ReadHeaderTimeout 5s + IdleTimeout 60s, deliberately NO Read/Write timeouts — SSE-safe; ShutdownTimeout 30s via `context.WithoutCancel`). The dashboard is session-gated (401) like adminui. Config validation at `New` normalizes trailing slashes, rejects `/` (login page owns root) and colliding paths; custom `AdminPath`/`DashboardPath` are passed to panels as `BasePath` so internal links/HTMX targets match the mount. Health endpoint at `/health` checks projection status (readiness gate under `AsyncStartup`). Config options: SessionTTL, Logger, LogoutURL, SSEURL, OnProjectionFailed, AsyncStartup, DashboardReadOnly (default true), DashboardPageSize, LoginNoRegistration, HealthPath, AdminMode, TenantID, AdminAuthorizer, DashboardAuthorizer. Has its own README and `.golangci.yml` (adminui pattern). Uses direct identity-model imports for auth provider types. 57 tests, 89.5% coverage.
- **systemadapter** (`systemadapter/v4`): Bridge module for go-cqrs-lite's `system.New()` composition root + `metaengine` storage planner. Exports `DomainConfig()` (pre-wires all 4 deciders + 20 commands + 21 event TypeDecoder), `EventTypeDecoder()` (maps event types to payload structs for `projectionadapter`), and `NewProjectionLayer(sys)` (creates usermgmt read models, Casbin authz, audit log backed by the system's event store + bus; `WithCheckpointStore`/`WithDeadLetterStore` options). See `docs/guides/leveraging-system-metaengine.md`.
- **health** (`health/v4`): Optional bridge to the go-health ecosystem — `NewProbe(provider, opts...)` builds a `gohealth.Probe` with one named check per projection (live/stopped pass, drain transient, failed infrastructure — mirrors `ProjectionReadinessCheck`), `Recorder(provider)` merges projection checks with a samber/do injector's own service checks, `NewDashboard(probe, opts...)` returns the go-health-dashboard UI. Depends on root (v4.8.0, published) + go-health v0.0.2 + go-health-dashboard v0.3.0 — zero local replaces. Has its own README/`.golangci.yml`/`.cqrs-lint.json`. 100% coverage.
- **auditlog** (`auditlog/v4`): Optional bridge to samber-do-auditlog — `WithAuditLog(auditCfg, viewerCfg)` returns a `Setup` (do.InjectorOpts for `do.NewWithOpts`, plugin handle, live SSE viewer as http.Handler) in one call. Depends on samber-do-auditlog v0.9.2 + do/v2 + errorfamily — zero local replaces. Has its own README/`.golangci.yml`/`.cqrs-lint.json`. 100% coverage.
- **integration_test**: Cross-module bridge tests (incl. fullstack UI suite: seeded admin render, dashboard projection health, login auth-button matrix)
- **e2e/server**: Playwright E2E test server for offline-sync browser testing
- **examples/**: `basic`, `datastar-demo`, `catalog-demo`, `admin-demo`, `dashboard-demo`, `middleware-demo`, `middleware-showcase`, `observability-demo`, `samber-do-demo` (best-practice samber/do v2 DI wiring: composition root, lazy singletons, named auth providers, lifecycle adapter for `Service.Close()`, test container with `do.OverrideNamed`), `setup-demo` (one-call `setup.New` full-stack demo: dev-login seeds super_admin via the real authz path, e2e test asserts 401 gates + authenticated flow; imports identity-model directly — lint-clean, unlike older examples), `system-demo` (full `system.New()` integration with introspection, health checks, and projection layer)

**Dependency direction:** identity-model ← usermgmt (type aliases). Root → usermgmt is zero imports (clean boundary). Auth strategies → root/usermgmt via interfaces only. adminui/loginpage → root + usermgmt + templ-components. dashboardui → root + usermgmt + templ-components (icons). datastar → go-datastar + go-sse only (no root dep). systemadapter → usermgmt + identity-model + go-cqrs-lite system/metaengine. health → root types (published, see health/go.mod) + go-health/dashboard. auditlog → samber-do-auditlog + do/v2 (no cqrs-htmx dep). Nothing depends on adminui, loginpage, dashboardui, datastar, setup, systemadapter, health, or auditlog.

**Key dependencies:** go-cqrs-lite v4.6.0 (CQRS/event sourcing; workspace uses local master for unreleased ADR-0114/ADR-0111 API), casbin/v3 (authz), httputil (HTTP middleware: CSRF, Server-Timing, rate limiting), go-error-family (error classification), go-branded-id (typed IDs), go-sse v0.5.0 (SSE broadcaster, stream, replay), go-datastar (DataStar protocol library; local replace, unpublished), a-h/templ (HTML templating), ginkgo/gomega (BDD testing). `justinas/nosurf` and `golang.org/x/time` are now transitive deps via httputil (no longer direct root deps).

## Key Patterns

- **Library principle:** Never enforce defaults consumers might disagree with (no mandatory CSP/HSTS/CSRF — all opt-in)
- **No stdlib error constructors:** `errors.New`/`fmt.Errorf` banned in non-test code. Use `event.New*/Wrap*/Wrapf/Newf` from go-cqrs-lite.
- **Error families → HTTP status:** Rejection(400), Conflict(409), Transient(503), Corruption(500), Infrastructure(503)
- **Duck-typing for external libs:** `Enforcer` (← casbin), `TemplComponent` (← templ), auth provider interfaces — consumers import what they need
- **authMode enum:** `authNone`/`authRequired`/`authAuthorized` — impossible states unrepresentable
- **templ `_templ.go` committed:** Generated files are committed so consumers run no codegen
- **Coverage gate:** Root ≥90% (actual ~93% [WithActor resolved — verify coverage]), usermgmt ≥74% (actual ~81% [unverified]), identity-model ≥70% (actual ~75% [unverified]) (CI-enforced)
- **Projection lifecycle via projectionhost:** `StartProjections` uses `projectionhost.Host` from go-cqrs-lite — per-projection goroutines, per-projection checkpoint keys (by projection `Name()`), DLQ, crash-restart. Read-your-writes preserved via `waitForDrain`. Returns `(*projectionhost.Host, error)`; all setup structs and `Service` hold it and stop it on `Close()`. ADR-0031 (Superseded). Shared `startProjectionHost` factory used by both `StartProjections` and `RebuildProjection`.
- **Event catalog (Published Language):** `cqrshtmx.EventCatalog` + `EventCatalogHandler` serve event schemas as immutable JSON (1-year cache, FNV-1a ETag). `usermgmt.DefaultEventCatalog()` pre-registers all 21 events. `EventCatalog()` method on both `EventSourcedSetup` and `Service`.
- **Projection health monitoring:** `cqrshtmx.ProjectionStatusHandler(provider)` serves live projection status as JSON (`no-cache`, per-request ETag). `ProjectionStatusProvider` interface implemented by `*usermgmt.Service` and `*usermgmt.EventSourcedSetup`. See `docs/guides/projection-health-monitoring.md`.
- **Async projection startup (`AsyncStartup`):** `ServiceConfig.AsyncStartup` / `EventSourcedConfig.AsyncStartup` / `setup.Config.AsyncStartup` (all default `false` = backward-compatible synchronous drain). When `true`, `NewService`/`setup.New` returns immediately after `host.Start()` — the HTTP server binds while projections replay the journal in the background, eliminating multi-minute restart outages. `cqrshtmx.ProjectionReadinessCheck(provider)` is the readiness gate (returns 503 while any worker is `idle`/`running`/`backoff`/`draining`/`failed`, 200 when all are `live`/`stopped`); `setup.Bundle` mounts it at `/health` automatically. In async mode projection failures during drain surface via `ProjectionStatuses()`/`/health`/`OnProjectionFailed` — not as a `NewService` error. Mechanism: `startProjectionHost(..., block bool, ...)` skips `waitForDrain` when `block=false`. See `docs/guides/async-projection-startup.md`.
- **Projection rebuild:** `RebuildProjection(ctx, name)` on both `EventSourcedSetup` and `Service` — stops host, resets checkpoint + read-model, creates fresh host, replays journal. See `docs/guides/event-replay-and-rebuild.md` and `docs/guides/rebuild-projection-runbook.md`.
- **go-cqrs-lite leveraging (the #1 undocumented capability):** the `*command.Dispatcher`/`*query.Dispatcher` passed to `Config.Commands`/`Config.Queries` ARE go-cqrs-lite dispatchers — they implement `Use(mw ...)`, so all 27 factories from `go-cqrs-lite/middleware/v4` (logging, recovery, retry, circuit breaker, metrics, OTel tracing, validation, idempotency) compose with zero glue. This is strictly richer than `BeforeDispatchHook`/`AfterDispatchHook` (which only see the HTTP request, not the command type). Full capability-vs-usage map + recipes: `docs/guides/leveraging-go-cqrs-lite.md`. Runnable proof: `examples/middleware-demo/`. Underused upstream modules worth knowing: `middleware` (dispatch-level), `otel`+`prometheus` (observability), `scheduling` (durable timers — usermgmt expiry is currently in-process, not durable), `deriver` (reactive sagas), `schema.VersionedSeekableJournal` (store-layer upcasting for projections — identity-model only upcasts at decode time).

- **system/metaengine integration (systemadapter/ submodule):** The `systemadapter/` module bridges cqrs-htmx's identity-model domain (4 aggregates, 20 commands, 21 events) into go-cqrs-lite's `system.New()` composition root and `metaengine` storage planner. Three exports: `DomainConfig()` returns a pre-wired `system.DomainConfig` with all deciders + commands + TypeDecoder; `EventTypeDecoder()` maps all 21 event types to payload structs for `projectionadapter`; `NewProjectionLayer(sys)` creates usermgmt read models, Casbin authz, and audit log backed by the system's event store + bus. The usermgmt `system_exports.go` file exports 20 decide functions (`DecideRegisterUser`, `DecideCreateTenant`, etc.) needed for `system.Execute[State]()` declarative routing. go.work has replaces for system/v4, metaengine/v4, metaengine/sqliteengine/v4, metaengine/projectionadapter/v4, metaengine/pebbleengine/v4, metaengine/pgengine/v4, metaengine/duckdbengine/v4, and record/v4 (unreleased ADR-0114/ADR-0111 API, same reason as main go-cqrs-lite block). See `docs/guides/leveraging-system-metaengine.md` and `examples/system-demo/`.

## Gotchas

- **`GOEXPERIMENT=jsonv2` is mandatory:** Build fails without it. Never add depguard rules banning `encoding/json/v2`.
- **`PIPESTATUS` does not work in this shell (mvdan/sh):** `${PIPESTATUS[0]}` silently expands wrong and has printed `EXIT: 0` on a FAILED build. Always capture exit codes as `cmd > /tmp/f 2>&1; echo $?` — never through a pipe.
- **BuildFlow pre-commit can crash on nix eval-cache lock contention (exit 14, "SQLite database ... eval-cache ... is busy"):** blind-retrying the identical commit fails again. Documented fallback: `git commit --no-verify` WITH justification in the commit message, then re-verify HEAD (build + the gates covering the change). Only safe because the hook's other content checks (golangci etc.) ran green in the failed attempt — check the log before bypassing.
- **`adminui/styles.css` mutates on EVERY commit:** the hook's tailwind-build step regenerates the minified CSS with a trailing-newline diff regardless of staged files. Hand-revert with `git restore adminui/styles.css` after commits; always `git diff`-inspect the tree post-hook (styles.css is the known offender). Root fix is an open TODO.
- **Concurrent sessions share this tree:** an auto-git daemon (and sometimes a second agent session) commits dirty files wholesale — uncommitted work-in-progress can be absorbed into someone else's commit (happened 2026-08-15: a script edit landed inside the concurrent templ-components-bump commit). Commit promptly after verifying; re-check `git log`/`git status` before assuming attribution.
- **Dead-replace guard (check-replace-directives.sh):** every local replace target (go.mod AND go.work) must contain a `go.mod` — inside-repo targets fail hard everywhere (CI included); sibling targets outside the repo (e.g. `../go-cqrs-lite`) are skipped on CI runners (`CI=true`) and verified by the local `nix run .#check-modules` gate. Catches the ADR-0128 class (directories exist but lost their go.mod).
- **`ActorID` is consolidated (ADR-0111):** All three modules (root, identity-model, usermgmt) now alias `id.ActorID` from go-cqrs-lite. Supports 5 kinds: User, Bot, System, Service, Unknown. Use `id.NewUserActor(uid)` / `id.NewBotActor(raw)` / `id.NewSystemActor(name)` / `id.NewServiceActor(id)` for typed construction, or `ParseActorID("kind:raw")` (returns error) for parsing prefixed strings. The old `cqrshtmx.NewActorID(string)` is deleted.
- **WithActor integration (v4.x — go-cqrs-lite master 2026-08-13):** go-cqrs-lite now has `event.WithActor`, `command.WithActor`, and `query.WithActor` (all take `id.ActorID`). cqrs-htmx integrates this at three layers: (1) **Auto-derivation:** `ContextEnrichmentMiddleware` and `App.enrichUserID` automatically derive `ActorID` from `UserID` via `cqrshtmx.ActorIDFromUser(uid)` when extracting the user — no consumer code needed for the common case. Skipped if a consumer already set `ActorID` (e.g., impersonation middleware). (2) **Event propagation:** `EventOptionsFromContext` calls `event.WithActor(actorID)` (context.go) — the previous build break is resolved. (3) **Command/Query propagation:** `CommandOptionsFromContext(ctx)` and `QueryOptionsFromContext(ctx)` produce `command.Option`/`query.Option` slices (including `command.WithActor`/`query.WithActor`) — consumers call these in command/query decoders so dispatched commands/queries carry the same audit-trail metadata as events. `Dispatch(ctx, cmd)` does NOT accept options; metadata must be set at command construction time.
- **CSRF middleware ordering:** `Chain(CSRFMiddleware, HTMXMiddleware, app.Middleware())` — CSRF first.
- **`HandlerConfig.Secure` is `*bool`:** nil defaults to true. Use `new(bool)` for false.
- **Registration is email-only:** No password field. Auth is exclusively via WebAuthn passkeys.
- **UserID types are aliased:** Root defines `type UserID = id.UserID` and usermgmt aliases the same type — they interoperate directly, no bridging needed.
- **Module path casing:** go-cqrs-lite uses lowercase `github.com/larsartmann/go-cqrs-lite`.
- **go-cqrs-lite pseudo-version publish bug (FIXED 2026-08-11):** The original zero pseudo-version bug in go.mod files is RESOLVED — published tags (command/v4.4.0, event/v4.4.0, etc.) have clean go.mod files with real version references. Verified via hermetic GOWORK=off builds of all modules. Root currently uses: command/v4 v4.6.0, event/v4 v4.6.0, id/v4 v4.4.0, query/v4 v4.5.0, idempotency/v4 v4.4.0, storage/memory/v4 v4.3.0, snapshot/v4 v4.3.0 (indirect: codec/v4 v4.4.0, dispatcher/v4 v4.3.0, metadata/v4 v4.4.0, record/v4 v4.2.0 — each module rides its own version train; V006's lockstep assumption is suppressed in go.mod).
- **go.work local replaces (mostly historical — see push-plan):** go-cqrs-lite HAS published the ADR-0114/0111 API tags (event/command v4.6.0, query v4.5.0, id v4.4.0, record v4.2.0, metadata v4.4.0, system v4.4.0, metaengine v4.10.0) — hermetic per-module builds of root/usermgmt/dashboardui/etc. resolve them from the proxy without replaces. The go.work replaces remain for: `metaengine/projectionadapter` + `metaengine/sqliteengine` (unreleased APIs — tag mappings in `docs/runbooks/release-v4.8.0-push-plan.md` §3), the commandlifecycle pair (transitive via system/v4; published v4.0.0 may still call `.String()` on the reverted `CausationID`), and local-dev consistency (go-idempotency, server_timing). See the comment block in go.work.

- **`govalid-generate` GOCACHE race (root-caused + definitively fixed):** `buildflow` fans out `govalid ./...` across 18 workspace modules. govalid uses `go/packages.Load(NeedTypes)` which calls `go list -export`, compiling shared dependencies (encoding/json/v2, go-cqrs-lite modules, httputil) to `$GOCACHE`.
