# cqrs-htmx

> **THIS IS A LIBRARY/SDK — NOT AN APPLICATION.** Consumers import this package into THEIR projects.

Go library that makes it easy to use go-cqrs-lite with HTMX, templ, and Casbin authorization. Framework-agnostic — works with `net/http`, Gin, Chi, etc.

> **Orientation.** This is a Go **library**, not an application — consumers import it.

## Architecture

**Multi-module Go workspace.** 31 modules under one `go.work` (the `./` entries, root excluded):

- **Root** (`cqrs-htmx/v4`): HTTP handler builder, HTMX/SSE helpers, authz (Casbin), error mapping, pagination, `openapi/` (dependency-free OpenAPI 3.1 builder + `WithOpenAPI`/`OpenAPISpecHandler`), `transport/` (canonical SSE domain-event surface: `DomainEventToSSE` + `EventPayload` envelope + `NewJournalSSEStore` + `ServeDomainEvents` + `WithSSEFilter` + `WithSSEMaxReplay`; envelope bytes pinned by golden tests, drift = test failure), **frontend sync protocol (ADR-0056, 2026-10-09): `SyncPullHandler` (cursor + permission-filter + ETag event pull WITH payloads; delivery encoding is honest — `"opaque"`/`SyncPayloadEncodingOpaque` when a json stamp's bytes are invalid, the gotcha-24 third victim) + `App.SyncPushHandler` (batched push, per-command classified outcomes, replays registered pipelines via the internal `commandRegistry` — zero new registration surface) + sync assets v1.6.0 (pull cache, batch flush, cursor-monotonicity guard, IndexedDB v1→v2 upgrade pinned, `window.cqrsSync`)**; guide `docs/guides/frontend-sync.md`. CSRF, Server-Timing, and keyed rate limiting are thin re-exports over `httputil` (`_reexport.go` files, deprecated). **SSE-only — WebSocket transport removed in v5 (ADR 0046).**
- **Root-module packages (2026-11-02 decomposition):** `htmx/` (the HTMX protocol vocabulary — `Request`, swap strategies, all 18 `Header*` constants, embedded htmx.min.js + extension assets, script/extension handlers), `httperr/` (error family → HTTP status, RFC 9457 payload, every ready-made handler), `eventcatalog/` (the published event language — `Catalog`/`EventMetadata`/`Handler`), and `internal/hx/` (shared plumbing that breaks the cycle — JSON keys, `WriteAll`/`MarshalJSONForResponse`, immutable JSON serving + `HashTag`, the request-ID context key, `PanicCode`). Root used to keep the published API through `htmx_reexport.go`/`httperr_reexport.go`/`eventcatalog_reexport.go` (type/const/var aliases); since 2026-11-06 those aliases are **deprecated** — [ADR-0062](docs/adr/0062-direct-imports-only.md), v5 removal class 1b — and the subpackage is the surface: write `htmx.Target`, not `cqrshtmx.HTMXTarget`. `api_surface_compat_test.go` still compile-pins the re-exported contract so the v5 delete is a file delete rather than a consumer surprise, and root production code uses none of its own aliases (`nix run .#check-reexport-policy -- --strict`). Layering is one-way (`internal/hx` imports nothing in-module; `htmx`/`eventcatalog` → `internal/hx`; `httperr` → `htmx`+`internal/hx`; root → all) and enforced by `nix run .#check-module-layers`. Root production files 57 → 51, root-package LOC 8,121 → 7,325, public API unchanged. `sync`/`openapi` stay in root: they need `App` methods and the unexported `handlerConfig`, which Go forbids across packages — v5 material behind an ADR.
- **identity-model** (`identity-model/v4`): pure domain types — IDs (UserID/TenantID/BotID/ActorID), 33 event payload structs (28 lifecycle + 5 auth-audit, 2026-11-24 identity-merge wave), 27 commands (accessor methods, not field access), fold functions (FoldUser/FoldMembership/FoldTenant/FoldBot), state structs, Casbin-backed Authz engine, Session/User/Membership/ExternalAccount/WebAuthnCredential, crypto helpers, domain errors (errorfamily-only, no HTTP dependency), upcaster registry, exported constants. Casbin is a first-class dependency.
- **legalparty-model** (`legalparty-model/v4`): event-sourced **legal party** domain for billing (issue #45, 2026-11-20) — `LegalParty` aggregate (`LegalPartyOpened`/`ProfileUpdated`/`Closed`; closure is terminal and NEVER destructive: no delete event exists, GoBD tax retention), five-value `LegalFormClass` (not a bool; entity/partnership openers require a registry anchor), typed tax identifiers (`VATID` with the DE ISO 7064 Mod 11,10 checksum vs `TaxNumber`, prefix-less, VAT-shaped values rejected), ULID-branded `LegalPartyID`, `LEI` (ISO 17442 mod-97, vectors = two live GLEIF records), deciders with the bot-actor guard (`ErrBotActorForbidden`; user/system/service actors only), and opt-in registry enrichment ports `LEIResolver`/`RegisterResolver` implemented by the `gleif` (api.gleif.org/api/v1/lei-records, no key, 60/min, 404/429 are HTML → branch on status; register lookup = exact-match `filter[entity.registeredAs]`) and `opencorporates` (X-API-TOKEN header, 403 = rate limit, German records keep the full address in street_address so the typed address only fills when locality exists; **ODbL attribution is mandatory** — `RegistryFacts.SourceURL` carries the link) packages. Facts never mutate an aggregate on their own: consumers apply them through `DecideUpdateLegalPartyProfile` with provenance riding the event. Depends on identity-model only (ActorID guard + Email reuse). Named `legalparty-model` because `billing-model` is reserved by the Stripe plan of record (M03/M23 vocabulary gate). Payloads are NESTED (`Profile LegalPartyProfile`, whole-profile replace — deliberate divergence from identity-model's flat payloads, documented in its README); `.cqrs-lint.json` carries seven dated disables (F032/B026/E004 catalog-adoption family, E005 handlerless-declarations, C013 time.Time payloads, S006 encryption-at-consumer, F005 upcasters-land-with-v2). Coverage row 80 (measured 83.9).
- **usermgmt** (`usermgmt/v4`): event-sourced CQRS user management — thin re-export layer over identity-model (type/var aliases + constructor wrappers) plus infrastructure (HTTP handlers, SQL stores with SQLite/Postgres/MySQL dialects, session middleware, read models, CasbinProjection, decide/dispatch). Auth via WebAuthn/TOTP/OAuth2 behind interfaces. **Composition (ADR-0038, executing since 2026-11-28):** `Service` embeds the focused sub-services BY VALUE (`BotService`, `TenantService`); promotion keeps `svc.RegisterBot(...)` working while `svc.BotService.RegisterBot(...)` names the owner. A new aggregate method goes on the sub-service that owns the aggregate, never on `*Service` (which keeps only shared infrastructure): `scripts/checks/check-service-methods.sh` — in `check-modules` + CI — caps `*Service` at 85 (75 now; it crossed at 96 on 2026-11-27) and every `*XService` at 30, and `TestService_ExportedAPISurface` pins the exported method set of `*Service` (`-update` only for a deliberate API change).
- **usermgmt/totp**, **usermgmt/webauthn**, **usermgmt/oauth2**: independent auth-strategy modules satisfying usermgmt interfaces via structural typing. oauth2 supports public (secret-less) PKCE clients (`ProviderConfig.ClientType`) and `FinishLoginWithToken` (raw ID token).
- **adminui**: ready-made admin dashboard (templ + HTMX) over a `*usermgmt.Service` — identity ops (users, tenants, members, audit log), write actions, role-gated, user-controllable theme toggle. "admin" = user administration; event-store introspection is dashboardui (cross-linked in both READMEs).
- **loginpage**: ready-made passwordless login page (built on templ-components since 2026-10-04 — `layout.Base`/`forms.Input`/`display.Button`/`feedback.Alert`, Tailwind-only styling, consumer-compiled CSS + CSP-nonce/cookie-theme hooks).
- **datastar**: optional DataStar adapter — script serving, signal decoding, SSE response builder (signal constructors return `(Patch, error)`), EventBridge with `OnError`. The Broadcaster lives upstream in `go-datastar/broadcast`; this module keeps deprecated alias shims until v5. Depends on go-datastar + go-sse only (no root dep). Guides: `docs/guides/datastar-integration.md`, `docs/guides/sse-and-datastar.md`.
- **huma**: optional **Huma v2 adapter** (cqrs-htmx#41 demand signal, 2026-11-06) — registers typed OpenAPI operations and runs the SAME pipeline stages the route builder runs: authorize → build → validate → guard → dispatch, with the same RFC 9457 problem document (`ProblemError` embeds `httperr.StructuredError`, `application/problem+json`, shared `code`). Huma keeps decode, input validation, status codes and schema generation (a test asserts `ErrorModel` still owns the spec's error responses). Config takes the dispatchers + a `cqrshtmx.PermissionChecker` (identity-model's `Authz` satisfies it structurally, so root still imports no engine); options `Authorize`/`AuthorizeIn`/`AuthorizeOn[I]`/`RequireAuth`/`ValidateCommand`/`ValidateQuery`/`Guard`/`WithTimeout`; stages exported for raw handlers (`Authorize`, `DispatchCommand`, `DispatchQuery`, `MapError`). Two deliberate divergences from the route pipeline, both documented: no `BeforeDispatch`/`AfterDispatch` hooks (they take an `*http.Request` a Huma handler never sees) and no decode/render/HTMX options (Huma owns those). Pins root **v4.16.0** and needs no root change — the adapter composes published API (`Decide`/`UserIDFromContext`/`CommandOptionsFromContext`), so hermetic builds were green on day one instead of waiting for a root tag (the gotcha-30 class). Guide: `docs/guides/fullstack-wiring.md` § OpenAPI-first APIs; module `huma/README.md`.
- **dashboardui**: ready-made CQRS/ES observability dashboard — projection health, event catalog, SSE live updates, time-travel. `startEventBridge` fails `New` on `SubscribeAll` error (fail-fast); `Config.SSEMaxReplay` caps first-connect backfill; SSE handler delegates to `transport.ServeDomainEvents`; CORS same-origin by default (wrap with `httputil.CORS` for cross-origin). Full templ rendering (2026-09-22 migration from the former strings.Builder hybrid — 9 `.templ` files, generated `_templ.go` committed); pure-data `core/` sub-package bridged via aliases; CSP-safe (no inline handlers). **Integration modes (2026-10-04):** `Autodetect(store)` probes all capability interfaces → ready Config (kills the consumer assertion dance); `Config.Layout` (`LayoutFunc` + exported `PageMeta`/`NavLink`) replaces the built-in page shell with a consumer-owned document so panels render inside the consumer's app chrome — the embed answer to the 2026-08-05 DiscordSync "two apps bolted together" audit; HTMX partials bypass the shell; error/404 pages keep the built-in shell; `setup.Config.DashboardLayout` passes the seam through; README § Integration Modes is the consumer doc. **Consumer nav (cqrs-htmx#38):** `Config.ExtraNav []NavEntry` appends consumer entries after the capability items in both the built-in sidebar and `PageMeta.Nav`; their `Href` renders verbatim (never BasePath-prefixed) so a surface mounted next door stays one click away, `NavLink.Verbatim` carries that contract to custom layouts, an in-panel extra entry still gets `Active`, and `setup.Config.DashboardExtraNav` threads the knob through the bundle (adminui's `AdminExtraNav` is the sibling seam).
- **setup**: optional one-call composition root — `setup.New(Config) (*Bundle, error)`; `Mount`/`Handler`/`Run`/`RunHandler`/`RunWithAppkit` (Run paths deliberately have no Read/Write timeouts — SSE-safe). Session-gated dashboard + `/health` readiness gate under `AsyncStartup`; scoped shared feed via `SSEFilter`. Full config surface: `setup/README.md` (the canonical table).
- **systemadapter**: bridge to go-cqrs-lite's `system.New()` + `metaengine` — `DomainConfig()` (4 deciders + 21 commands + 27-event TypeDecoder), `EventTypeDecoder()`, `NewProjectionLayer(sys)` (deprecated — ADR-0051; declarative path canonical, checkpoint/DLQ limitation documented in `docs/guides/declarative-projections.md`). Guide: `docs/guides/leveraging-system-metaengine.md`.

## Key Patterns

- **Library principle:** never enforce defaults consumers might disagree with (no mandatory CSP/HSTS/CSRF — all opt-in).
- **Direct imports only (ADR-0062, 2026-11-06):** a cross-package alias is never a permanent API. A move ships repointed consumers, not a shim; a compatibility alias must carry `// Deprecated:` naming the owning import path and its removal release; there is exactly ONE breaking window per major version (v5 is this generation's). Four exemption classes exist and must be argued in the ADR. The gate — not the convention — is what keeps it monotone: without `check-reexport-policy` the next extraction re-creates the façade, which is exactly how the 2026-11-02 split shipped 336 LOC of aliases labelled "not deprecated".
- **No stdlib error constructors:** `errors.New`/`fmt.Errorf` banned in non-test code; every error is built with `github.com/larsartmann/go-error-family` (`errorfamily.NewRejection`/`NewConflict`/`NewTransient`/`WrapInfrastructure`/`Wrapf(err, event.Conflict, code, msg)`; wrap a dispatch error with `errorfamily.Classify(err)` so its family survives). `go-cqrs-lite/event/v4` re-exposes only the family constants (`event.Rejection`, ...) — it has NO `New*`/`Wrap*` constructors (the skill taught `event.NewRejection` until 2026-11-28; `check-skill-claims` cannot see non-`cqrshtmx.` symbols). Error families → HTTP status: Rejection(400), Conflict(409), Transient(503), Corruption(500), Infrastructure(503); a 404 needs `httperr.WithHTTPStatus` (no NotFound family).
- **Duck-typing for external libs:** `Enforcer` (← casbin), `TemplComponent` (← templ), auth provider interfaces — consumers import what they need.
- **authMode enum:** `authNone`/`authRequired`/`authAuthorized` — impossible states unrepresentable.
- **Authorization contract + durable grants (ADR-0057, 2026-11-02):** `cqrshtmx.Request{Subject, Domain, Resource{Type,ID}, Action}` + `Decide(PermissionChecker, Request) (Decision, error)` is the ONE decision surface; `Decision.Reason` separates `allowed` / `denied_by_policy` / `no_matching_policy` / `not_authenticated`, and an engine failure is an error (503), never a silent denial. `PermissionChecker` is primitive-shaped so `identitymodel.Authz.Check` satisfies it structurally — root still imports no Casbin, identity-model still imports no HTTP; the compile-time assertion lives in usermgmt (the only module seeing both). `Service.GrantRoles`/`RevokeRoles`/`HasAdminGrant` are the durable write path (membership commands → event → projection replay); `Authz.AddGroupPolicy` is DEPRECATED in v4 (ephemeral, gotcha 45) with `Authz.ApplyGroupPolicy` as the projection-only seam. `EnforceIn` is the shipped 4-arg shape (`Enforce` keeps 3 args + wildcard domain and falls back on a request-size mismatch — the 403-not-503 fix). Five rules hold it together: (1) two invariants — a query never returns a templ component, a component never dispatches; (2) out-of-band views ride FRAGMENT responses only, never a page render; (3) selection is request-derived and fail-loud for free — an `HX-Target` no region matches is a `400 unroutable_view` answered BEFORE any loader runs, and the rejection lists what would have matched; never fall back to the page (a whole document swapped into a fragment target is the 2026-10-18 blanking class from the other direction) — a page that wants it says so with a `Default` region; (4) response parity — `Trigger`/`Notify*`/`PushURL`/`Redirect` apply exactly as on `App.Query` (headers first, a non-HTMX redirect terminal) because "HandlerOption is HandlerOption"; (5) loaders are loader-agnostic and a nil result applies the zero value — nothing is skipped silently. `LoadScopeFor(r)` is the single page-or-fragment decision that both the scheduler and the view selector call. ## Benchmarks

Every serious comparison uses `b.Loop()` (Go 1.24+) + `b.ReportAllocs()` + `b.ReportMetric(req/s)` + benchstat (`-benchtime=2s -count=5`), with `b.Cleanup` stopping timers before server drain. Suppress per-request logging in benches (`appkit.LogLevelError`, or pin `slog.SetDefault(slog.New(slog.DiscardHandler))` for the sub-bench + restore on cleanup) — skipping this makes log lines the dominant measurement. One-off `time.Since` blocks in tests are forbidden — they belong in `*_bench_test.go`. Canonical pattern: `setup/run_appkit_test.go:BenchmarkSpikeBaselineVsAppkit`. The machine-pinned raw baseline (`docs/benchmarks/setup-baseline.raw.txt`) is the ONLY gate-comparable artifact; human markdown records are not comparable.
