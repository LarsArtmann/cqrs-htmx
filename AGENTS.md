# cqrs-htmx

> **THIS IS A LIBRARY/SDK — NOT AN APPLICATION.** Consumers import this package into THEIR projects.

Go library that makes it easy to use go-cqrs-lite with HTMX, templ, and Casbin authorization. Framework-agnostic — works with `net/http`, Gin, Chi, etc.

> **Long-form notes:** dated histories, incident narratives, and version-drift war stories live in [`docs/agents-notes.md`](docs/agents-notes.md) (the verbatim archive of this file's former 120 KB self). This file is the distilled, enduring core — when they disagree, this file and the tree win.

## Architecture

**Multi-module Go workspace.** 28 modules under one `go.work`:

- **Root** (`cqrs-htmx/v4`): HTTP handler builder, HTMX/SSE helpers, authz (Casbin), error mapping, pagination, `openapi/` (dependency-free OpenAPI 3.1 builder + `WithOpenAPI`/`OpenAPISpecHandler`), `transport/` (canonical SSE domain-event surface: `DomainEventToSSE` + `EventPayload` envelope + `NewJournalSSEStore` + `ServeDomainEvents` + `WithSSEFilter` + `WithSSEMaxReplay`; envelope bytes pinned by golden tests, drift = test failure). CSRF, Server-Timing, and keyed rate limiting are thin re-exports over `httputil` (`_reexport.go` files, deprecated). **SSE-only — WebSocket transport removed in v5 (ADR 0046).**
- **identity-model** (`identity-model/v4`): pure domain types — IDs (UserID/TenantID/BotID/ActorID), 21 event payload structs, 20 commands (accessor methods, not field access), fold functions (FoldUser/FoldMembership/FoldTenant/FoldBot), state structs, Casbin-backed Authz engine, Session/User/Membership/ExternalAccount/WebAuthnCredential, crypto helpers, domain errors (errorfamily-only, no HTTP dependency), upcaster registry, exported constants. Casbin is a first-class dependency.
- **usermgmt** (`usermgmt/v4`): event-sourced CQRS user management — thin re-export layer over identity-model (type/var aliases + constructor wrappers) plus infrastructure (HTTP handlers, SQL stores with SQLite/Postgres/MySQL dialects, session middleware, read models, CasbinProjection, decide/dispatch). Auth via WebAuthn/TOTP/OAuth2 behind interfaces.
- **usermgmt/totp**, **usermgmt/webauthn**, **usermgmt/oauth2**: independent auth-strategy modules satisfying usermgmt interfaces via structural typing. oauth2 supports public (secret-less) PKCE clients (`ProviderConfig.ClientType`) and `FinishLoginWithToken` (raw ID token).
- **adminui**: ready-made admin dashboard (templ + HTMX) over a `*usermgmt.Service` — identity ops (users, tenants, members, audit log), write actions, role-gated, user-controllable theme toggle. "admin" = user administration; event-store introspection is dashboardui (cross-linked in both READMEs).
- **loginpage**: ready-made passwordless login page (hand-rolled `lp-*` CSS, no templ-components).
- **datastar**: optional DataStar adapter — script serving, signal decoding, SSE response builder (signal constructors return `(Patch, error)`), EventBridge with `OnError`. The Broadcaster lives upstream in `go-datastar/broadcast`; this module keeps deprecated alias shims until v5. Depends on go-datastar + go-sse only (no root dep). Guides: `docs/guides/datastar-integration.md`, `docs/guides/sse-and-datastar.md`.
- **dashboardui**: ready-made CQRS/ES observability dashboard — projection health, event catalog, SSE live updates, time-travel. `startEventBridge` fails `New` on `SubscribeAll` error (fail-fast); `Config.SSEMaxReplay` caps first-connect backfill; SSE handler delegates to `transport.ServeDomainEvents`; CORS same-origin by default (wrap with `httputil.CORS` for cross-origin). Full templ rendering (2026-09-22 migration from the former strings.Builder hybrid — 9 `.templ` files, generated `_templ.go` committed); pure-data `core/` sub-package bridged via aliases; CSP-safe (no inline handlers).
- **setup**: optional one-call composition root — `setup.New(Config) (*Bundle, error)`; `Mount`/`Handler`/`Run`/`RunHandler`/`RunWithAppkit` (Run paths deliberately have no Read/Write timeouts — SSE-safe). Session-gated dashboard + `/health` readiness gate under `AsyncStartup`; scoped shared feed via `SSEFilter`. Full config surface: `setup/README.md` (the canonical table).
- **systemadapter**: bridge to go-cqrs-lite's `system.New()` + `metaengine` — `DomainConfig()` (4 deciders + 20 commands + 21-event TypeDecoder), `EventTypeDecoder()`, `NewProjectionLayer(sys)` (deprecated — ADR-0051; declarative path canonical, checkpoint/DLQ limitation documented in `docs/guides/declarative-projections.md`). Guide: `docs/guides/leveraging-system-metaengine.md`.
- **health**: bridge to go-health — `NewProbe` (per-projection checks), `Recorder` (merge with samber/do injector checks), `NewDashboard`. Own README/`.golangci.yml`/`.cqrs-lint.json`. 100% coverage.
- **auditlog**: bridge to samber-do-auditlog — `WithAuditLog(auditCfg, viewerCfg)` returns a `Setup` (do.InjectorOpts) with a live SSE viewer handler. Zero cqrs-htmx deps. Own README/configs. 100% coverage.
- **integration_test**, **e2e/server**, **examples/** (12 demos — `setup-demo` one-call full-stack, `system-demo` system.New integration, `samber-do-demo` DI best practice, `middleware-demo`/`observability-demo` OTel+metrics proofs, etc.).

**Dependency direction:** identity-model ← usermgmt (aliases). Root → usermgmt is zero imports (clean boundary). Auth strategies → root/usermgmt via interfaces only. adminui/loginpage/dashboardui → root + usermgmt (+ templ-components). datastar → go-datastar/go-sse only. systemadapter → usermgmt + identity-model + go-cqrs-lite system/metaengine. Nothing depends on adminui, loginpage, dashboardui, datastar, setup, systemadapter, health, or auditlog.

**Key dependencies:** go-cqrs-lite (per-module version trains — NOT lockstep; current pins in go.mod), casbin/v3, httputil (HTTP middleware: CSRF core, Server-Timing, rate limiting, CORS/Compression/body limits — see `docs/guides/leveraging-httputil.md`), go-error-family, go-branded-id, go-sse, go-datastar + go-datastar/broadcast, a-h/templ (generated `_templ.go` committed so consumers run no codegen), ginkgo/gomega (BDD testing).

## Key Patterns

- **Library principle:** never enforce defaults consumers might disagree with (no mandatory CSP/HSTS/CSRF — all opt-in).
- **No stdlib error constructors:** `errors.New`/`fmt.Errorf` banned in non-test code; use `event.New*/Wrap*/Wrapf/Newf` from go-cqrs-lite. Error families → HTTP status: Rejection(400), Conflict(409), Transient(503), Corruption(500), Infrastructure(503).
- **Duck-typing for external libs:** `Enforcer` (← casbin), `TemplComponent` (← templ), auth provider interfaces — consumers import what they need.
- **authMode enum:** `authNone`/`authRequired`/`authAuthorized` — impossible states unrepresentable.
- **Projection lifecycle via projectionhost:** per-projection goroutines, per-projection checkpoint keys (`Name()`), DLQ, crash-restart, read-your-writes via `waitForDrain`. `AsyncStartup` (opt-in) returns before drain — failures surface via `ProjectionStatuses()`/`/health`/`OnProjectionFailed`, not as a `NewService` error; `cqrshtmx.ProjectionReadinessCheck` is the readiness gate. `RebuildProjection(ctx, name)` swaps in a fresh host (projectionhost hosts are one-shot). Guide: `docs/guides/async-projection-startup.md`, `docs/guides/event-replay-and-rebuild.md`.
- **Checkpointed restarts via SQL hydrate:** `CheckpointStore` + SQL read models rebuild in-memory state before the host starts; `hydrationAwareCheckpointStore` (applied by the shared `startProjectionHost` factory) forces casbin-projection + the default in-memory AuditLog to full-replay, so authz policies and the audit trail stay complete after restarts. Append handlers are idempotent (at-least-once convergence); `MemberAdded.AddedAt` uses event time. TOTP secrets persist in `users_view.data` — rows written by pre-hydrate versions lack the secret: run `RebuildProjection(ctx, "user-read-model")` once after upgrading an existing SQL read model, or affected TOTP users re-enroll.
- **go-cqrs-lite is richer than the hooks:** the `*command.Dispatcher`/`*query.Dispatcher` passed to `Config.Commands`/`Config.Queries` implement `Use(mw ...)` — all 27 factories from `go-cqrs-lite/middleware/v4` (logging, recovery, retry, circuit breaker, metrics, OTel, validation, idempotency) compose with zero glue. Capability map + recipes: `docs/guides/leveraging-go-cqrs-lite.md`; runnable proofs in `examples/middleware-demo` + `examples/observability-demo`.
- **OTel posture:** the library is otel-free by design (verify: `rg -l go.opentelemetry.io root/ usermgmt/ setup/` finds nothing outside go.mod/go.sum). go-cqrs-lite's decider/storage layers emit spans via the GLOBAL tracer — one `cqrsotel.Setup()` call auto-traces the entire identity domain. Canonical doc: `docs/guides/leveraging-go-cqrs-lite.md` §2 (the older `docs/observability-wiring.md` is SUPERSEDED). `setup.Config.Observability` accepts an upstream `*middleware.OTelBundle`.
- **Event catalog (Published Language):** `cqrshtmx.EventCatalog` + `EventCatalogHandler` serve event schemas as immutable JSON (1-year cache, FNV-1a ETag); `usermgmt.DefaultEventCatalog()` pre-registers all 21 events. Guide: `docs/guides/event-catalog-guide.md`.
- **Actor/audit chain is built-in:** `NewService` wires `commandAuditMiddleware()` (session→actor bridge, upstream `middleware.CommandActorContext()`, causation) onto the single dispatcher, and `repositoryOptions` composes `event.ActorEnricher` + `requestContextEnricher` (correlation/request-ID) + `event.CommandCausalityEnricher` — every dispatched command emits attributed events with zero consumer code. E2E: `integration_test/actor_attribution_test.go`. `ServiceConfig.CommandMiddleware` is the consumer seam (applied INSIDE the chain); `Service.Dispatcher()` is deliberately NOT exported (lifetime + chain-integrity hazard).
- **Context enrichment uses structural interfaces:** root's enrichment asserts `commandOptionApplier`/`queryOptionApplier` (`ApplyOptions`), never concrete wrapper types — embedding promotes the interface through every command wrapper. The 20-command bijection (`Cmd*` constants ↔ `RegisterTyped`) is mechanically enforced by `scripts/check-command-bijection.sh`.
- **WithActor integration:** `ContextEnrichmentMiddleware` auto-derives `ActorID` from `UserID` (never overrides a consumer-set actor); `EventOptionsFromContext`/`CommandOptionsFromContext`/`QueryOptionsFromContext` propagate actor/correlation metadata. `Dispatch(ctx, cmd)` does NOT take options — metadata is set at construction.

## templ-components (family of 5 modules — current train in go.mod)

adminui + dashboardui depend on it; loginpage does not. Before hand-rolling any UI element, check the library first (110+ components across 10 packages). Enduring gotchas learned here:

- **Rebuild the CSS bundles in the SAME change as any family bump** (`nix run .#build-adminui-css` / `.#build-dashboardui-css`) — the compiled bundle captures the era's class set; a stale bundle ships missing utilities. The buildflow hook may rewrite the bundles WITHOUT `--minify`; re-run the flake builders and commit the minified form (class sets identical, formatting-only). `nix run .#check-css-bundles` (gated in `check-modules` + CI since 2026-09-23) enforces the canonical form: 1-line minified, banner header, byte floor, canary utilities — it catches the hook-rewrite class AND the near-empty staged-bundle incident (2026-09-22 ~13:05).
- **Set `BaseProps.ID` on every library component the JS/tests target** — `EnsureID` randomizes un-pinned IDs (keep DOM hooks stable across regenerations).
- **Table-fragment contract:** partials for `hx-swap=innerHTML` targets contain rows but NOT the wrapper; polled-region partials re-render the REGION itself (outerHTML contract — bare children would kill polling after one refresh).
- **CSP:** inline `--tc-sidebar-w` style attributes are dropped by nonce CSP — redefine in consumer CSS; the library's popover/dialog CSS and dark-surface classes may need vendoring into the consumer's compiled CSS (the library's own bundle never loads in these modules).
- **Dark-mode surfaces:** if the consumer's `@theme` remaps gray-800/900 (e.g. to `--text`), pin them back to literal darks in dark mode — library `dark:` variants assume literal darks (all library `text-gray-800/900` occurrences carry `dark:` overrides, so the pin is safe). Dark mode itself is CLASS-driven in both UI modules (adminui + dashboardui, 2026-09-23): `@custom-variant dark` + `html.dark` tokens + `layout.ThemeScript`/`ThemeToggle`; the old media-query token flip is gone (no-JS degrades to light).
- **Hybrid (strings.Builder) rendering:** templ `{children...}` renders EMPTY in the hybrid path — use props-based components or the `templ.WithChildren(ctx, child)` escape hatch (v1.19.1); `display.Grid`/`htmx.PolledRegion` need a real templ path. Ends here: dashboardui converted to full templ (2026-09-22); no remaining repo consumer renders library components through strings.Builder.
- **loginpage adoption opportunities:** `recipes.AuthLayout`, `forms.Input`/`forms.Form`, `feedback.Alert`, `display.Button`.
- **Adoption inventory:** the grep-able adopted/custom/divergent table lives in `dashboardui/README.md` (§ Styling and templ-components Adoption); audit series in `docs/research/2026-09-{17,23}_templ-components-deep-dive.html` with the comparable rubric in the 09-23 report §06.

## Gotchas

1. **`GOEXPERIMENT=jsonv2` is mandatory** (build fails without it; never add depguard rules banning `encoding/json/v2`). Manual Go commands outside the devShell also need the 1.27.1 toolchain — `scripts/lib/go-cache-env.sh` (sourced by gates and the pre-commit hook) auto-aligns `GOTOOLCHAIN` to the go.work floor; the toolchain resolves from the local module cache.
2. **`go build ./...` does NOT compile `_test.go` files** — make `go vet ./...` part of every verification pass; run `GOWORK=off go build ./...` (+ tidy + vet) per-module after go.mod changes (workspace mode masks hermetic breakage).
3. **Shell traps (proven repeatedly):** `PIPESTATUS` breaks in mvdan/sh — capture `cmd > /tmp/f 2>&1; echo $?`, never through pipes (`cmd | tail; echo $?` reports tail's rc); `set -e` does not abort on `grep -q && …` lists — use explicit `rc=$?` checks in multi-module batch loops, never `set -e`; a redirect to a path with a slash in a variable silently skips the command (the `/tmp/sweep-e2e/server.log` class); after version sweeps assert ABSENCE (`grep -rE 'stale-pattern' --include=go.mod` expecting zero), don't sample presence; use unique `/tmp/<repo>-<purpose>-$$-$(date +%s).log` paths — concurrent sessions share /tmp; process substitution `<(...)` is unreliable under mvdan/sh — a `cmp file <(git show HEAD:f)` returned a false EQUAL against differing content (2026-09-22), materialize to a temp file and compare files instead.
4. **Commit at phase boundaries, never at the end** — the auto-commit daemon polls faster than a long verification tail and shreds batched work into heuristic `chore: auto-commit` commits. Verify → commit → next phase. Concurrent sessions share this tree: re-check `git log`/`git status` before assuming attribution; never revert diffs you didn't author (another session made them intentionally). The mechanical guard is `nix run .#preflight-tree-check` (abort-on-surprise before ANY tree-mutating batch step: dirty tree / fresh non-daemon commit / commit-velocity burst — daemon commits are exempt churn) and `nix run .#wait-tree-quiet` (block until clean tree + stable HEAD for a full window, before push retries or release trains); both carry fixture self-tests inside `check-modules` + CI (added 2026-09-22). No tree-mutating verification inside a foreign repo's in-flight release train (the 2026-09-22 templ-components tidy-interference lesson: `go mod tidy` reverted a concurrent session's version pins mid-verify).
5. **NEVER tag a module whose go.mod edits are uncommitted** — always tag via `scripts/verify-tag.sh <module-dir> <version> [--push]`, never raw `git tag` (enforces committed tree, no family dev-replaces/unpublished internal requires, post-push ls-remote). Never re-push a version at a different commit (proxy caches poison it). The `larsartmann/*` repos are PUBLIC — anonymous `git ls-remote` works; CI runners can run the release-train gate.
6. **Release trains:** every internal require must resolve to a PUBLISHED tag (UNPUBLISHED = hard fail — a phantom require poisons the WHOLE workspace module graph; workspace mode masks it forever). Prefer wave-ordered cuts (each commit's requires point at already-published tags — zero `--no-verify`; codified in `docs/guides/release-playbook.md` §3a). A mid-train bump commit fails the pre-commit gate by design; documented fallback: `git commit --no-verify` WITH justification, after independent verification. CI enforces `check-release-train --strict-lag 0` — and since 2026-09-22 the LOCAL script defaults to those exact CI flags too (`--advisory` restores planning mode; the pre-commit hook runs `--advisory` deliberately so lag cannot brick intra-train commits or the auto-commit daemon), with the pre-push hook enforcing the strict flags at the push boundary. The advisory/strict split brain that reddened CI on 2026-09-22 is dead.
7. **nolint directives must survive golines:** a trailing `//nolint:<linter> // reason` only applies while its line stays ≤120 chars INCLUDING the reason — keep reasons short or hoist to its own line. `exhaustruct` → `exhaustruct_v5` rename (golangci 2.13): directives MUST name `exhaustruct_v5`. `exhaustruct_v5` PANICS on promoted-key struct literals (Go 1.27 `modernize` embedlit rewrites) — keep explicit nested `BaseProps: utils.BaseProps{...}` form behind `//nolint:modernize`.
8. **The ACTIVE pre-commit hook is at `.githooks/pre-commit`** (global `core.hooksPath=.githooks`), NOT `.git/hooks/`. Template of truth: `scripts/hooks/pre-commit.template`; after ANY `buildflow precommit install` regeneration, run `scripts/install-git-hooks.sh --force` (self-test: `scripts/test-install-git-hooks.sh`). BuildFlow's `--fix` can re-break intentional patterns (fatcontext `captured := ctx` captures, dupword SSE `data:` prefixes) — those lines carry `//nolint` directives with reasons; NEVER run `golangci-lint run --fix` repo-wide; fallback: `git commit --no-verify` + justification, or `git restore` the fixer damage. BuildFlow pre-commit can crash on nix eval-cache lock contention (exit 14, "eval-cache busy") — retrying the identical commit fails again; use the documented fallback. Its remaining bare-shell step failures are DETERMINISTIC environment-class, not transient (diagnosed 2026-09-22): `tsc` without any tsconfig (Go repo), `go-licenses` only exists in the devShell, `govulncheck` package-pattern errors, `samber-linter` ~90% historical failure rate — treat as noise from a non-devShell, independently verify content, and use the `--no-verify` fallback with the step names in the message. Findings gate is `fail_on: none` (triaged; restoration conditions in `.buildflow.yml` comments).
9. **`adminui/styles.css` + `dashboardui/styles.css` are ORPHAN buildflow outputs** — never served (the modules embed `assets/*-tw.css` served at `/-/admin-tw.css` / `/-/dashboard-tw.css`), never hand-revert them, never consume them; verify visual changes against the embedded artifacts.
10. **Formatter division of labor:** treefmt (`nix fmt`) is canonical (golines 120, shfmt 2-space, shellcheck, gofmt, nixfmt, dprint/prettier for md/json); BuildFlow pre-commit formats STAGED files only — no double-format fight. `templ generate` must run from the MODULE dir (bare `FileName:` fields are canonical; repo-root runs emit path-prefixed form and the two FIGHT inside one hook run) — `nix run .#gen` / `.#check-codegen` verify module-canonical form; NEVER regenerate from the repo root. A buildflow "no-op" label does NOT mean output matched (it still runs and mutates).
11. **`go.work` is TRACKED** (CI checkouts need it; every go.work-dependent gate silently false-greens — zero iterations — when it's missing). `go.work.sum` stays untracked. `GOWORK=off` for per-module go.mod commands. `forEachGoModule` flake apps (`build`/`test`/`coverage`/…) auto-discover modules from go.work — no manual list updates; `lint` excludes e2e/examples; `coverage-gate`/`errorfamily`/`check-cqrs-lint` use hardcoded lists (new modules need manual adds there + possibly CI).
12. **Go caches live on `/mnt/buildcache` (failure history)** — when EVERY gate fails uniformly with `failed to initialize build cache`, check `df -h /mnt/buildcache` first; fallback layout: `GOCACHE=/tmp/go-build-cache GOMODCACHE=/tmp/go-mod-cache GOLANGCI_LINT_CACHE=/tmp/golangci-cache` (mkdir first; `go-cache-env.sh` automates fallback + low-disk fail-fast — NOTE: as of 2026-09-22 the disk is 100% FULL (rust/ 155G + sccache/ 20G dominate; the Go caches are ~12G), so the /tmp fallback is the de-facto session layout until someone reclaims space; buildflow lint steps also need `GOLANGCI_LINT_CACHE` pointed at /tmp or they die with "no space left on device" — RESOLVED same day ~13:00 (164–169G free again, reclaimed by a concurrent session; the fill-drain cycle recurs, so still `df -h` first)). Playwright browsers/ffmpeg cache there too (`PLAYWRIGHT_BROWSERS_PATH=/tmp/pw-browsers` fallback after a one-time install). **VCS-cache corruption class:** `GOPRIVATE` family deps resolve via `git ls-remote` inside `/mnt/buildcache/go-mod/cache/vcs/*/` bare repos — an entry that loses its `origin` remote breaks hermetic builds with load-error-shaped failures (`invalid package name: ""`); repair with `git -C <vcs-dir> remote add origin https://github.com/larsartmann/<repo>.git` — or just run `bash scripts/check-vcs-cache.sh` (gated in `check-modules` + CI since 2026-09-22; prints the exact repair command). `go env -w` CANNOT repoint caches (`~/.config/go/env` is read-only).
13. **cqrs-lint:** ensure `go build ./...` passes before trusting output (old versions silently report "No Go files found" on broken builds). Suppression: `//cqrs-lint:ignore(RULE) reason` — parser checks the finding's own line + first non-blank line above; end-of-line works (v4.6.0+); comma-separated rules OK; block `ignore-start/end` for ranges; module-level findings take a comment in `go.mod`; package-level take the line above `package`. gofmt's space-after-`//` is normalized (both forms accepted) but a BLANK line between suppression and declaration breaks it. Act on stale-suppression warnings ("safe to remove"). `V006` lockstep is the one suppressed false positive (per-module trains). The gate's `.` walk is RECURSIVE across nested modules — root's run also sees examples/e2e findings.
14. **IDE/LSP diagnostics are unreliable after multi-module edits** — stale gopls/golangci_ls warnings have repeatedly phantom-flagged clean code (gci/exhaustruct/"unused" on wired handlers); NEVER create work items from LSP output — verify with `golangci-lint run` / treefmt CLI first.
15. **identity-model is the domain source of truth:** new domain types go there + alias in usermgmt (Go has no const aliases — constants become `var` there). Commands use accessor methods (`c.Email()`). `ActorID` is consolidated (ADR-0111): 5 kinds (User/Bot/System/Service/Unknown) via `id.NewUserActor`/`NewBotActor`/`NewSystemActor`/`NewServiceActor`, or `ParseActorID("kind:raw")` (returns error). `NewActorID(string)` is deleted.
16. **Deprecated constructors/configs:** `NewUserID(string)` silently SHA-256-hashes non-ULIDs — use `ParseUserID` (strict) / `SyntheticUserID` (explicit stable hash) / `GenerateUserID` (fresh ULID). `SnapshotConfig` is opt-in (zero-value = full replay; set Store + Codec + Strategy together — ADR-0041). `usermgmt.NewExternalAccount(...)` is the only way to construct `ExternalAccount` externally.
17. **SSE vocabulary (hub-first):** the canonical shareable object is `*sse.Broadcaster[sse.Event]` — "the hub". Both `cqrshtmx.Broadcaster` and go-datastar's `broadcast.Broadcaster` EMBED it (`Hub()` + `NewBroadcasterFromHub(hub)`; the datastar `Broadcast(patch)` intentionally shadows the hub's `Broadcast(sse.Event)` → `BroadcastEvent` for raw events). Deprecated (v5 removal, same bundle as the SSE re-export layer): `Raw()`/`NewBroadcasterFromRaw`, `RawBroadcaster` — do NOT add a replacement interface; pass the hub directly.
18. **setup contracts:** `New` validates/normalizes paths (rejects `/` — login owns root — and collisions; subtree routing needs the trailing slash); `Mount` is once-only (duplicate mux patterns panic); dashboard 401-gating is deliberate — consumers wanting a public dashboard mount `bundle.Dashboard.Handler()` themselves; session middleware only enriches context, never blocks; auth mutations carry no CSRF by design (README security section documents why); flattened `ReadModelDB` is SQLite-only (dialect-probed at `New` — Postgres/MySQL go through `ServiceConfig.ReadModelDialect`).
19. **Status-report hygiene (docs-health):** reports are point-in-time, append-only; annotate resolved items INLINE (`~~item~~ done at \`hash\`` / `done (evidence)` / `**Won't implement — reason.**`) + a dated `> ANNOTATED YYYY-MM-DD` blockquote; absence of a marker IS the open signal; mixed tables (struck=done, unstruck=open) are first-class. Gates (both CI-wired via `check-modules` + flake apps + fixture self-tests): `scripts/check-status-annotations.sh` (Gate 1: presence + blockquote, epoch 2026-09-09, older = legacy-exempt) and `python3 scripts/check-status-rows.py` (Gate 2: PARTIAL rows — cells disagreeing within a row — are the only failure; the docs-health skill's `check-rows.py` asset is the annotator's authoring aid). Convention: `docs/status/README.md`. **New gates ship atomically: checker + fixture self-test + flake app + check-modules stage + CI step + README command — anything less is dead code.**
20. **TODO_LIST/docs ownership:** TODO_LIST carries ONLY `[ ]`/`[~]` (completed → CHANGELOG, rejected/deferred → ROADMAP "Not Planned", never `[x]`). README = end-user sales; FEATURES = honest inventory; TODO = short-term actionable; ROADMAP = long-term + raw ideas; CHANGELOG = append-only; AGENTS.md = enduring AI context (dated histories → `docs/agents-notes.md`); DOMAIN_LANGUAGE = glossary.
