> **THIS IS A LIBRARY/SDK — NOT AN APPLICATION.** Consumers import this package into THEIR projects.

## Architecture

**Multi-module Go workspace.** 29 modules under one `go.work`:

- **Root** (`cqrs-htmx/v4`): HTTP handler builder, HTMX/SSE helpers, authz (Casbin), error mapping, pagination, `openapi/` (dependency-free OpenAPI 3.1 builder + `WithOpenAPI`/`OpenAPISpecHandler`), `transport/` (canonical SSE domain-event surface: `DomainEventToSSE` + `EventPayload` envelope + `NewJournalSSEStore` + `ServeDomainEvents` + `WithSSEFilter` + `WithSSEMaxReplay`; envelope bytes pinned by golden tests, drift = test failure), **frontend sync protocol (ADR-0056, 2026-10-09): `SyncPullHandler` (cursor + permission-filter + ETag event pull WITH payloads; delivery encoding is honest — `"opaque"`/`SyncPayloadEncodingOpaque` when a json stamp's bytes are invalid, the gotcha-24 third victim) + `App.SyncPushHandler` (batched push, per-command classified outcomes, replays registered pipelines via the internal `commandRegistry` — zero new registration surface) + sync assets v1.5.0 (pull cache, batch flush, `window.cqrsSync`)**; guide `docs/guides/frontend-sync.md`. CSRF, Server-Timing, and keyed rate limiting are thin re-exports over `httputil` (`_reexport.go` files, deprecated). **SSE-only — WebSocket transport removed in v5 (ADR 0046).**
- **identity-model** (`identity-model/v4`): pure domain types — IDs (UserID/TenantID/BotID/ActorID), 25 event payload structs (22 lifecycle + 3 auth-audit, 2026-10-25), 21 commands (accessor methods, not field access), fold functions (FoldUser/FoldMembership/FoldTenant/FoldBot), state structs, Casbin-backed Authz engine, Session/User/Membership/ExternalAccount/WebAuthnCredential, crypto helpers, domain errors (errorfamily-only, no HTTP dependency), upcaster registry, exported constants. Casbin is a first-class dependency.
- **usermgmt** (`usermgmt/v4`): event-sourced CQRS user management — thin re-export layer over identity-model (type/var aliases + constructor wrappers) plus infrastructure (HTTP handlers, SQL stores with SQLite/Postgres/MySQL dialects, session middleware, read models, CasbinProjection, decide/dispatch). Auth via WebAuthn/TOTP/OAuth2 behind interfaces.
- **usermgmt/totp**, **usermgmt/webauthn**, **usermgmt/oauth2**: independent auth-strategy modules satisfying usermgmt interfaces via structural typing. oauth2 supports public (secret-less) PKCE clients (`ProviderConfig.ClientType`) and `FinishLoginWithToken` (raw ID token).
- **adminui**: ready-made admin dashboard (templ + HTMX) over a `*usermgmt.Service` — identity ops (users, tenants, members, audit log), write actions, role-gated, user-controllable theme toggle. "admin" = user administration; event-store introspection is dashboardui (cross-linked in both READMEs).
- **loginpage**: ready-made passwordless login page (built on templ-components since 2026-10-04 — `layout.Base`/`forms.Input`/`display.Button`/`feedback.Alert`, Tailwind-only styling, consumer-compiled CSS + CSP-nonce/cookie-theme hooks).
- **datastar**: optional DataStar adapter — script serving, signal decoding, SSE response builder (signal constructors return `(Patch, error)`), EventBridge with `OnError`. The Broadcaster lives upstream in `go-datastar/broadcast`; this module keeps deprecated alias shims until v5. Depends on go-datastar + go-sse only (no root dep). Guides: `docs/guides/datastar-integration.md`, `docs/guides/sse-and-datastar.md`.
- **dashboardui**: ready-made CQRS/ES observability dashboard — projection health, event catalog, SSE live updates, time-travel. `startEventBridge` fails `New` on `SubscribeAll` error (fail-fast); `Config.SSEMaxReplay` caps first-connect backfill; SSE handler delegates to `transport.ServeDomainEvents`; CORS same-origin by default (wrap with `httputil.CORS` for cross-origin). Full templ rendering (2026-09-22 migration from the former strings.Builder hybrid — 9 `.templ` files, generated `_templ.go` committed); pure-data `core/` sub-package bridged via aliases; CSP-safe (no inline handlers). **Integration modes (2026-10-04):** `Autodetect(store)` probes all capability interfaces → ready Config (kills the consumer assertion dance); `Config.Layout` (`LayoutFunc` + exported `PageMeta`/`NavLink`) replaces the built-in page shell with a consumer-owned document so panels render inside the consumer's app chrome — the embed answer to the 2026-08-05 DiscordSync "two apps bolted together" audit; HTMX partials bypass the shell; error/404 pages keep the built-in shell; `setup.Config.DashboardLayout` passes the seam through; README § Integration Modes is the consumer doc.
- **setup**: optional one-call composition root — `setup.New(Config) (*Bundle, error)`; `Mount`/`Handler`/`Run`/`RunHandler`/`RunWithAppkit` (Run paths deliberately have no Read/Write timeouts — SSE-safe). Session-gated dashboard + `/health` readiness gate under `AsyncStartup`; scoped shared feed via `SSEFilter`. Full config surface: `setup/README.md` (the canonical table).
- **systemadapter**: bridge to go-cqrs-lite's `system.New()` + `metaengine` — `DomainConfig()` (4 deciders + 20 commands + 24-event TypeDecoder), `EventTypeDecoder()`, `NewProjectionLayer(sys)` (deprecated — ADR-0051; declarative path canonical, checkpoint/DLQ limitation documented in `docs/guides/declarative-projections.md`). Guide: `docs/guides/leveraging-system-metaengine.md`.
- **health**: bridge to go-health — `NewProbe` (per-projection checks, detailed: duration_ns on the wire, built on `NewWithDetailedCheck`), `Recorder` (merge with samber/do injector checks; implements `DetailedHealthRecorder`), `RecorderChain` (ordered recorder merge, later wins — the auditlog "one probe" composition), `NewDashboard`. Own README/`.golangci.yml`/`.cqrs-lint.json` (README carries the "which surface for which consumer" map). 100% coverage. Deep review + outcome annex: `docs/research/2026-10-08_samber-do-v2-health-checks-deep-review.md`.

- **integration_test**, **e2e/server**, **examples/** (13 demos — `setup-demo` one-call full-stack, `system-demo` system.New integration, `samber-do-demo` DI best practice, `middleware-demo`/`observability-demo` OTel+metrics proofs, `sync-demo` the executable ADR-0056 frontend-sync guide, etc.).

**Dependency direction:** identity-model ← usermgmt (aliases). Root → usermgmt is zero imports (clean boundary). Auth strategies → root/usermgmt via interfaces only. adminui/loginpage/dashboardui → root + usermgmt (+ templ-components). datastar → go-datastar/go-sse only. systemadapter → usermgmt + identity-model + go-cqrs-lite system/metaengine. ## Key Patterns

- **Library principle:** never enforce defaults consumers might disagree with (no mandatory CSP/HSTS/CSRF — all opt-in).
- **No stdlib error constructors:** `errors.New`/`fmt.Errorf` banned in non-test code; use `event.New*/Wrap*/Wrapf/Newf` from go-cqrs-lite. Error families → HTTP status: Rejection(400), Conflict(409), Transient(503), Corruption(500), Infrastructure(503).
- **Duck-typing for external libs:** `Enforcer` (← casbin), `TemplComponent` (← templ), auth provider interfaces — consumers import what they need.
- **authMode enum:** `authNone`/`authRequired`/`authAuthorized` — impossible states unrepresentable.
- **Auth route posture is library-enforced (ADR-0055, 2026-10-04):** WebAuthn enrollment ceremonies enforce the owner-match rule (401 no session / 403 mismatched `user_id`; no HTTP opt-out — headless enrollment goes through the service-level API), and every `currentUser`-reading `/auth/*` route self-wraps with an enrich-only session pass inside `RegisterRoutes` — the "context-only handler + bare mount = dead route" class is dead. loginpage's register→begin→finish flow depends on the register-issued cookie riding `credentials: "same-origin"` fetches (same-origin mount required; proven by `TestBareMount_LoginPageFlow_WorksUnderGate`). `setup.RequireSession`/`RequireSessionRedirect` are the exported gates for consumer surfaces. Invariant mechanized: `scripts/checks/check-session-route-wrappers.sh` (`nix run .#check-session-route-wrappers`, in check-modules + CI).
- **Projection lifecycle via projectionhost:** per-projection goroutines, per-projection checkpoint keys (`Name()`), DLQ, crash-restart, read-your-writes via `waitForDrain`. `AsyncStartup` (opt-in) returns before drain — failures surface via `ProjectionStatuses()`/`/health`/`OnProjectionFailed`, not as a `NewService` error; `cqrshtmx.ProjectionReadinessCheck` is the readiness gate. `RebuildProjection(ctx, name)` swaps in a fresh host (projectionhost hosts are one-shot). Guide: `docs/guides/async-projection-startup.md`, `docs/guides/event-replay-and-rebuild.md`.
- **Checkpointed restarts via SQL hydrate:** `CheckpointStore` + SQL read models rebuild in-memory state before the host starts; `hydrationAwareCheckpointStore` (applied by the shared `startProjectionHost` factory) forces casbin-projection + the default in-memory AuditLog to full-replay, so authz policies and the audit trail stay complete after restarts. Append handlers are idempotent (at-least-once convergence); `MemberAdded.AddedAt` uses event time. TOTP secrets persist in `users_view.data` — rows written by pre-hydrate versions lack the secret: run `RebuildProjection(ctx, "user-read-model")` once after upgrading an existing SQL read model, or affected TOTP users re-enroll.
- **go-cqrs-lite is richer than the hooks:** the `*command.Dispatcher`/`*query.Dispatcher` passed to `Config.Commands`/`Config.Queries` implement `Use(mw ...)` — every factory from `go-cqrs-lite/middleware/v4` (logging, recovery, retry, circuit breaker, metrics, OTel, validation, idempotency) composes with zero glue. Capability map + recipes: `docs/guides/leveraging-go-cqrs-lite.md`; runnable proofs in `examples/middleware-demo` + `examples/observability-demo`.
- **OTel posture:** the library is otel-free by design (verify: `rg -l go.opentelemetry.io root/ usermgmt/ setup/` finds nothing outside go.mod/go.sum). go-cqrs-lite's decider/storage layers emit spans via the GLOBAL tracer — one `cqrsotel.Setup()` call auto-traces the entire identity domain. Canonical doc: `docs/guides/leveraging-go-cqrs-lite.md` §2 (the older `docs/observability-wiring.md` is SUPERSEDED). `setup.Config.Observability` accepts an upstream `*middleware.OTelBundle`.
- **Event catalog (Published Language):** `cqrshtmx.EventCatalog` + `EventCatalogHandler` serve event schemas as immutable JSON (1-year cache, FNV-1a ETag); `usermgmt.DefaultEventCatalog()` pre-registers all 24 events (incl. the auth-audit trio). Guide: `docs/guides/event-catalog-guide.md`.
- **Actor/audit chain is built-in:** `NewService` wires `commandAuditMiddleware()` (session→actor bridge, upstream `middleware.CommandActorContext()`, causation) onto the single dispatcher, and `repositoryOptions` composes `event.ActorEnricher` + `requestContextEnricher` (correlation/request-ID) + `event.CommandCausalityEnricher` — every dispatched command emits attributed events with zero consumer code. E2E: `integration_test/actor_attribution_test.go`. `ServiceConfig.CommandMiddleware` is the consumer seam (applied INSIDE the chain); `Service.Dispatcher()` is deliberately NOT exported (lifetime + chain-integrity hazard).
- **Context enrichment uses structural interfaces:** root's enrichment asserts `commandOptionApplier`/`queryOptionApplier` (`ApplyOptions`), never concrete wrapper types — embedding promotes the interface through every command wrapper. The 20-command bijection (`Cmd*` constants ↔ `RegisterTyped`) is mechanically enforced by `scripts/checks/check-command-bijection.sh`.
- **WithActor integration:** `ContextEnrichmentMiddleware` auto-derives `ActorID` from `UserID` (never overrides a consumer-set actor); `EventOptionsFromContext`/`CommandOptionsFromContext`/`QueryOptionsFromContext` propagate actor/correlation metadata. `Dispatch(ctx, cmd)` does NOT take options — metadata is set at construction.

## templ-components (family of 5 modules — current train in go.mod)

adminui, dashboardui, and loginpage depend on it. Before hand-rolling any UI element, check the library first (110+ components across 10 packages). Enduring gotchas learned here:

- **Rebuild the CSS bundles in the SAME change as any family bump** (`nix run .#build-adminui-css` / `.#build-dashboardui-css`) — the compiled bundle captures the era's class set; a stale bundle ships missing utilities. The buildflow hook's bundle-rewrite class is DEAD at the source since 2026-09-26 (`tailwind-build` skipped + bundles excluded in `.buildflow.yml`); before that the hook rewrote bundles WITHOUT `--minify`. `nix run .#check-css-bundles` (gated in `check-modules` + CI since 2026-09-23) enforces the canonical form: 1-line minified, banner header, byte floor, canary utilities. `nix run .#check-css-bundle-classes` (gated since 2026-09-26) enforces the CONTENT: the committed bundles' sorted class-token sets must equal a fresh canonical build — it mechanizes the "formatting-only, class sets identical" proof family bumps need and fires on any class-set drift; the gate rebuilds in place and `git restore`s, refusing to run on a dirty bundle. The SAME commit also carries: the agents-notes `uniform at vX` claim updated to the new version (the docs-freshness gate red's CI otherwise — hit live 2026-10-08, one avoidable CI cycle) and a consumer-suite run BEFORE pushing, because family bumps carry RENDER changes (v1.21.0's omit-empty nonce rule drifted dashboardui's two page goldens — regenerate only after diffing old-vs-new line by line to confirm the drift is exactly the documented upstream change).
- **Set `BaseProps.ID` on every library component the JS/tests target** — `EnsureID` randomizes un-pinned IDs (keep DOM hooks stable across regenerations).
- **Table-fragment contract:** partials for `hx-swap=innerHTML` targets contain rows but NOT the wrapper; polled-region partials re-render the REGION itself (outerHTML contract — bare children would kill polling after one refresh).
- **htmx attribute INHERITANCE leaks the boost wrapper onto every ajax element (2026-10-18, the overview-blanking bug):** dashboardui's `.app-layout` wrapper carries `data-hx-boost/target/select/swap="#main-content"` for boosted navigation, and htmx resolves `hx-target` AND `hx-select` through the ancestor chain for EVERY ajax element (verified in the embedded 2.0.10's `ne()` resolver). Any `hx-get`/`hx-post` element inside the subtree without its own pins selects `#main-content` from a partial response that has none → htmx swaps an EMPTY fragment into `#main-content` → the page blanks within a second (first SSE event fires the `refresh` trigger). Defense: EVERY self-fetching element inside a boosted wrapper must pin its own attrs — `hx-target="this"` + `hx-select="unset"` (`ne()` treats the literal "unset" as no-selection; the events filter form already self-defends with explicit target/select/swap, and the projection-health PolledRegion now carries `hx-target="this" hx-select="unset"` via `BaseProps.Attrs`, pinned by the overview golden). Also: journal reads from a ZERO cursor return the OLDEST events (`ReadFrom(zero, n)` = head, not tail) — newest-N views must page the journal keeping a rolling tail (`core.LoadTailEvents`), never trust a zero-cursor read for "recent".
- **CSP:** inline `--tc-sidebar-w` style attributes are dropped by nonce CSP — redefine in consumer CSS; the library's popover/dialog CSS and dark-surface classes may need vendoring into the consumer's compiled CSS (the library's own bundle never loads in these modules).
- **Dark-mode surfaces:** if the consumer's `@theme` remaps gray-800/900 (e.g. to `--text`), pin them back to literal darks in dark mode — library `dark:` variants assume literal darks (all library `text-gray-800/900` occurrences carry `dark:` overrides, so the pin is safe). Dark mode itself is CLASS-driven in both UI modules (adminui + dashboardui, 2026-09-23): `@custom-variant dark` + `html.dark` tokens + `layout.ThemeScript`/`ThemeToggle`; the old media-query token flip is gone (no-JS degrades to light).
- **Hybrid (strings.Builder) rendering:** templ `{children...}` renders EMPTY in the hybrid path — use props-based components or the `templ.WithChildren(ctx, child)` escape hatch (v1.19.1); `display.Grid`/`htmx.PolledRegion` need a real templ path. Ends here: dashboardui converted to full templ (2026-09-22); no remaining repo consumer renders library components through strings.Builder.
- **loginpage ADOPTED the library** (2026-10-04): `layout.Base`, `forms.Input`, `display.Button`, `feedback.Alert`, `utils.Class`/`utils.Ternary` — the former "adoption opportunities" list is fully consumed; loginpage's page compiles through templ, its JS-injected spinner uses only scanned Tailwind utilities (see loginpage/README.md § Styling).
- **Adoption inventory:** the grep-able adopted/custom/divergent table lives in `dashboardui/README.md` (§ Styling and templ-components Adoption); audit series in `docs/research/2026-09-{17,23}_templ-components-deep-dive.html` with the comparable rubric in the 09-23 report §06.

## Benchmarks

Every serious comparison uses `b.Loop()` (Go 1.24+) + `b.ReportAllocs()` + `b.ReportMetric(req/s)` + benchstat (`-benchtime=2s -count=5`), with `b.Cleanup` stopping timers before server drain. Suppress per-request logging in benches (`appkit.LogLevelError`, or pin `slog.SetDefault(slog.New(slog.DiscardHandler))` for the sub-bench + restore on cleanup) — skipping this makes log lines the dominant measurement. One-off `time.Since` blocks in tests are forbidden — they belong in `*_bench_test.go`. Canonical pattern: `setup/run_appkit_test.go:BenchmarkSpikeBaselineVsAppkit`. The machine-pinned raw baseline (`docs/benchmarks/setup-baseline.raw.txt`) is the ONLY gate-comparable artifact; human markdown records are not comparable.
