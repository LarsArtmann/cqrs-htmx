# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/).

## [Unreleased]

### Changed

- **Hub-first SSE broadcaster vocabulary (root + datastar):** the canonical shareable object for cross-transport fan-out is go-sse's `*sse.Broadcaster[sse.Event]` — "the hub" — not a "raw" escape hatch. `datastar.Broadcaster` now **embeds** the hub (previously a hidden unexported `inner` field with six hand-written pass-through methods): `Health`, `Shutdown`, `Close`, `OnSubscribe`, `OnUnsubscribe` promote from go-sse with identical signatures, and `Subscribe`/`Unsubscribe`/`SubscribeFilter` become callable directly on the datastar adapter (previously required unwrapping). `Broadcast(patch)` still shadows the hub's `Broadcast(sse.Event)` intentionally — raw events go through `BroadcastEvent`. Both adapters gained `Hub()` and `NewBroadcasterFromHub(hub)`; setup's SSE endpoint wiring uses `Hub()`.

### Deprecated

- **Raw-named broadcaster API (removal bundled with v5):** `cqrshtmx.Broadcaster.Raw()`, `cqrshtmx.NewBroadcasterFromRaw`, `datastar.Broadcaster.Raw()`, `ds.NewBroadcasterFromRaw`, and the `cqrshtmx.RawBroadcaster` interface — all superseded by `Hub()` / `NewBroadcasterFromHub` / passing `*sse.Broadcaster[sse.Event]` directly. The interface and both `FromRaw` constructors had zero production consumers at deprecation time; deprecated symbols stay functional (and test-pinned) through v4. Guide rewritten hub-first (`docs/guides/sse-and-datastar.md`).

### Added

- **Per-benchmark thresholds for the bench-spike gate:** `BENCH_THRESHOLD_<NAME>` overrides the global gate for one benchmark — NAME is the bench name uppercased with non-alphanumerics mapped to `_`, and a distinctive suffix matches (e.g. `BENCH_THRESHOLD_JSON_ROUNDTRIP=15` covers `BenchmarkSpikeBaselineVsAppkit/json-roundtrip`). Rationale: sub-2µs benches flap near any fixed percentage (measured ~9% noise on the ~1µs `json-roundtrip` sub-bench vs ~5% on the HTTP benches), so a single noisy bench no longer forces a loosened global threshold. Non-numeric override values fail the gate with a message naming the variable. Documented in `docs/benchmarks/README.md` and the AGENTS.md Bench row.

- **Low-disk-space fail-fast in the shared Go cache guard:** `scripts/lib/go-cache-env.sh` now checks free space on the resolved `GOCACHE` filesystem and fails up front with a what/why/fix message instead of letting a full disk surface minutes later as phantom "no space left on device", corrupted module cache, or bogus "missing go.sum entry" errors (the 2026-08-29 /tmp tmpfs incident). `GO_CACHE_MIN_FREE_MB` (default 2048; 0 disables) tunes the bar; AGENTS.md gained a Go caches quick-ref row documenting the `/tmp` layout so fresh sessions stop re-deriving it.

- **`setup.Config.ServiceConfig` escape hatch (non-breaking):** pass a full `*usermgmt.ServiceConfig` to the bundle and keep every service knob the flattened fields cannot express — `MaxUsers`, `TokenPepper`, `SecurityHooks`, `CheckpointStore`, `SnapshotConfig`, `SessionStore`, `Lockout`, `EmailVerification`, custom `AuditLog`, and more — while still getting the panels, session middleware, SSE, and health endpoint. Precedence: `Service` (adopt, caller owns lifecycle) > `ServiceConfig` (override, bundle owns lifecycle) > flattened fields (convenience). `Service`+`ServiceConfig` are mutually exclusive, and either conflicts with the 10 flattened service-construction fields (`EventStore`, `EventBus`, `ReadModelDB`, `TOTP`, `WebAuthn`, `OAuth2`, `SessionTTL`, `Logger`, `AsyncStartup`, `OnProjectionFailed`) — rejected at `New`, never silently ignored. Exactly one default applies on top of an override: a nil `AuditLog` gets the in-memory audit log, matching the flattened path. `New` now sources the shared stores from `svc.Journal()`/`svc.EventBus()` on every path (adopted or built), so the dashboard, SSE bridge, and health endpoint always observe the infrastructure the service actually commits to. Covered by internal `resolveServiceConfig` mapping/copy-semantics tests plus behavioral tests (MaxUsers enforcement e2e, conflict rejections, mutual-exclusion rejection). Documented in `setup/README.md` (config table + "ServiceConfig override" section) and `setup/doc.go`.

- **`nix run .#bench-spike` gate + `benchstat` in the devShell:** the documented bench-spike workflow (run the canonical `BenchmarkSpikeBaselineVsAppkit` spike 5×2s, compare via benchstat, fail on a >5% median ns/op regression) is now a flake app instead of a copy-paste recipe. The app runs the bench, prints the benchstat baseline→current table, and gates each benchmark's median ns/op against a pinned raw baseline (`docs/benchmarks/setup-baseline.raw.txt`, the machine-comparable sidecar — the 2026-08-17 markdown artifact stays as the human record, but its Xeon numbers are not comparable to other machines). Guards: a goos/goarch/pkg/cpu environment check refuses to gate across machines and prints the re-pin command (`nix run .#bench-spike -- --save-baseline`); `BENCH_COUNT`/`BENCHTIME`/`BENCH_SPIKE_THRESHOLD` override the defaults. `benchstat` is not packaged in nixpkgs, so the flake builds it from `golang.org/x/perf` (pinned `19be9d8e6c70`, 2026-08-25) as `.#benchstat` and adds it to the devShell — closing the "recipe without a tool" gap. Gate verified end-to-end: OK path (exit 0), synthetic regression path (exit 1), environment-mismatch path (exit 2), and bare `ns/op`-terminated bench lines (no `-benchmem`) parse correctly.

- **Checkpointed restarts that actually survive (usermgmt SQL hydrate + hydration-aware checkpoints):** `CheckpointStore` is now safe to enable. Every SQL-backed read model implements the new `Hydrator` interface (`Hydrate(ctx)` rebuilds the in-memory maps and secondary indexes — emails, external accounts, byActor, byTokenHash — from the view store), and `NewEventSourcedSetup` and `StartProjections` hydrate before the projection host starts, aborting construction on failure instead of serving half-hydrated state. - **HTTP status mapping reconciled with upstream `go-error-family`** (ADR-0017). `Corruption` errors now return **500** (was 422) — data integrity breaks are server-side, not client input errors. `Infrastructure` errors now return **503** (was 500) — the correct "service unavailable, retry later" semantic. - **Broadcaster send-on-closed-channel panic** (`fanout.go`): `Broadcast()` previously snapshted subscriber channels under RLock, released the lock, then iterated — a concurrent `Unsubscribe()` could `close()` a channel mid-iteration, panicking the entire process. Fixed by holding the RLock during the non-blocking fan-out (race-safe: `Unsubscribe()` cannot acquire the write lock to close a channel during iteration). Regression test added.

### Breaking Changes

- **`SQLEventStore.Close()` no longer closes the `*sql.DB`.** The delegated upstream store uses a borrowed DB handle — callers now own its lifecycle. **Migration:** any code that called `store.Close()` to clean up the DB must now call `db.Close()` separately:

  ```go
  // Before (v2.5.0):
  store, _ := usermgmt.NewSQLEventStore(ctx, db, "postgres")
  defer store.Close() // closed db too

  // After (v3.0.0):
  store, _ := usermgmt.NewSQLEventStore(ctx, db, "postgres")
  defer store.Close() // marks store closed; db stays open
  defer db.Close()    // caller owns the DB lifecycle
  ```

  Rationale: shared-DB usage (event store + session store on one `*sql.DB`) was already broken under the old behavior — `store.Close()` would close the DB out from under the session store. The upstream library's "borrowed handle, caller owns lifecycle" philosophy is `database/sql` best practice and is correct for shared-DB scenarios. No backward-compat wrapper is provided because silently closing the DB was itself a bug for shared-DB consumers.

- **`SQLEventStore.Load()` on empty aggregate** now returns `event.ErrAggregateNotFound` instead of an empty slice. The decider's `Repository` handles this transparently (returns `Initial` state), so consumers going through `Service` are unaffected. Direct callers of `store.Load()` should check `errors.Is(err, event.ErrAggregateNotFound)` if they need to distinguish "no events yet" from a real error.
- **MySQL dropped for event store.** `NewSQLEventStore(ctx, db, "mysql")` now returns an error — `go-cqrs-lite/storage` has no MySQL dialect. `SQLSessionStore` retains MySQL support (it manages its own simpler schema). Migration path: switch to Postgres or SQLite for the event store.
